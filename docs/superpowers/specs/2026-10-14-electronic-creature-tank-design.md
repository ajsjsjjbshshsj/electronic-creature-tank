## 1. 愿景

创造一种**新物种**。它长得像一颗毛茸茸的五角星：占脸约 28% 的大眼睛、一条会摇的尾巴、个体之间颜色各不相同。它的表达手段有三样：**身体的动作与形变**、**体色与发光**，以及**一小撮它自己会的词**。

> **⚠️ 2026-10-20 修订（控制方裁定）：原愿景写的是「它不能说话，没有一句台词、没有一个文字气泡、没有任何符号外挂」。**
> 新要求是：个体要用简单词语表达自己的性格、意愿与心情；活泼爱撒娇的会「喵喵」「咩咩」这类萌系特征词；高冷的不爱说话；聪明程度在个体间波动，有的特别聪明有的特别傻。
> 这不是加一个功能，是把本项目的立身之本改了一半 —— 所以本节、§核心设计原则 1、§4.12 繁殖、§5.1 身体一起重写，并由 §9.2 新增的第 7 条验收标准反向钉住：**关掉文字层，缸仍必须完全可读**。
> 一句话概括这次修订：**文字是新增的第二通道，不是替代第一通道。** 原来的承诺仍然成立，只是不再是唯一的承诺。

它是一个**群体**，不是一个宠物。它们在深水里自己觅食、相遇、卖萌、吵架、自己下蛋、孵化、长大、衰老、死去，并且对着彼此、对着你说话。你是照料者 —— 你可以投食、可以抚摸、可以讲东西给它听、可以看着它们，但你控制不了它们。

它最核心的设计承诺仍然是：**你能在不读任何文字说明的情况下，读懂它们。**

### 核心设计原则

1. **身体语言是第一通道，且必须独立可读**（2026-10-20 由「身体是唯一的语言」修订）。文字层只允许说"它想说什么"，永远不许说"它现在是什么情绪" —— 情绪的呈现仍然必须完全通过形变、姿态、运动、体色、发光、眼睛与尾巴。仍然**不加** ♡ 💢 ？ ！ 这类漫画符号：气泡里只允许出现它自己词汇表里的词，出现一个解说符号就算破坏。
   这条原则有机器可验的版本：`CONFIG.speech.enabled = false` 时，§8.2 的视觉核对清单必须逐项仍然通过（§9.2 第 7 条）。
2. **涌现优先于脚本**。不写好剧本。胆大的先探到缸底发现食物、贪吃的去抢兄弟姐妹的食物被打了一顿于是记住了这笔账 —— 这些必须是系统交互的自然结果，不是我编排的动画。
3. **世界规则始终自洽**。种群上限不靠硬编码屏蔽，而表现为"它看了看缸角，又走开了""这枚卵的光慢慢熄灭了"。绝不出现"明明在产卵却什么都没发生"的突兀感。（2026-10-20 随 §4.12 改孤雌，例子换掉了，**这条原则本身一个字没改**。）
4. **绝不静默丢失用户数据，绝不让整个世界崩溃。**
5. **零依赖**。不装 npm 包，不构建，不加载音频文件。十年后双击 `start.bat` 还能打开。

### 3.2 模块边界原则

**纯逻辑模块**（`genes` `needs` `emotions` `memory` `personality` `behavior` `speech` `lexicon` `rng` `names`）**不得 import `canvas`、不得 import `world`、不得触碰 DOM**。`speech.js` 尤其不许 `fetch` —— 它只负责"规则引擎那一档"的话，联网那一档的升级点在 `main.js` 里做装饰器注入（见 §4.13 的实现分层），这样 `tests/speech.test.js` 在 Node 里能完整跑通。

这条约束的回报是：它们能在 Node 里直接单测，不需要浏览器、不需要 jsdom、不需要任何测试框架依赖。`node --test tests/*.test.js` 就能跑完。

每个模块对外只暴露具名函数，内部状态由调用方持有（生物对象），模块本身无状态。这样模块可独立理解、独立替换。

### 3.3 主循环数据流

```
requestAnimationFrame
 → 累加器切成固定步长 dt（1/60s），乘时间流速
 → world.tick(dt)
     每只生物：
       needs.decay(dt)               需求衰减
       memory.decay(dt)              恩怨随时间淡化
       senses = world.perceive(c)    看到的食物 / 邻居 / 玩家的手
       emotions.update(...)          需求 + 事件 → 情绪向量
       behavior.decide(...)          情绪 × 性格 × 情境 → 行动意图
       c.act(intent, dt)             移动 / 蹦跳 / 进食 / 卖萌 / 求关注 / 逃避
       speech.maybeSay(c, ctx)       性格 × 心情 × 听过的词 → 0 或 1 句短话（有冷却）
       body.update(emotion, motion)  形变、尾巴摆动、卷毛抖动与体色跟随情绪
       c.age(dt)                     生长推进 / 阶段切换 / 衰老 / 死亡
     world.resolve()                 碰撞、自产卵、孵化、外来血统漂入、争食、哀悼
     world.respawnFood(dt)           光藻缓慢再生
 → render.draw(world)
 → ui.sync(world)
 → 每 5 秒 save.flush()
```

### 3.4 五个关键技术决定

1. **固定步长积分**
   模拟用累加器切成 1/60s 定步长，渲染按真实帧率。手机 120Hz 与电脑 60Hz 下，生物的生长速度、饥饿速度完全一致 —— 否则同一份共享存档在两台设备上会活得快慢不同，这对"手机电脑同一个缸"是致命的。
   累加器**封顶 0.25s**，防止标签页从后台恢复时一次补算几百步（死亡螺旋）。

2. **世界坐标归一化存储**
   位置存 `[0,1]²`，体型存"世界单位"。渲染时世界尺寸 = 视口 CSS 尺寸，缩放系数由视口**短边**推导并 clamp。
   隐喻是**水填满容器**：竖屏手机上缸是高高的，横屏电脑上是宽的，同一份存档在两边都自然铺满，生物不会在手机上小到看不见。
   `resize` 时按新旧尺寸比例映射所有位置。

3. **发光用预渲染光晕精灵**
   启动时按色相量化成 32 桶预渲染光晕 sprite，运行时 `drawImage` + `globalCompositeOperation='lighter'`。
   **绝不每帧调 `shadowBlur` 或新建渐变对象** —— 这是手机浏览器上最大的性能杀手。

4. **空间网格做邻居查询**
   感知与碰撞天然是 O(n²)。用均匀空间网格降到接近 O(n)，保证桌面 24 只、手机 16 只都满帧。

5. **静态背景交给 CSS**
   深水渐变写在 `css/main.css` 的背景上，canvas 保持透明叠加。省掉每帧一次全屏填充，也让 `lighter` 混合只在 canvas 内部生效（正是想要的效果）。

## 4. 生命系统

### 4.1 基因：孟德尔式双等位基因

每个性状存**两个等位基因** `[a, b]`（各为 0–1 的浮点数），不是单个数值。

```
表现型 phenotype = a × dom + b × (1 − dom)      dom = 该位点的母方权重（0.5 = 共显性，公平混合）
配子   gamete    = 随机取 a 或 b（各 50%）+ N(0, mutationRate) 后 clamp 到 [0,1]
子代   offspring = 双亲各贡献一个配子，组成新的 [a, b]
槽位约定         = slot 0 是母方、slot 1 是父方（layEggs(mother, father) → inherit(rng, mother.genes, father.genes)）
                   ⚠️ 2026-10-20 随 §4.12 改孤雌：父方槽位取消，两个配子都由母方提供
                   （layEggs(mother) → inherit(rng, mother.genes, mother.genes)，即**自体合并**）。
                   **slot 0 的排序契约必须原样保留** —— `pattern` 的 dom=0.7 与 `glow` 的 0.6 全靠它，
                   `tests/genes.test.js` 与 `tests/breeding.test.js` 钉的就是"slot 0 来自第一配子"。
                   改孤雌只改第二个实参传谁，不改 inherit 的内部逻辑。
```

**`dom` 到底是什么 —— 以及它不是什么。** 这一条必须写清楚，因为它决定了家谱读起来是什么感觉，也因为它容易被误读成教科书里的显隐性：

- `dom = 0.5` 是**共显性**：表现型就是两个等位基因的均值，与谁在 slot 0 无关。`hue` 属于这一类 —— 颜色永远是双亲的公平混合，交换父母顺序不会改变孩子的色相。这是有意的：色相是整个项目里最显眼的性状，它不该取决于家谱里谁被写在前面。
- `dom ≠ 0.5` 是**偏母本权重**：slot 0（母方）的等位基因占更大比重。`pattern` 的 0.7 意味着花纹更像妈妈，`glow` 的 0.6 意味着发光基线略偏母方。因此**正反交的结果不同** —— 同一对基因，母方与父方互换会得到花纹不一样的孩子。这是刻意的家族信号：颜色混双方、花纹随母亲，于是"看得出像谁"在家谱里有了两条独立的线索。
  > **⚠️ 2026-10-20 孤雌制下这条的一半失效，但 `dom` 本身不能删。** "正反交"这个实验不存在了（没有父方可换），可 `dom ≠ 0.5` 仍然在做功：自体合并时两个配子各自独立地从 `[a,b]` 里随机抽一个，**谁被放进 slot 0 是随机的**，所以同一窝的两枚蛋仍会长出不同花纹。家族信号从"颜色混双方、花纹随母亲"变成"**同一位母亲的一窝蛋彼此就不一样**"。删掉 `dom` 会让花纹退化成母方两等位基因的均值，隔代惊喜少一条腿。
- 它**不是**等位基因层面的显隐性。这个模型里没有任何一个等位基因会被另一个"掩盖"：`dom` 是加权系数，不是掩码。所以本节早先"因为玫红基因在双亲体内都是隐性的"那句解释是错的，已在下面更正。

**这个模型孟德尔的部分在哪里**：在**颗粒遗传**与**分离定律**，不在显隐性。两个等位基因在基因组里始终是分开的两个数，永远不会被平均掉；每个亲本形成配子时随机交出其中一个。正因为等位基因保持颗粒性，两个杂合亲本（各自都携带一个低色相等位基因、但表现型只是中等偏浅）可以生出一个**纯合低值**的孩子 —— 那孩子的色相落在双亲之外，比父母都深。

这才是"隔代惊喜"的真实机制，而它是**分离**在做功，不需要显隐性参与。`tests/genes.test.js` 里的 F1→F2 重现测试正是钉住这条路径的：如果分离退化成"永远取 slot 0"或"永远取 slot 1"，那条测试会失败。

**所有等位基因都是 `[0,1]` 区间内的无量纲浮点数**，由表现型解码函数映射到实际性状。这样做有两个必要好处：

1. **混合永远在基因空间（线性）进行，不在性状空间进行。** 这对色相尤其关键 —— 粉色区间跨越 0°，直接在角度空间插值会绕远路得到错误的中间色；在基因空间插值则永远正确。
2. 存档与变异逻辑与具体性状的单位无关，新增性状不需要改遗传代码。

**为什么用双等位基因而不是单个数值**：因为**颗粒遗传 + 分离**能生出双亲之外的性状。一对浅樱粉的父母可能生出一只深玫红的孩子 —— 不是因为玫红基因被"隐性掩盖"过（这个模型没有显隐性），而是因为双方都携带一个低色相等位基因，而分离让这两个低值在孩子身上凑到了一起。共显性性状（如色相）在多数情况下表现为混合色，但偶尔会跳出双亲的范围。几代之后缸里会自然分化出可辨认的家族支系，而你能在家谱里看出谁像谁 —— 色相看双方、花纹看母亲。单个数值的加权平均永远给不出这种惊喜：它只会让每一代都向均值收敛，几代之后全缸长成一个样。

**外观基因**

| 基因 | 表现型解码 | 母方权重 `dom` |
|---|---|---|
| `hue` | `(315 + phenotype × 70) mod 360` → 315°–385°(=25°)，即粉色区间 | 0.5（共显性） |
| `sat` | `0.45 + phenotype × 0.5` → HSL 饱和度 **45%–95%** | 0.5（共显性） |
| `lum` | `0.62 + phenotype × 0.22` → HSL 亮度 **62%–84%** | 0.5（共显性） |
| `size` | `MIN_SIZE + phenotype × (MAX_SIZE − MIN_SIZE)`，单位为世界单位 | 0.5（共显性） |
| `glow` | `0.35 + phenotype × 0.65` → 发光**基线**强度 **0.35–1.0** | 0.6（偏母本） |
| `pattern` | **分桶离散化**：`[0,0.2)` 无 / `[0.2,0.4)` 圆斑 / `[0.4,0.6)` 环纹 / `[0.6,0.8)` 云斑 / `[0.8,1.0]` 星点 | 0.7（偏母本） |
| `patternDensity` | 直接作为花纹密度系数 | 0.5（共显性） |
| `wobble` | 直接输出 `[0,1]`，由运动层（计划 2）映射到身体弹簧的刚度与阻尼 | 0.5（共显性） |
| `fluff` | 直接输出 `[0,1]`，由表现层映射到**卷毛长度与边缘毛簇密度**（§5.1）。2026-10-20 新增：用户要求"毛茸茸"，而这必须是遗传性状而不是全体共用一个贴图 —— 否则一窝孩子毛一样蓬，物种认同就白建了 | 0.5（共显性） |
| `eggTint` | **唯一一个不解码成身体性状的位点**（2026-10-20 裁定新增，控制方选项「新增第 10 个位点」）。表现型按**分段最近邻**映射到 §11 的 8 色蛋表：马卡龙六色各占约 13%，白占约 8%，**黑占表尾 `[0.975, 1.0]` 那 2.5%** —— 于是黑蛋的稀有度是**基因位置天然给的**，不需要再掷一次骰子，也就不存在"两次随机对不上"的坑 | 0.5（共显性） |

> **`eggTint` 为什么值得多一个位点**：不遗传的话蛋色只是个随机数，"这一家都下蓝蛋"这条家谱线索就没了 —— 而 §4.12 改孤雌之后，家谱本来就在失去线索（没有父亲了）。这个位点补回来一条，而且它补的正是**最显眼**的那一环：蛋在缸底一躺就是几十秒，玩家盯着看的时间比看成体长。
> **代价如实记**：`ALL_GENES` 从 14 个位点变 19（外观 8→10、性格 6→9），`tests/genes.test.js:13` 的 `APPEARANCE_GENES.length === 8` 要改成 10；存档里每只个体多存一个二元数组。

**为什么 `sat` / `lum` / `glow` 是区间映射而不是直接透传**（这三行修正了本节早先"直接作为 HSL 饱和度/亮度"的写法，那句与 §4.2 的粉色锁定冲突）：

- **`sat` 下限 45%**：饱和度接近 0 的个体是灰白的，而灰白不是粉色。用户对这个物种的明确要求是"颜色是粉色，可爱一点"，§4.2 也写着"这个物种就是粉色的"。让基因自由决定饱和度，等于允许缸里出现不符合物种认同的灰色个体。
- **`lum` 区间 62%–84%**：下界保证个体在深靛紫水体（`#0B0620 → #2D1240`）里始终可读 —— 一只接近黑色的个体，不管它是半透明凝胶还是毛茸茸，在暗水里都等于隐形；上界防止高光溢出成白色而丢掉色相。（2026-10-20 换造型之后这条**更严了不是更松**：毛绒靠的是同色相内的明暗渐变塑形，亮度一旦溢出到白，毛的体积感就整个没了。）
- **`glow` 下限 0.35**：`decode().glow` 是**基因决定的发光基线**，不是最终亮度。情绪表现层（§5）会在此基础上做乘法调制 —— 困倦时脉冲几乎停摆、恐惧时光晕收缩到核心、兴奋时最亮。有下限才意味着"从不发光"不是这个物种的状态，情绪的明暗变化靠调制而非开关来表达。渲染层（计划 2）应当读取这个 `[0.35, 1.0]` 的基线，再乘以情绪系数。

**`wobble` 的行是有意留白的**：它是唯一不在 `decode` 里完成单位换算的外观基因，因为它要变成弹簧物理参数，而那属于运动层。`decode` 只负责外观单位（色相角度、HSL 百分比、世界单位尺寸），物理参数由计划 2 的 `body.js` 解释。


`pattern` 是唯一需要离散化的基因：它必须分桶，因为"半个圆斑和半个环纹"没有意义。分桶的副作用是有益的 —— **两个表现型相近的父母可能因为落在不同桶里而生出花纹完全不同的孩子**，这是另一种隔代惊喜。

**性格基因**（均为 0–1，`dom` 一律 0.5 即共显性 —— 性格是双亲的公平混合，不偏向任何一方）

| 基因 | 低值 ← → 高值 | 调制什么 |
|---|---|---|
| `bold` | 胆小 ↔ 胆大 | 害怕阈值、敢不敢接近玩家的手 |
| `clingy` | 独立 ↔ 黏人 | 社交匮乏上升速度、卖萌频率、**对主人的依恋上限** |
| `irritable` | 温和 ↔ 暴躁 | 生气阈值、怒气持续、撞击倾向 |
| `gluttonous` | 少食 ↔ 贪吃 | 饥饿阈值提前量、争食倾向 |
| `curious` | 安分 ↔ 好奇 | 好奇增长速度、探索半径、**听进去新词的概率** |
| `activity` | 安静 ↔ 好动 | **蹦跳的频率与高度**（§4.7.1）、尾巴摆动速度、闲不住程度 |
| `talk` | 高冷 ↔ 话痨 | **出词频率与词汇宽度**（§4.13）：低值可以整缸生命周期里只说十几句 |
| `intellect` | 傻 ↔ 聪明 | **词汇量、"听进去的话"能记几条、复述时的还原度**（§4.13） |
| `broody` | 冷淡 ↔ 想当妈 | **自产卵的间隔与每窝枚数**（2026-10-20 取代 `libido`） |

> **⚠️ 2026-10-20 三处改动，都是 breaking：**
> 1. **新增 `activity` `talk` `intellect` 三个位点。** 它们不是装饰：用户要求"越好动的个体越喜欢蹦蹦跳，蹦的越高频率越快""活泼的有萌系特征词，高冷的不爱说话""有的特别聪明有的特别傻" —— 这三条都必须是**可遗传的连续量**，否则缸里所有个体说话一样多、跳一样高、一样聪明，性格系统就是假的。
> 2. **`libido` 改名 `broody` 并换语义。** 孤雌制下"求偶欲"没有受者了，它原来的两个作用（求偶评分、接受求偶的概率）同时失效。新语义是产卵倾向。`src/personality.js` 的阈值映射表、`tests/personality.test.js` 的方向断言、`CONFIG.personality` 的键都要跟着改。
> 3. **`GENE_KEYS` 是冻结数组**（Task 2 复查时钉的），加位点会同时打破 `tests/genes.test.js` 的槽位数断言与 `tests/config.test.js` 的冻结深度断言。**先改测试再改实现**，别指望它悄悄通过。

### 4.2 色系：锁定粉色家族

`hue` 基因的取值范围从 0–360° **收窄到 315°–360° + 0°–25°**，即樱花粉 → 桃粉 → 珊瑚粉 → 玫红粉 → 淡粉紫这一段。饱和度和亮度仍自由变异。

**这个物种就是粉色的。** 家族色系在粉色区间内分化，比"什么颜色都可能"更有物种认同感，而孟德尔遗传带来的隔代惊喜完整保留。

| 性状 | 色值 |
|---|---|
| 樱花粉（最常见基色） | `#FFC8DE` |
| 桃粉 | `#FF9EB5` |
| 珊瑚粉 | `#FF8FA3` |
| 淡粉紫 | `#E8A7D8` |
| 玫红（稀少 —— 需要双亲都携带低色相等位基因，靠分离凑到一起，见 §4.1） | `#FF4D8D` |
| 腮红 | `#FF6B9D` |
| 瞳孔 | `#2D1240`（**不用纯黑** —— 纯黑在粉色身体上显得空洞） |

花纹四种：**圆斑 / 环纹 / 云斑 / 星点**（星点是身上散落的小亮点，像雀斑，在暗水里会单独发光）。

**蛋色是另一张表（2026-10-20 新增）**：马卡龙六色 + 白 + 黑，见 §11 的 `EGG_TINTS` 与 `EGG_TINT_BANDS`，黑蛋占表尾 2.5% 那一段。**身体锁粉色这条没有变** —— 用户那句"它们之间可以有不同颜色"要不要连身体一起放开，已在 §13.2 第 1 条裁定为**不放开**：照片那只就是粉的，而 `tests/simulate.mjs` 有一条色相区间断言挂在这上面，不放开意味着那条断言一个字都不用改。

**花纹在毛绒上要主动让路**：alpha 压到 0.35 左右（§5.1 第 3 层）。"绣在毛里的图案"和"印在塑料上的图案"不能同时成立，而这次要的是前者。副作用是好的：**星点**这一型在毛上反而比在凝胶上更好读 —— 它现在看起来像毛尖沾了一圈亮粉。

### 4.3 背景：深靛紫而非冷蓝黑

原来的深蓝黑会**压制**粉色（接近补色对抗，粉色会显得脏）。改用深靛紫渐变：

```
#0B0620  顶部深水
#1A0B2E  中部
#2D1240  底部
微粒：#FFD9E8，alpha 0.15–0.4，缓慢上浮
```

靛紫与粉色在色环上相邻，所以**和谐**；但明度差极大，所以粉色生物光依然**对比强烈、像在发光**。这是"可爱"和"梦幻"能同时成立的关键。

### 4.4 需求：四条匮乏度

全部为 0–1，**0 = 满足，1 = 极度匮乏**。

| 需求 | 上升于 | 满足于 | 基因调制 |
|---|---|---|---|
| `hunger` 饥饿 | 时间流逝 | 吃到食物 | 体型大、`gluttonous` 高 → 上升更快 |
| `energy` 精力 | 活动 | 休息 / 睡眠 | — |
| `social` 社交 | 独处 | 附近有同伴 | `clingy` 高 → 上升更快 |
| `safety` 安全感 | 被戳、被欺负、被逼近 | 安静环境 + 亲属或常在一起的伙伴在旁 | `bold` 高 → 上升更慢 |

**需求的角色**：需求**不直接决定行为**，而是为 4.10 的效用评分提供"紧迫度"这一项。所以最匮乏的需求会强烈地推高相关候选行为的得分，但不会一票否决其他行为 —— 一只极饿但正被大只逼近的生物，仍然会选择先逃。**这个竞争关系正是行为看起来"像活的"的原因。**

### 4.5 情绪：并存向量，不是互斥状态机

**情绪向量恰好六个分量**：`joy` `anger` `fear` `curiosity` `sleepy` `arousal`，各 0–1。

- **带惯性平滑趋近**目标值 —— 生气不会瞬间消失，会持续一阵再慢慢平复。这是"生物感"的关键。
- **关键决定：情绪可以并存。** 一只生物能同时"害怕 0.7 + 好奇 0.4"，即想靠近又不敢。行为由加权竞争决定，**表现由主导情绪决定，但次要情绪会泄漏出来**（害怕地缩着，却还是微微往前探了一点）。

这正是"你能读懂它"的丰富性来源：它不是显示一个状态，而是**同时表达好几层**。2026-10-20 之后这句话更关键了 —— **它会说话之后，这一层反而成了主要通道**：文字只能说一句"要摸摸"，而"社交匮乏 0.8 + 好奇 0.3 + 困 0.2"这三层同时存在的东西，只有身体表达得出来。

> **注意：`affection`（依恋/卖萌）不是情绪向量的分量。** 它是 `memory` 里的**关系性数值**（针对某个特定对象，见 4.8），因为"依恋谁"本质上是关于一段关系的，不是关于当下状态的。
> 下表把"卖萌"列为一种**表达状态**，它的触发条件是：`memory[PLAYER].affection` 高 **且** 玩家的手在附近 **且** `joy` 不低。它由记忆 + 情境共同触发，而不是由一个独立的情绪分量驱动。

#### 情绪 → 身体语言与体色（本项目的灵魂）

| 情绪 / 表达状态 | 身体语言 | 体色 | 发光 |
|---|---|---|---|
| `joy` 开心 | 膨胀成圆球、轻快上下浮动、小幅弹跳、蹭玩家 | 亮桃粉 `#FF9EB5` | 光晕扩大，缓慢脉动 |
| `anger` 生气 | 剧烈颤抖、身体压扁且前端变尖、冲刺撞对方、背过身 | 深品红 `#FF1F6B` | 高频急闪，光晕收紧变刺 |
| `fear` 害怕 | 摊平贴缸底、缩成一小团、急逃、躲到缸壁角落 | 褪成灰白粉 `#D8C4CC` | 收缩到只剩核心一点 |
| `curiosity` 好奇 | 身体朝目标伸长、缓慢靠近、前端左右摆 | 偏蜜桃橙粉 | 光晕前移集中 |
| `sleepy` 困倦 | 下沉瘫在缸底、形变幅度极小、缓慢起伏 | 暗粉紫 `#8E6A8C` | 脉动慢到几乎停止 |
| `arousal` 兴奋 / 社交高峰 | 绕圈、**与对方脉动同步**、轻触、膨胀展示、尾巴高举 | 粉紫 ↔ 桃粉双色交替 | 全场最亮 |
| 卖萌（记忆驱动，非情绪分量） | 贴着手指蹭、翻肚皮、吐小泡泡、轻撞玩家的手 | 最柔樱花粉 + 腮红泛开 | 呼吸式柔和脉动 |

> 上表的"身体语言"列自 2026-10-20 起**隐含包含尾巴与蹦跳**：尾巴的摆速/幅度、蹦跳的频率/高度都是情绪的读出通道，规则见 §4.7.1 与 §4.7.2。不逐行重写是为了避免"六行表格 × 三个通道"变成一张没人维护的矩阵。

#### 4.5.1 五档心情（2026-10-20 新增）

用户要的是"心情有安静、伤心、快乐、幸福、愤怒"。六分量情绪向量已经存在且带惯性，**不推翻它** —— 心情是它的**只读派生量**：一个纯函数 `moodOf(emotions, needs, memory)`，返回五档之一。谁都不许把它当状态写回去，那是 §4.5 刚否决过的互斥状态机。

| 心情 | 判据（**按此顺序**，取第一个命中的） |
|---|---|
| 愤怒 | `anger ≥ 0.5` |
| 伤心 | `joy < 0.25 且 (fear ≥ 0.4 或 近期有死亡/被欺负事件)`，或 `social ≥ 0.7` |
| 幸福 | `joy ≥ 0.6` 且 四条需求匮乏全 `≤ 0.25` 且 `memory[PLAYER].affection ≥ 0.6` |
| 快乐 | `joy ≥ 0.45` |
| 安静 | 以上都不成立（默认档） |

**顺序本身就是设计**，不是排版。愤怒必须排第一：一只又饿又气、但 `joy` 还有 0.65 惯性残留的个体，如果先过"幸福"判据，就会报出"幸福" —— 那是假话，而且假得能看见（它同时在颤抖）。把 幸福 放在 伤心 之后也是同一个理由：`joy` 高但刚死了同伴的，应该报伤心。

**为什么非要这一档**：语言层需要它（§4.13）。情绪向量是六个连续量，选不了词 —— 一只生物不会说"我 joy 0.62 arousal 0.11"，它说的是"喵喵 开心"。**心情档是连续的六分量内核与离散的词表之间唯一的桥**，所以它必须存在，且必须只有一个定义点。

阈值全部进 `CONFIG.mood`，可调（属于 §12 授权范围，实现时按观感定，无需再确认）。`moodOf` 必须能在 Node 里测：给定六分量 + 需求 + 记忆，断言档位；并断言它**不修改任何入参**。

### 4.6 眼睛与朝向：可爱最大的杠杆

毛绒五角星靠形变表达情绪是好的，但在**"身体必须独立可读"**这条设定下（§1 原则 1），**眼睛仍然是信息密度最高的通道**。眼睛属于身体，不是漫画外挂。

它与 §4.13 那个文字气泡是**两条不许互相代偿的通道**：眼睛不许画成"气泡里那两个词就能替代的东西"，气泡也不许替眼睛说话（说"开心"的同时把眼睛画成开心，是允许的冗余；但**只**说"开心"而脸上什么都没有，就是失败 —— 那正是 §9.2 第 7 条要抓的情形）。

**先定义朝向（`facing`）**：一只软体团子必须有明确的"前端"，否则"前倾""后移""背过身"全都无从谈起。

```
facing = 单位向量，由速度方向平滑插值得到（转向有惯性，不是瞬间掉头）
静止时  = 保持上一次的 facing（它不会失去朝向）
朝向改变的速度由 bold 基因调制：胆大的转身果断，胆小的迟疑
```

眼睛长在 `facing` 一侧，垂直于 `facing` 的方向上左右分开。所有眼睛参数的"前/后"都指**沿 `facing` 方向的偏移**。

用**四个连续参数**驱动，不用预设表情：

```
pupilSize   瞳孔大小 0–1
lidOpen     眼睑开合 0–1
eyeSpacing  两眼间距（惊吓外扩，生气内收）
eyeOffset   沿 facing 的位置偏移（前倾=好奇，后移=害怕，上望=卖萌时叠加一个垂直分量）
```

| 情绪 / 心情 | 眼睛 |
|---|---|
| joy 快乐 | 眯成两道上弯弧 `^^`，`lidOpen ≈ 0.3` |
| **幸福**（§4.5.1 的最高档） | **星星眼**：瞳孔画成四角星，`pupilSize ≈ 0.8`，随 `arousal` 轻微旋转与缩放 |
| **伤心** | **委屈眼**：`lidOpen ≈ 0.55` 但**下眼睑上抬**（不是上眼睑下垂），`eyeSpacing` 外扩，瞳孔放大且**整只后移**，高光偏到眼睛下缘 —— 看着像含泪 |
| anger | 瞪圆但上眼睑压低，`pupilSize ≈ 0.25`，`eyeSpacing` 内收 |
| fear | 瞪到最大，`pupilSize ≈ 0.15`，`eyeOffset` 沿 facing 后移 |
| curiosity | **一只眼睁大一只微眯**，瞳孔放大，`eyeOffset` 前倾 |
| sleepy | 半闭，极缓慢地眨 |
| 卖萌 | 瞳孔放到最大 `≈ 0.95`（婴儿式），叠加向上的垂直偏移（微微上望） |
| 信任玩家 | 看着玩家的手时**缓慢眨一次眼**（猫的 slow blink） |
| 死亡 | 眼睛缓缓闭合，`lidOpen → 0` |

眼睛大而圆，占身体宽度约 28%。瞳孔用深紫 `#2D1240`，**不用纯黑** —— 纯黑在粉色身体上显得空洞。

> **⚠️ 2026-10-20 三处新增，与参考照片对过：**
> 1. **`快乐` 与 `幸福` 分家。** 原表只有一条 `joy → ^^`。新要求是"高兴变成星星眼"，但如果 joy 一过 0.45 就切星星眼，那星星眼会变成常态，最有力的表情就贬值了。所以按 §4.5.1 分两档：**快乐 = `^^` 眯弧（常见），幸福 = 星星眼（稀有，要 joy 高 + 四条需求全满足 + 对玩家好感高同时成立）**。稀有才是奖赏。
> 2. **委屈眼是新增的独立形态**，不是 `fear` 的复用。区别必须看得见：害怕是"整只收缩 + 后移 + 瞪圆"，委屈是"下眼睑上抬 + 含泪高光"。两者共用一行会导致伤心的生物看起来像在怕什么，那是错的归因。
> 3. **照片里那只"黑眼睛"仍然用 `#2D1240` 画**，不改成纯黑。`#2D1240` 的明度已经低到在粉色卷毛上读作"黑眼珠"，但比纯黑多一点点紫调，不会在粉身体上出现空洞感 —— 这条原则和照片不冲突，所以不动。
> 4. **眨眼频率成为性格的读出通道**：`blinkInterval = base / (0.4 + activity)`，好动的眨眼勤、安静的半天一次。这条与 §4.7.2 的蹦跳同源，都由 `activity` 驱动。

**"看着玩家的手"**：当玩家的手指/光标在附近时，`facing` 会缓慢转向它（好感高时主动转，好感低时反而转开）。这个"它在看你"的感觉，比任何表情都更能建立联系。

#### 4.6.1 眼睛长在身体的哪里（2026-10-22，F-2 修复的裁定）

B20 用真像素量到 **8/8 只的眼盘有 9.3–12.4% 落在星形轮廓之外**（像素侧独立印证：6/8 只的
其中一只眼外缘 alpha 只有 4–119，而眼心恒 255）。根因不是"某个常量填大了"，是**方向**：
`facing` 那个方向本身就是一根星臂的尖（`starRadius(0) = outerRatio`），而锚点是"沿 facing 前移 +
垂直分开"，于是两只眼刚好落在臂的**斜面**上 —— 那里轮廓正从内凹 0.62 爬向臂尖 1.0（**这个数在
D-1 之后是 0.71**，见 §4.7.3；本节其余的数都是 0.62 那一版量的，而凹口变浅只会给眼睛更多余量，
所以那四条裁定照旧成立），而斜面中段
（约 ±50°）比眼盘需要的空间窄。四条裁定：

1. **基准眼位从斜面挪到两根前臂尖上**：`forward` 0.15 → 0.09，于是基准眼角落在 **±66.8°**
   （2026-10-23 用 `eyeAnchorsInto` 实测的；本节原本写"±72°"，那是"臂尖在 ±72°"被顺口写成了
   "眼也在 ±72°" —— 差 5.2°，紧挨着臂尖而不是正压在臂尖上）。也就是星形最宽的那一带。
   spacing 保持 0.42（spec §4.6 的"约占身体宽度 28%"一个字没改）。
2. **一次径向兜底（`fitK`），但它是安全网而不是常规路径**。扫遍
   (`forward` × `spacing` × `sadSpacing`) 的 105 个组合，能同时满足"不出界 + 两眼不相碰 +
   后移不越过中心线"的是 **0 个**（0.62 那一版量的）—— 因为修正项是在**不随星形旋转**的直角坐标里加的，
   而轮廓半径是角的**非单调**函数。
   > **D-1 之后重跑同一个扫描（`.superpowers/sdd/tmp/c2-scan.mjs`，2026-10-23）：60 / 105 可行。**
   > 凹口从 0.62 浅到 0.71 就把"无解"翻成"六成有解"，而这**恰好是这道兜底最硬的理由**：
   > 眼睛常量能不能自洽，由一个眼睛层**不拥有**的常量（`STAR_INNER_RATIO`）说了算。
   > 常量挑得到的只是"现在不出界"，挑不到"以后也出不了界" —— 所以让几何自己兜底。
   眼盘越界时沿"体心 → 眼心"射线等比收回（只收不推，留 `fitMargin = 0.05r`）。
   角度必须在 **facing 相对系**里算 —— 在屏上算会在 facing 一转之后用错角度（有条旋转不变性测试钉它）。
   兜底在真实表情集合上**仍然不 binding**（`fitK ≡ 1` 那条断言没动，凹口变浅只会更宽松）。
3. **径向收回与 §4.6 的坐标契约有冲突，冲突被写下来而不是藏起来**：收回同时动两个轴，
   所以"eyeSpacing 只动垂直轴"这条契约的成立范围是**合法参数区间**，不是全体实数。
   于是那两条既有测试的探针从 0.7 / −0.2 退到合法区间内（0.55 / −0.10），
   另加一条测"越界之后发生什么"（收回，但不抹掉 facing 方向、不把眼甩出本体）。
   **改探针不是放宽判据**：契约本身一个字没动。
4. **一条正向不变量**：`forward × 2 > max(sadOffset, fearOffset)` —— 否则那格表情会把眼睛
   挪到中心线后面去（= 后脑勺）。`sadOffset` 0.18 → 0.10、`fearOffset` 0.22 → 0.12 都是被这条压下来的；
   方向（"整只后移"）是 spec 的，幅度归 §12。反过来 `sadSpacing` 试过降到 0.04，**被探针退回来了**：
   `forward` 修好之后 0.10 已经在轮廓之内，再缩就是把"委屈外扩"这格表情改弱。

### 4.7 可爱的两个物理机制

**幼态比例（neoteny）**：可爱有生理基础 —— 大眼、圆身、短小、动作笨拙（婴儿图式 baby schema）。所以：

- 眼睛比例偏大，且**成体也保留幼态特征**（不像真实动物那样长大后眼睛比例变小）
- 身体更圆更短，`wobble` 基因整体偏高 → 形变更明显
- 幼体与亚成体的移动带**轻微笨拙感**：偶尔冲过头、撞到缸壁、跌一下再爬起来。**这不是 bug，是可爱。**

**Q 弹物理**：形变必须带**过冲回弹**（squash & stretch + overshoot）：

- 落地/停下时先压扁再弹回，弹回时**超过**原尺寸一点点再收敛
- 移动时身体有延迟跟随的惯性抖动（像果冻）
- 挤压幅度由 `wobble` 基因决定，所以有的孩子天生更 Q，有的更挺

**毛绒质感（2026-10-20 新增，第三个机制）**：照片上那只的可爱有一半来自卷毛。规则与被否决的做法：

- 身体轮廓是**五角星软体**（§5.1），毛画在轮廓法线方向上向外伸，长度 = `fluff × 0.18 × 身体半径`
- **只画"毛尖的浅色碎边"，不画"有颜色的毛"。** 这一条是性能上的生死线：卷毛的质感其实来自两件事 —— 边缘的碎毛轮廓，加上毛尖那一层比体色亮一档的反光。既然碎边是半透明的浅粉白，它叠加在**任何**体色上都成立，于是毛边只需 **2 张预渲染 sprite**（常态 / 受惊收缩）。如果按"每根毛都有自己的颜色"去做，就要 32 色相桶 × 8 蓬松档 = 256 张 sprite，或者每帧画 24 只 × 120 段贝塞尔 = 2880 段路径 —— 后者直接违反 §5.3 的预算，手机必崩。
- **毛必须跟着形变走**：身体被压扁时，毛边 sprite 用**同一个 squash 变换矩阵**一起变换（一次 `drawImage` + `setTransform`，极便宜），而不是重新计算毛的位置。毛如果独立于身体动，视觉上就变成一圈光晕，那正是 §4.3 已有的东西，等于白画一层。
- 被摸时那一段的毛要**倒伏**（近手侧一小段压毛带 + 短伏毛），这是"它感觉到了"的直接证据，进 §8.2 清单。**2026-10-26 做了抚摸这一半**：复用 `body.petX/petY` 的局部方向，不改两张 fluff sprite 的预算，也不碰内核判定。**被戳时局部炸开仍没做** —— 今天只有整体 `fluffSprite` 档位随 anger 切换；那是另一条独立表现，不在本轮。

#### 4.7.1 尾巴：新增的第三条读出通道

用户明确要"有尾巴""可以通过表情和尾巴表现"。规则：

```
结构   = 3 段链，Verlet 跟随身体挂点（挂点在星形后侧的那个凹角）
长度   = 0.5 × 身体半径（**不新增基因**，由 size 派生 —— 性状已经够多了，加位点要付测试代价）
摆速   = base × (0.4 + activity) × (1 + arousal)
幅度   = 心情档决定：幸福 > 快乐 > 安静 > 伤心
```

| 心情 / 情绪 | 尾巴 |
|---|---|
| 幸福 | 竖直高举 + 快速大幅摆（"整个屁股都在摇"） |
| 快乐 / 卖萌 | 中幅快摆 |
| 安静 | 低频慢摆，偶尔甩一下 |
| 伤心 | 垂着不动，尖端轻微卷 |
| fear | **夹起来**（收到身体下方、幅度趋零） |
| anger | 炸开（sprite 换成蓬松那一档）+ 急促前后抽 |
| 死亡 | 松掉，随身体下沉漂开 |

尾巴与眼睛是**冗余通道**，这是故意的：只靠眼睛表达高兴，玩家在小屏幕上（手机竖屏、生物只有 30px）会漏读；两条通道同时说同一件事，读出来的概率翻倍，而**不一致**的时候最有趣 —— 摇着尾巴但眼睛是委屈的，就是"嘴上说没事其实有事"。

#### 4.7.2 蹦跳：新增 `hop` 意图

用户要"会蹦蹦跳，越好动的个体越喜欢蹦蹦跳，蹦的越高频率越快，但是累了会休息"。这不是表现层的自由发挥，**必须进内核的效用评分**，否则"累了还跳"没法被系统知道：

```
候选新增：hop（蹦跳）
score(hop) = 性格权重(activity) × joy 倾向 × energy 可用性 × 情境可行性
             └ energy 低 → 该项塌陷，rest 得分自然超过它 ⇒ "累了会休息"是涌现的，不是 if 出来的
最小持续时间 = 0.6s / (0.3 + activity)      ⇒ 好动的跳得勤
跳起冲量     = base × (0.5 + activity)      ⇒ 好动的跳得高
落地         = 走 §4.7 的 squash & overshoot，能量消耗计入 energy
```

> **⚠️ breaking**：`INTENTS` 从 12 项变 13 项（本节的 `hop` 与 §4.10 的 `brood` 各加一项，同时删掉 `court`，净 +1）。它是**冻结数组**（Tasks 9-11 预飞审查特意钉过 `INTENTS` 未冻结的问题），`tests/behavior.test.js` 里有按 12 项写的断言，`tests/simulate.mjs` 的意图统计也会多一列。加之前先数一遍有多少条测试会红。

#### 4.7.3 五角星的剖面照素材重定（D-1，2026-10-23）

玩家配了一套 `assets/star_puff_*.png`（八张表情 + 头像 + 图集），并指定"星星像这样"。
缸里仍然是程序化的（裁定：素材留给计划 3 的 HUD，缸里改形状函数），所以这次改的是 `starRadius`。

**量法两步，缺一不可。** ① 零依赖解 PNG（`zlib` + 手写 unfilter），取 alpha>128 的实心轮廓，
360 条射线各二分找轮廓半径（`.superpowers/sdd/tmp/measure-star.mjs`）。② 把这条轮廓按 72°
**对称化**（`.superpowers/sdd/tmp/d1-phase.mjs`，瓣尖相位 55°+72k，代价函数取"凹/尖最小"的那个对齐 ——
错相位会把凹口抹平，五瓣离差对相位几乎不敏感，不能用）。

只走①得到的数是**错的**，而这一版就这么错过一次：素材那只戴睡帽、有手脚，
直接取 `min/max` 读到 0.545，那只是"帽子压在左瓣上"的一条深沟。据此把 `innerRatio` 定成 0.55
并新加一个 `tipPower=3.2` 的钝度旋钮，结果缸里开出一朵五瓣花。对称化之后的真数：

| 量 | 素材 | 改前（线性 / 0.62） | 错的那一版（幂 3.2 / 0.55） | **现在（smoothstep / 0.71）** |
|---|---|---|---|---|
| 凹口 / 瓣尖 | **0.710** | 0.620 | 0.550 | **0.710** |
| 逐点 RMS（对素材对称轮廓） | — | 0.0557 | 0.0635 | **0.0117** |
| 最大逐点偏差 | — | 0.091 | 0.161 | **0.021** |

四条裁定：

1. **凹口深度 0.62 → 0.71。** 逐瓣单独量的凹/尖是 0.55 0.56 0.64 0.69 0.70 0.70 0.77 0.77 0.77 0.80，
   中位 0.695 —— 与对称化的 0.710 同向，取后者（最小二乘拟合的最优值是 0.716，圆到 0.71）。
2. **过渡形状从"角度上线性"换成 smoothstep**（`t²(3−2t)`）。素材的轮廓**两头都是平的**：
   瓣尖 ±3° 内几乎不掉半径，凹口底部也走平。线性在两端导数非零 ⇒ 尖角 + V 形沟。
   把凹口调到 0.71 而形状仍用线性，RMS 只降到 0.027，**仍不合格** —— 所以这一条不是深度那条的附赠品。
3. **不加幂次旋钮。** 在 smoothstep 之上再乘一个 `t^p`（最优 p≈1.16）只把 RMS 从 0.0117 买到 0.0038，
   最大偏差从 0.021 到 0.011 —— 在 r=15px 的个体上是 **0.15px**，读不出来。
   按"没有生产者就不许有旋钮"那条，`tipPower` 已经删掉，`CONFIG.star` 回到三个键。
4. **渲染层真正吐出来的那条曲线也复证过。** 身体只有 24 个采样点，而五个尖里只有 facing 那一个
   正好落在采样上（72° 落在 60 与 75 之间），其余四个由 Catmull-Rom 插出来 ⇒ 会被削。
   按 `render.js:buildBodyPath` 逐字同式把 24 点展成贝塞尔再采样：RMS **0.0127**（只比解析式差 0.001），
   四个离相位尖削到 0.996，凹口**画出来是 0.722 而不是写进去的 0.71**（样条把沟填平 0.012 ≈ 0.2px）。
   不为这 0.012 反向补偿 —— 那是把常量绑死在采样数上。

**这一处改动没有第二个出口**：`starRadius` 是身体轮廓、毛边 sprite（`render.js:1386` 同源）、
眼睛兜底 `fitK`（§4.6.1）与尾巴挂点共用的那一个函数，所以它们**自动**跟着变胖；
凹口变浅只会给眼睛**更多**余量（`fitK` 在真实表情集合上仍恒等于 1，那条断言没动）。

> **仍未验证的部分（如实记）**：本轮 in-app Browser 的 `evaluate_script` 被权限分类器拦下，
> 所以"缸里真像素"这一环没有做，上面那张表是**渲染层曲线的几何复证 + 离线光栅化看图**，
> 不是浏览器里截到的帧。清单里那一行留给玩家自己的眼睛。

### 4.8 关系记忆：它记得谁对它好

每只生物对其他个体维护一条记录：

```js
{ id, familiarity /* 熟悉度 0–1 */, affection /* 好感 −1..1 */,
  kinship /* 亲缘系数 */,
  role /* mother|sibling|offspring|companion|null */ }
```

> **2026-10-20 随孤雌制调整**：`father` 不再写入（存档里那个键保留、恒 `null`，理由见 §7.2）；`mate` 这个角色**删除**，改为 `companion` —— 长期凑在一起、会自发同步脉动的那只。它不是配偶，因为这套繁殖里没有配偶这个概念，但**关系本身必须留着**：§9.2 第 2 条"你能看出两只之间的关系"靠的就是它，删了 `mate` 而不补 `companion`，缸里就只剩血亲一种关系，那太单调了。

- `affection` 由互动累积：喂食 / 抚摸 / **同步脉动** / **守巢与共同孵化** → **+**；抢食 / 撞击 / 欺负 → **−**
- **恩怨指数衰减趋向 0** —— 会淡忘。但 `companion`、母子的衰减极慢，近乎不忘
- `kinship`：父母与同胞 0.5、祖孙 0.25 → 用于**近亲回避**与**亲属偏好**（更容忍亲属靠近）
- **对玩家也维护一条同结构的记忆** `id: 'PLAYER'` —— 这是"手机上喂过它，回到电脑上它还认得你"的实现基础。好感高的会主动游向玩家的手卖萌；好感低的会躲开；被戳多了的一见手就逃
- **容量上限 12 条**，超出时淘汰 `familiarity` 最低的 —— 多代之后内存不会无限增长，而且"遗忘"本身就是真实的
- **但玩家那条豁免 `familiarity` 衰减、也永不被淘汰**（2026-10-14 裁定）。理由：上面两条在本节里是冲突的 ——
  "它还认得你"要求这条记忆持久，而 `familiarityDecay 0.004`（半衰期 173.287 秒）加上"淘汰 `familiarity` 最低的"，
  会让"在热闹的缸里玩家十几分钟不互动"这件事**把玩家整个忘掉**：`memory[PLAYER]` 被当作全新关系重建，
  好感归零，"好感高的会主动游向玩家的手卖萌"随之失去依据。
  豁免只针对 `familiarity`（认得你是谁）→ 持久；**`affection`（此刻对你什么感觉）仍按普通速率衰减**，
  以保住本节"恩怨指数衰减趋向 0 —— 会淡忘"。这样两个字段各司其职，两条设计意图都成立。
  容量上限**不因此松动**：永远只有 12 条，只是换一个个体被忘掉。
  离线期间本就不受影响 —— 见面时世界冻结（见 §9.2 验收标准 5），不推进就不衰减。

#### 4.8.1 听进去的话（2026-10-20 新增）

用户要"可以给它讲东西，让它记住，做出个性化反馈和个性化表达"。**先把能力边界写死，因为它决定这套实现值不值得信**：规则引擎这一档做的是**记住并复现关键词**，不是理解语义。

**它能做到**：

- 你在输入框里打「宝宝今天也要好好吃饭哦」，它按标点与空白切、去停用词、中文再按 2–3 gram 兜底，抽出实词候选
- 按 `intellect` 与 `curious` 决定这一次听进去几个词、总共能存几条：`HEARD_CAP = 4 + round(intellect × 8)` ⇒ 傻的存 4 条，聪明的存 12 条
- 存下的词进入它自己的词表，在**相关情境**下冒出来：存了「吃饭」，在它 `hunger` 高时说出来 ⇒ 看起来就是"它记得你说过吃饭，而且它现在想吃"
- 第一次听到某个词时它当时的心情会给那个词定价（正价 / 负价）。于是你常叫的名字它会回头，你拿来骂过的词它会躲

**它做不到**：区分"今天"和"明天"、回答你的问题、把两个词组合出新意思。**那些是可选 API 那一档的事**（§4.13.2），不许在规则档里假装能做到。

```js
heard: [ { token, price, boundMood, boundNeed, heardAt, lastUsed, uses } ]
```

衰减与淘汰沿用 §4.8 那套指数淡忘，但 `uses` 高的半衰期加倍（被反复说的词记得牢）。**`heard` 不占关系记忆的 12 条配额** —— "记得你说的话"和"记得你"是两回事，混在一个池子里会让热闹缸里的对话把玩家本人挤掉。

##### 4.8.1.1 实现裁定（2026-10-21，Task A7）

1. **条目是七个键，不是原先写的六个**：多了 `boundNeed`。上面那个例子（"存了吃饭，在它 `hunger` 高时说出来"）要求把词与**当时的需求**绑在一起，只存 `boundMood` 做不到 —— 心情是 sad 不等于那条匮乏是饿。`recall` 的相关性判据就是 `boundNeed === 现在最紧的那条需求`，这是规则档能做到的"情境联想"的全部形状：不查语义、不建索引，只保留当时的处境。
2. **淘汰比的是 `(1 + uses) × 剩余强度`，不是光比剩余强度。** 这不是优化，是防一个自相矛盾：只比强度的话，刚听到的词此刻是 1.0，而反复说过六次的老词是 0.99，于是**新词永远挤掉老朋友**，"反复说的记得牢"这句话会在淘汰那一步被自己推翻（第一版实测就栽在这里）。
3. **`recall` 是纯读的**，不写 `lastUsed` / `uses`。否则"反复听到才记得牢"会被它自己的复述刷成永生 —— 那是本节没有规定的新机制。与 §4.13.1.1 第 1 条同一界线：语言不许改变世界。
4. **"它会躲"在内核里的形状是"它自己不再提这个词"**（`price ≤ suppressBelow` 的条目不参与召回），不是"它后退"。后退属于表现层对 price 的读取（B 阶段）。**不许把前者说成后者。**
5. **"近邻词"在规则档里只能实现成"同一张词表里的另一个词"**，不是语义相近。语义相近是 API 档的事，这里不许假装做到。
6. **`hear` 对 `opts.need` 不设默认值，缺省抛错。** 默认成 `'hunger'` 的症状是"它总在饿的时候提起任何词"，一个听起来还算合理的错，比抛错难查十倍。
7. **实现落在独立模块 `src/heard.js`，没有并进 `memory.js`**（这是对计划的偏离）。理由：memory.js 是一组严格的**五键关系条目**契约（`remember()` 逐键校验、`decay` 按 role/kinship 分速率、`prune` 按 familiarity 淘汰、玩家豁免），而 heard 是另一种记录：七键、按 uses 分半衰期、按 strength 淘汰、没有角色。两种记录塞进同一个模块，`decay`/`prune` 就得开始判"这是哪种条目" —— 那正是本文件抓过多次的"一份代码同时伺候两套契约"。两者共享的只有"指数淡忘"这一条数学。

**智力必须是看得见的**：`intellect` 低的个体复述时会说错词（按 `1 − intellect` 的概率把 token 换成词表里的近邻），高的说得准。这是"有的特别聪明有的特别傻"唯一的落地方式 —— 智力得表现为**可观察的行为差异**，不是信息卡上一个没人看的数字。

### 4.9 性格 → 行为调制

性格基因不直接指定行为，而是**调阈值和权重**：

| 基因 | 调制效果 |
|---|---|
| `bold` 高 | 害怕阈值高、更敢接近玩家的手、被打扰后恢复快 |
| `clingy` 高 | 社交匮乏上升快、更倾向靠近其他个体、更常卖萌 |
| `irritable` 高 | 生气阈值低、生气持续时间长、更常撞击 |
| `gluttonous` 高 | 饥饿阈值提前触发觅食、会为食物争抢 |
| `curious` 高 | 新事物出现时好奇增长快、探索半径大、**听进去新词的概率高** |
| `activity` 高 | 蹦跳频率与高度大（§4.7.2）、尾巴摆速快、眨眼勤、**`energy` 掉得更快**（好动的先累，"累了会休息"因此是涌现的） |
| `talk` 高 | 出词频率高、词汇宽度大、萌系特征词多。**低值 = 高冷**：可以整缸生命周期里只说十几句，且句子短 |
| `intellect` 高 | `heard` 容量大、复述准确、词与情境的关联条数多 |
| `broody` 高 | 自产卵间隔短、每窝枚数偏多（2026-10-20 取代 `libido` 那一行） |

**结果**：同一窝出生的孩子，因为基因组合不同，会走出完全不同的生活。这些是涌现的，不是编排好的剧本。

> **⚠️ 2026-10-20 关于"高冷"的一条纪律**：`talk` 低的个体必须**真的少说话**，不许为了"看起来可爱"给所有个体都按同一个频率出词。如果缸里每只都在喵喵，性格系统就是装饰。反过来，最安静的个体仍然必须有**尾巴、眼睛、蹦跳**这三条通道 —— 这正是 §1 原则 1 那条验收（关掉文字层仍要完全可读）存在的理由。

### 4.10 行为决策：效用评分

```js
候选 = [觅食, 进食, 休息, 社交, 自产卵, 探索, 逃避, 卖萌, 蹦跳, 抗议, 争斗, 哀悼, 发呆]

score(候选) = 需求紧迫度 × 性格权重 × 情境可行性 × 情绪倾向
            + 少量随机扰动

选择最高分者；行为有最小持续时间和中断规则（进食被打断会生气）
```

> **⚠️ 2026-10-20 换血：`求偶 court` 删掉，`蹦跳 hop` 与 `自产卵 brood` 加进来，`INTENTS` 从 12 项变 13 项。**
> 数一下：原 12 项（`forage eat rest socialize court explore flee beg protest fight mourn idle`）减 `court` 得 11，加 `hop` 与 `brood` 得 **13**。
> `court` 随 §4.12 改孤雌一起作废（没有受者了）。它的社交需求由 `socialize` 承接 —— **缸里仍然要有社交**，否则一群自产自卵的个体就成了一堆平行运行的机器，§9.2 第 2 条"你能看出两只之间的关系"直接失去依据。`mourn`（哀悼）与 `idle`（发呆）原本就在 `INTENTS` 里，上面那行候选清单是第一次把它们写全。

**求关注是一条升级链，不是一个新意图。** 用户要"最喜欢主人，想要主人的关注，会做一些自己认为可以吸引主人注意的事"。做法是复用已有的 `beg`，加**未被理睬就升级**的规则：

**计数挂在个体身上（`c.begIgnored`），不挂在 `memory[PLAYER]` 上。** 本 spec 早先写的是"升级计数挂在 memory[PLAYER] 上"，2026-10-20 实现时改为挂在个体上，理由是硬的：
记忆条目是**五键的磁盘契约**（`remember()` 逐键校验有限性，`tests/memory.test.js` 钉住"恰好五个键"），
为一个每帧累加的计时器加第六个键，会让 12 条关系记录和每一份存档都长出一个用不上的字段，
而 `decay()` 还得专门跳过它 —— 它是线性秒数，不是指数淡忘的量。
语义完全等价：它只在"玩家在场且不回应"时累加，被理睬或玩家离场即归零，读起来仍然是"这段关系里它被冷落了多久"。

```
玩家的手/光标在附近且它 beg 成功（被抚摸）→ 停在原地，affection +
beg 了 3 秒没被理睬 → 升一级：hop 到手的正前方 / 挡在指针路径上 / 尾巴幅度拉满 / 出词（萌系）
再 5 秒仍没被理睬 → 再升一级：protest（生气、背过身、不理你）
```

**两级的出口是替换而非叠加**（2026-10-20 实现裁定）：到第二级 hop 的加成归零、protest 拿保底分。
若两级叠加，被冷落越久 hop 分越高，读起来是"它越被无视越开心"，正好与这一节想要的表现相反。

"被理睬"在内核里指的是 `isPetting`（温柔的手 **且** 近到能碰上），与熟悉度通道共用同一个谓词 ——
两处各写一遍迟早漂移，漂移的症状是"它按 A 距离认识你、按 B 距离归零冷落账"。
粗暴的手**算没回应**：它要的是抚摸，不是"被碰了一下"。



选效用评分而非状态机的理由：新增行为只要加一个候选项和评分函数，不动其他代码；行为之间的竞争与犹豫是自然涌现的；随机扰动避免机械感 —— **它不该每次都做"最优"选择**。

### 4.11 生命周期：连续生长 + 阶段门槛

默认时长（模拟秒，@1×）。**完整寿命 = 60 + 180 + 300 + 480 + 180 = 1200 秒 = 20 分钟**；从卵到具备繁殖能力的成体需 540 秒 = 9 分钟：

| 阶段 | 时长 | 特征 |
|---|---|---|
| 卵 `egg` | 60s | 缸底微光脉动；快孵化时脉动加快，壳内透出轮廓 |
| 幼体 `hatchling` | 180s | 极小、光弱、几乎只吃和睡、紧贴孵化点、认妈妈 |
| 亚成体 `juvenile` | 300s | 快速长大、好奇强、爱探索、会和同伴打闹、不能繁殖 |
| 成体 `adult` | 480s | 性成熟、体型最大、发光最强 |
| 老年 `elder` | 180s | 体型微缩、动作变慢、光转暗转暖、不再繁殖 |
| 死亡 | — | 停止运动 → 光慢慢熄灭 → 身体溶散成微粒上升消散 |

20 分钟 @1× 是刻意选的：一晚上开着 4× 就能看到十几代，而单只的寿命又长到足以建立感情。这两个目标互相拉扯，20 分钟是折中点，最终靠 `config.js` 调。

**生长是连续插值，不是阶段跳变**：体型、光强、花纹密度都随年龄平滑变化，阶段只是能力门槛。所以你能看见它一天天变大，而不是某天突然换了一个形态。

> **⚠️ 2026-10-20 新增：蛋的大小决定起点，不决定终点。**
> 用户要"越大的蛋孵化出来的个体开始越大，**并且会长大**，越小的蛋孵化出来越小"。拆开写成可实现的三条：
>
> ```
> hatchSize  = EGG_SIZE_MIN + (eggSize − EGG_SIZE_MIN) × HATCH_GAIN     // 出壳体型，直接读蛋大小
> adultSize  = decode(size).adult                                       // 成年体型完全由 size 基因定
>              └ EGG_SIZE_BIAS = 0（控制方不追认蛋大小对成年体型的任何影响）
> 幼体期时长 = STAGE_HATCHLING × (1.25 − 0.5 × eggSize归一)               // 大蛋的幼体期短一点，"追得上"
> ```
>
> **EGG_SIZE_BIAS 为什么是 0。** 我一度把它定成 0.3，理由是"留 0% 的话玩家看不到大蛋的长期痕迹"。**控制方 2026-10-20 明确不追认那条决定**，所以机制撤回、常数归零 —— 未经裁定的行为不写进内核。归零之后其实更贴用户原话：那句"并且会长大"说的就是**起点由蛋定、终点由基因定**，两条通道各管一段，不互相代偿。
>
> 代价如实记在 §9.2 第 11 条：成年之后大蛋和小蛋孵出来的**看不出区别**（同胞会收敛到相近的成年体型），所以"一眼看出哪只是大蛋孵的"这条只在**幼体期与亚成体期**成立。若控制方日后想让它留痕，改 `EGG_SIZE_BIAS` 一个常数即可，结构不用动。
>
> 蛋大小本身：由母方的 `size` 表现型 × `broody` × 营养（`hunger` 低时蛋更大）共同决定，范围 `EGG_SIZE_MIN..MAX = [0.6, 1.4]` 相对值。**所以"喂得好，蛋就大"是玩家能直接感知的因果**，这条比数值本身重要 —— 它影响的是出壳那一刻和幼体期长短，这两段都是看得见的。

**死亡时，附近的个体会停顿、变暗一小会儿** —— 一种非常原始的哀悼。不解释、不提示，你看到就看到了。

### 4.12 繁殖：孤雌自产卵 + 外来血统漂入

> **⚠️ 2026-10-20 整节重写（控制方裁定）。** 原节是「求偶仪式 + 双亲遗传 + 近亲回避」。新要求是"通过下蛋的方式，自己下蛋就可以，不需要交配"。下面先写改完的样子，再写**这个改动带来的一个结构问题** —— 它不是注意事项，是必须一起做第二件事。

1. **触发**：个体为成体或老年前期、`broody` 驱动的间隔到期、`hunger` 低、`safety` 不塌。满足即**自己**产卵，不需要任何对象。
2. **产卵**：1–3 枚（枚数由 `broody` 与营养决定），落在缸底柔软小丘（§5.2）。每枚带 `eggSize`（§4.11）与 `eggTint`（第 5 条）。
3. **基因**：**自体合并** —— `inherit(rng, mother.genes, mother.genes)`，两个配子各自独立地从母方的 `[a, b]` 里随机抽一个，再加 `N(0, MUTATION_RATE)` 变异。`inherit` 内部逻辑**一行不改**，只改第二个实参传谁。
4. **孵化**：时长 = `STAGE_EGG × (0.8 + 0.5 × eggSize归一)` ⇒ **大蛋孵得久**（@1× 约 48s–78s）。出壳时子代记 `mother`；`father` 字段从此恒为 `null`（**保留键而不是删掉** —— 存档 v1 里有它，删了会让所有旧档的 `lineage` 形状变化，迁移成本远高于留一个恒 null 的键）。母亲在幼体期守在附近（`affection` 高时）。
5. **蛋色**：马卡龙六色 + 白 + 黑（用户指定）。**已裁定作为第 10 个外观位点 `eggTint`**（§13.2 第 2 条），表现型按分段最近邻映射到色表，黑蛋占表尾 2.5% 那一段 —— 稀有度是基因位置天然给的，不再单独掷一次骰子（分段细节见 §4.1）。
6. ~~求偶仪式~~ **删除**。原第 2 条那套「相互绕圈 → 体色脉动同步 → 轻触 → 膨胀展示」是整个项目里被写得最动人的画面，但它服务的机制没有了。**它的一部分被搬到别处保住**：绕圈与脉动同步改造成 `socialize` 的高级表现（两只吃饱且互相好感的个体会自发同步脉动 —— 不再是交配前置，而是"它们聊得来"），求偶成功的小铃音改挂在同步脉动上（§5.4）。

#### 孤雌带来的结构问题：杂合度每代减半

自体合并是**近亲繁殖的极限情形**。杂合度按 `H_t = H_0 × (1/2)^t` 衰减，**一代就砍一半**。本缸 @1× 一代约 20 分钟，一小时 3 代 ⇒ 开缸两小时后（约第 6 代）缸里已经没有杂合位点了。

玩家会直接看到的结果：一窝蛋颜色趋同、花纹分化消失、几代之后**全缸长成一个样**。这正是 §4.1 反对"单个数值加权平均"时预言的那个结局 —— 那次写的是"几代之后可能收敛"，这次是**必然，而且很快**。连带地 §9.2 第 3 条"偶尔遇到一次隔代遗传的惊喜"会枯竭：隔代惊喜的机制是分离把两个低值凑到一起，而纯合之后没有低值可凑。

**同时有一个方向反转的好消息。** §9.1 记录的那套灭绝机制（血统坍缩 → 严格近亲闸门把 55/55 个配对全挡掉 → 出生冻结 → 整批老死；4 只创始下 5/8 灭绝）在孤雌制下**消失了**，因为闸门本身没有了。缸不会因此灭绝，但会**变得单调**。所以验收要从"灭绝率"换成"多样性曲线"。

**解法：外来血统漂入（`drift-in`）。** 每 `DRIFT_INTERVAL`（默认 240s @1×）且种群未达上限时，一枚不知谁家的蛋随水流漂进缸，或一只亚成体访客游进来，携带**全新的随机等位基因**。

> **⚠️ 2026-10-20 实测：上面那句"且种群未达上限时"把这套机制变成了空操作。**
> 基线脚本 `.superpowers/sdd/tmp/diag-drift.mjs`（seed 999，8 个世代）：缸从第 1 代起就
> **钉在上限**（alive=24/24，cap=12 时同样 12/12），于是 40 个漂入窗口**全部**被这道门挡掉，
> `driftIns=0`。漂入开了和关着的两次模拟**逐字节相同**。也就是说：只要缸是满的（而它总是满的），
> 漂入就等于不存在，多样性补给为零。**这条策略是我在写 spec 时想当然加的，被实测否掉。**
> 同时被否的还有判据本身："杂合度按 (1/2)^t 砍半"要成立，前提是等位能**恰好相等**；
> 而 `MUTATION_RATE = 0.06` 是施加在 [0,1] 连续量上的高斯扰动，两个等位几乎永不相等，
> 于是按"两等位是否不同"定义的 H 实测 8 代仍停在 **0.97**（理论值应约 0.004）—— 它测的是噪声，不是血统。
> **真正在衰减的是表型方差**：hue 的组内标准差 8 代从 0.19 掉到 0.09–0.13（约腰斩），
> 这才是"缸里颜色变单调"的可测对应物。判据要换成它，而漂入的触发策略需要重新裁定（四个选项见台账）。

- 它是多样性的**唯一**补给源，是把 `H_t` 从指数衰减改成"衰减—补给"稳态的那个阀门
- 它给玩家的是事件感：「水面上飘来一枚蛋」远好过"系统偷偷注入了新个体"，且完全符合 §1 原则 3「世界规则始终自洽」
- **频率是可调的**：漂得勤 → 缸热闹但家系不清；漂得稀 → 家谱好看但单调得快。默认值靠 `tests/simulate.mjs` 实测多样性曲线定，**不靠猜**
- **触发策略已由控制方裁定为 C（2026-10-20）**：满员时不再跳过，而是让**最老的老年个体顺水流漂走**
  （emigrate，**不是死亡**：不记 `deaths`、不发 `death` 事件、不触发哀悼），给新血统腾出这一格。
  缸里没有老年个体时**这一轮放弃** —— 宁可不进，也不降低标准去搬一只成体（那读起来是掠食或杀婴）。
- **选它的理由与实测数字**：原策略"满员就跳过"经基线实测是**空操作** —— 缸长期钉在上限，
  seed 999 × 6 代里 40 个漂入窗口全部落空，**开与关的两次模拟逐字节相同**。
  改成 C 之后同一口径实测色相组内标准差：第 4 代 **开 0.2301 vs 关 0.0869（2.6 倍）**，
  且开着的每一代都不低于关着的；12 次漂入 / 12 次漂走，峰值仍不超上限（23/24）。
- **判据同时换掉了**：`H = 两等位是否不同` 在连续变异（σ=0.06）下 6 代仍停在 0.97（理论应约 0.004），
  测的是变异噪声而非血统多样性。改用**表型方差**，下限检查在 `tests/simulate.mjs`，
  正反两向的 A/B 曲线在 `.superpowers/sdd/tmp/diag-drift.mjs` —— 60 分钟只到第 3 代，
  那时开/关差异还没拉开（两边都在 0.2 上下），所以 A/B 不能塞进 60 分钟的验收里冒充判据。
- 漂入个体的后代与本地血统**无亲缘**，于是家谱图上天然长出新的支系 —— 这是"看得出谁像谁"在多代之后的新来源

**被否决的三条路**（记下来免得后人重推）：

| 方案 | 为什么否决 |
|---|---|
| 把 `MUTATION_RATE` 从 0.06 提到 0.2+ 来补多样性 | 突变是各向同性的随机扰动，重建不了"两个杂合亲本凑出纯合"那种**结构**，只会把 §4.2 精心锁定的粉色区间打成噪点。多样性会涨，物种认同会没 |
| 保留"偶尔有个父方"（社会性父亲 / 邻居贡献配子） | 违背用户"不需要交配"的字面要求；而且一引入父方就等于把整套求偶闸门请回来 |
| 接受单调，把缸设计成"一代就看完" | 与 §9.2 第 3 条直接冲突，也让 20 分钟寿命与 24 只上限失去意义 |

**近亲回避不再存在**（没有交配可言），但 `kinship` 这个量**保留**：它仍驱动亲属偏好（更容忍亲属靠近）与守巢行为，仍是 `memory` 记录的字段，仍进家谱图。删它只会让家谱少一条边，不会让代码变简单。

**种群上限仍用叙事实现**：达上限后 `broody` 评分被压低（表现为"它看了看缸角，又走开了" —— 产卵点已经满了），到期卵不孵化（表现为"这枚卵的光慢慢熄灭了"）。世界规则始终自洽。

> **⚠️ 2026-10-14 的那条实测裁定注（近亲回避不能保证种群健康、seed 999 的 55/55 配对被挡）已挪到 §9.1**，那里保留了完整数据。它记录的灭绝机制随孤雌制一起作废，但**数据必须留着** —— 那是 8 个种子 × 60 分钟扫出来的，重跑一次要两小时，而且它是"结构决定结局"这个判断的唯一证据。

### 4.13 语言系统：它会说一小撮词

#### 4.13.1 规则档（默认，零依赖，离线）

**词汇分三层**：

| 层 | 内容 | 由什么决定 |
|---|---|---|
| 口癖 | 喵喵 / 咩咩 / 呜 / 啵 / 哼 | 候选集由 `talk × clingy` 定（活泼爱撒娇的才有萌系词，高冷的候选集里只有"哼"），**在出生时抽定一次并固化进个体**，随母方的 rng 分叉 ⇒ 同一家倾向同类口癖但不强制 |
| 需求词 | 饿饿 / 要摸摸 / 困困 / 怕怕 / 气气 / 玩 | 四条匮乏度（§4.4）里最紧的那一条 |
| 情绪与称呼 | 开心 / 幸福 / 坏 / 主人 / 自己的名字 / 对方的名字 | 心情档（§4.5.1）+ `memory` |

**句式**：`[口癖]? [称呼]? [状态词] [诉求词]?`，2–5 个 token，**绝不生成完整长句**。它说"喵喵 要摸摸"，不说"我现在想要你摸摸我"。

**频率、宽度、准确度由性格定**：`talk` 决定出词间隔（`SPEECH_COOLDOWN = 18s − 12s × talk`）与候选词宽度，`intellect` 决定 `heard` 容量与复述准确率（§4.8.1）。

> **高冷的正确实现方式是"少说"，不是"换一套更酷的词"**。`talk = 0.1` 的个体在 20 分钟一生里说 8–15 句，每句 1–2 个 token。如果给高冷个体一套"本喵不屑"式的台词，那是在演高冷；而少说话是真的在高冷 —— 而且它省下来的表达负担必须由尾巴、眼睛、蹦跳接住，这正好逼着 §1 原则 1 那条验收成立。

**显示纪律**：气泡浮在头顶，最多 2 行、字号 ≥14px、3 秒淡出，样式跟 `fluff` 走（浅色描边，像绣在毛上）。**同一时刻屏上最多 2 个气泡**，其余排队 —— 24 只一起说话会变成弹幕，而弹幕是这个项目最该避免的东西。

##### 4.13.1.1 实现裁定（2026-10-21，Task A6）

五条，都是实现时才发现"原设计没说、但必须定"的东西，写在这里是为了让下一轮不必重新推导：

1. **出词走一条独立的分叉随机流 `world.speechRng`，不占 `world.rng`。**
   理由不是洁癖：若出词用主流，"关掉文字层"就会让全缸的觅食/产卵/漂入取值整体平移，
   于是 §9.2 第 7 条想要的对照（**关掉文字层，其余状态逐位不变**）根本做不出来，
   而"语言层是只读旁路"就只能是注释里的一句愿望。
   现在这句话是一条可跑的测试（`tests/sim.test.js`：开与关两缸指纹 `deepEqual`），
   而且它已经在探针下被抓过一次（把 `speechRng` 换成 `world.rng` 会当场变红）。
   分叉发生在初始个体投放之后，所以主流的既有取值序列一个都不动。
2. **冷却没到期时一次随机数都不抽。** 否则每次调用都消耗抽样，语言层会独占整条随机流。
   全缸的抽数上界是「个体数 ÷ 冷却秒数」而不是「个体数 × 60」。
3. **开关是运行时状态，不是常量。** `CONFIG.speech.enabled` 只给默认值，
   真正的开关是 `world.speechEnabled`（由计划 3 的设置页写），`maybeSay` 从 `ctx.speechEnabled` 读覆盖。
   原设计写成"`CONFIG.speech.enabled = false`"是**测不了的**：CONFIG 是深冻结的常量表（这是对的），
   测试无法把它改成 false 再改回来。契约不变，只是载体从常量表移到了世界状态。
4. **`talk` 进三个地方**：出词间隔（cooldown）、出词意愿（概率乘子）、候选词宽度（token 预算）。
   只进间隔的话 `talk=0.1` 与 `0.9` 的出词数之比只有 2.3，人眼看不出差别；
   拉进意愿之后才到 5 上下。**断言必须是比值而不是绝对值** —— 断言绝对值的人一调 COOLDOWN 就全线红。
   宽度也要单独钉：只断言"句长 ≤ 5"抓不到任何与 talk 有关的错误（探针实测如此）。
5. **句子组装：必填是心情词（+够紧的需求词），修饰是口癖/称呼/对方名字。**
   超预算时**从修饰的队尾砍起，绝不砍心情词** —— 宁少说一句口癖，不少说"它此刻的感受"。
   凑不到 2 个 token 就是"真的没什么可说"，返回沉默（安静又满足的个体走的就是这条路）。

##### 4.13.1.2 气泡层落地裁定（2026-10-22，Task B19a）

上面那条「显示纪律」只有六个字的要求（最多 2 行 / ≥14px / 3 秒淡出 / 跟 fluff 走 / 同屏 2 个 / 其余排队），
实现时每一条都撞到一个原设计没说的决定。八条，写给下一轮：

1. **"其余排队"必须有上界**：池容量 = `onscreenMax × bubbleQueueMul` = 2 × 4 = **8**。
   原设计只说"排队"，没说排多少。没上界的队列与 `world.events` 那个"每帧不清空就无界增长"同源，
   而 24 只 × 每 6–18 秒一句天天在填它。溢出时丢**排队者里最旧的那条**，
   **正在显示的不被打断** —— 中途撤字等于把说到一半的话吞掉，与这一层要传达的东西正好相反。
   丢了几条、被自己顶掉几条、自然收走几条、截掉几个词，全是**读数**（§7.7 不许静默）。
2. **折行在"上场那一刻"做一次，不是每帧重算。** §5.3 用 `measureText` 相对贵来给气泡定预算，
   每帧重量等于把"上限 2 条"这条预算抹平。**代价如实记录**：一条气泡显示期间视口被拖窄，
   那两行不会立刻重新折行，最多 3 秒（TTL）后自然换掉。这是取舍，不是漏。
3. **气泡跟的是绘制几何，不是 `c.pos`。** B16 之后身体会竖向抬升（跳）与上浮（溶散），
   钉在 `c.pos` 上的气泡会留在原地 —— 症状是"它跳起来了，话掉在地上"。
   锚点 = 那 24 个软体点的包围盒顶边（与 `writeBodyScreen` 同一条变换公式，含 `lift / rise / expand / squashV`）
   再减毛尖伸出的那一圈。不复用 `renderer.sx/sy`：那是逐只覆盖的复用数组，生物循环跑完只剩最后一只。
4. **字号是 CSS 像素，永不乘 `dpr`。** `main.js` 每帧先把上下文缩放到 dpr，绘制坐标与字号已在 CSS 空间里。
   写成 `bubbleFontPx * dpr` 的错法在手机上会把"≥14px"乘成 4.7px（或反过来：位图空间里 14px 只占 4.7 CSS px）。
   由 `tests/render-bubble.test.js` 的"dpr=3 字号不变"与"x 随视口宽缩放而不随 dpr 缩放"两条钉住。
5. **"样式跟 fluff 走"的字面实现是取同一个浅色**：底色从 `CONFIG.colors.mote` 推导、描边取 `eyeWhite`、
   墨色取 `pupil`，都在 render.js 里由既有常量**推导**而不是再抄一份十六进制（否则改毛色不会改气泡，
   而"跟 fluff 走"就只剩注释）。**心情不参与气泡配色** —— 让文字颜色跟着心情变，
   等于把文字通道做成身体通道的复读机，正是 §9.2 第 7 条要防的那种自我重复。
6. **关掉文字层时 `say` 事件连队列都不进**，且池子当场清空。只"不画"是不够的：
   静音期间攒下的旧句子会在重新打开的那一帧一次性喷出来 —— 那就是弹幕。
   这条层的守法是**调用序列前缀**：关掉之后其余七层的桩调用序列必须是开启那份序列的前缀，
   所以气泡必须是 `draw()` 的**最后一段**调用（插在中间，这条判据就废了）。
7. **每帧上界**：`fillText` ≤ `onscreenMax × bubbleMaxLines` = **4 笔**；气泡层**零** `drawImage`、
   **零**新建 sprite（给每条气泡预渲染贴图会破 B14 立的"每只每帧恰好 7 次贴图"上界）、
   **零** `quadraticCurveTo`（圆角用 `arc` 画）。也不用 `ctx.roundRect`：老 Safari 没有，
   而 §1 原则 5 要求这条路在手机上照样成立。
8. **12 个新旋钮全部进 `CONFIG.speech`，只做标量、不加子表**（所以 §11 那两条"节点 47 / 顶层键 48"的计数不动）。
   补偿措施：给 `CONFIG.speech` 补一条**键集 deepEqual**（30 键，数出来的）——
   它是这一段唯一的"加了个没人读的旋钮"守卫。这条与 §4.13.1.1 第 3 条同一界线：
   `CONFIG` 只是默认值，运行时开关是 `world.speechEnabled`。

**已知债务（不是 bug，如实记着）**：① 已在屏上的气泡不随 resize 重新折行（≤3 秒自纠，见第 2 条）；
② 说话的那只被 splice 掉之后，它占的槽位仍要等 TTL 才释放 —— 表现为"少了一条气泡"，不表现为报错。


#### 4.13.2 可选 API 档（默认关闭）

设置页可填一个 OpenAI 兼容端点 + model + key。填了之后，出词改由模型生成，但喂给它的不是原始向量，而是**结构化状态摘要**（心情、最紧的需求、性格三行、刚听进去的话、对玩家好感）。

三条硬纪律，一条都不能省：

1. **失败即回落**：请求失败、超时、被拦、key 无效 ⇒ 立刻回到规则档。**绝不允许出现"填了 key 反而不说话了"** —— 这是 §7.7「绝不静默」的语言版。
2. **模型是只读旁路，不许改世界**：它的产出只有文字。任何情况下都不许因为模型返回的内容去改 `needs` / `emotions` / `behavior` / `memory`。否则一段被投喂的提示词就能操控整个缸，而这个世界唯一的价值就是它自洽。
3. **验收跨档位成立**：§9.2 第 7 条（关掉文字层仍完全可读）在规则档和 API 档下都必须通过。

**如实记录代价**：填了 key，那台设备上的缸就依赖网络和该 key 的存活。`start.bat` 十年后仍能打开的是**规则档**；API 档不做这个承诺。这是对 §1 原则 5 一次**有边界的让步**，边界就是"默认关、可回落、不碰世界状态"。

##### 4.13.2.1 API 档落地裁定（2026-10-22，Task B19b）

上面那一段只有三行纪律加一句代价。实现时把它拆成两半（B19b-i 纯函数层 `src/api.js`、B19b-ii 接线层），
一拆就撞出六条原设计没说的决定，体例同 §4.13.1.1 / §4.13.1.2 / §5.4.1：

1. **API 档是输出侧的旁路（bypass），不是说话的门（gate）。** 内核照旧决定"说不说、什么时候说" ——
   它自己的概率、冷却、`world.speechRng` 一条都不动，照旧发那条带着**规则档文案**的 `say` 事件；
   档位开着时，调用方拿着"已经要说的那一拍"去问模型，成功就把这段文字升级，
   **任何**失败（网络错、超时、401、形状不对、内容被拒）都让规则档那一句原样站着。
   这个方向不是修辞，它把上面三条纪律里的两条变成**结构性质**而不是需要各自验收的行为：
   - **第 3 条（跨档位验收）因此才可证**：开关不改变世界的任何一个字节 —— 零随机数消耗、零字段写入，
     于是 §9.2 第 7 条在两个档位下是**同一条测试**，不必为 API 档再造第二条（再造的那条永远不会有人跑）。
     `tests/sim.test.js` 对 `speechEnabled` 已经用两缸指纹 `deepEqual` 证过一次，
     `tests/api.test.js` 里"真缸每帧穿插调用本层全部函数、与不穿插的缸逐位相同"是同一手法。
   - **第 1 条（填了 key 反而不说话了）因此没有表达通路**：本层每个出口都是"替换 / 不替换"，
     返回值里没有"闭嘴"这一格。请求构造器同样不是门 —— 它拿到的是已经要说的一拍。
     唯一的暗门是超时那侧：`deadlineFor` 若照抄 `start + timeout`，一次时钟回拨（休眠唤醒、跨设备）
     会把 deadline 留在过去，每条请求当场被判超时 ⇒ 症状恰好就是那句话。
     所以它写成"回拨时以当前时刻重新起算"，并有一条测试专门钉住。
   - 反面代价也如实记着：**开了档也不会让它多说一句**。想让它更话痨只能调 `CONFIG.speech`，
     API 档只换措辞、不换频率 —— 这是这条形状的固有结果，不是漏。
2. **模型的全部输出通道就是一个字符串**（第 2 条的字面实现）。`validateReply` 只可能给出
   `{ text, tokens }` 或 `{ ok: false, reason }`，而那一份 `{ text, tokens }` 与规则档 `maybeSay`
   的产物**逐字同形**（`text === tokens.join(' ')` 是同一条等式，不只是长得像）——
   于是气泡层与叫声层认不出这段话是谁给的，"两档不可互换"那一类 bug 在结构上没有位置。
   推论：入参契约错用（budget 越界、没给个体）一律**抛错**，内容不合法一律**带原因的拒绝** ——
   与 speech.js 把"非法心情"抛掉、把"没什么可说"返回 null 是同一条分界。
3. **摘要是一条白名单投影，不是转储。** 八格：`名字 / 口癖 / 此刻心情 / 最紧的需求 / 性格 / 刚听进去的话 / 对玩家好感`，
   外加可选的第八格 `可以照着说`（规则档那句，作为**建议**附上）。六分量情绪向量一个都不进 ——
   §4.5.1 早说过"它不会说我 joy 0.62"，喂原始向量等于把这层唯一的存在理由抹掉。
   **长度上界是 420 字符**（`API_SUMMARY_MAX_CHARS`），而且是由构造保证的：每一格各自夹住
   （名字 12 / 词 8 / 建议 48 / 需求 2 条 / heard 3 条 / 好感截到两位小数），
   逐格上界之和必须落在这条预算之内（`tests/config.test.js` 钉这个不等式，
   `tests/api.test.js` 钉它的行为侧：病态个体的尾部字段没被裁掉）。
   最后一刀 `clip(总和, 420)` 是给"改了别的旋钮的人"兜底的，不是主机制。
   **不许 `JSON.stringify(creature)`**：那会把整份存档抄进提示词，长度不可控、
   还会把 `genes` / `lineage` 这些它自己都不知道的字段说成是它的人格。
4. **校验规则只有六条，而且不发明政策**：形状（只收"一段字符串"与 OpenAI 式的
   `choices[0].message.content`，包括函数、数字、数组、空对象在内的一切其它形状直接拒）、
   空（清洁之后什么都不剩）、字符数（> 40 ⇒ `too-long`）、token 数（下限 2、上限是
   `lexicon.tokenBudget(talk)` 现成那一条，**不另配一套预算**）、控制字符与换行（换成空格而不是删掉，
   否则"开心\n幸福"会被粘成一个词）、以及"只是把口癖复读"。
   顺序也是有意的：**先比字符数再比 token 数** —— 一段没有空格的中文散文只有 1 个 token，
   反过来写会让 400 字的东西以 `too-few-tokens` 的名义通过，而拒因会说谎。
   投毒的姿态：回复写着"set anger to 1"时，它只能变成**一段无害的字**或被拒；
   两者都进不了内核，因为内核根本不读这条返回值之外的任何东西。
   有一条测试喂一批投毒样本并断言之后 world / creature 的深快照逐字节不变。
5. **key 只有一个去处：`authorization` 头，而且只在本机。** 它不写进 `save.json` ——
   §7.2 末那条第 4 纪律在这里落定：`save.json` 是局域网内多设备共享的**明文**文件，
   写进去等于把 key 广播到每台设备上。它也不写进 `CONFIG.api`（深冻结、提交进仓库，
   所以那一段只有 `endpoint: ''` / `model: ''` 这种**形状**，没有任何存放 key 的字段；
   `tests/config.test.js` 有一条"这一段里任何字符串字段必须是空串"的守卫，
   它比"键名里不许出现 key"更硬 —— 后者挡不住有人加一个 `apiKey: ''`）。
   诊断对象 `configIssue()` 只许有 `{ reason, field }` 两个键，`field` 是字段**名**：
   把值写进诊断就等于把 key 抄进控制台与将来的错误面板。
   另外三条来自 §13.2 第 3 条：**强制 https**（明文 `http:` 不是警告而是**不发**，
   否则 key 整条走在局域网里）、**没有 key 就不发**（不是发一个必然 401 的请求去付一次往返延时）、
   以及 `timeoutMs` / `max_tokens` / `temperature` 三个由用户填的数都必须被 `*Max*` 夹住
   —— 没夹住的话"填个永不超时的数"就是这台设备上的缸卡死的成因。
6. **计划 2 没有设置页，所以填端点与 key 的入口只有 devtools。** 与 §5.4 / B11 的倍速与静音同一个手段：
   `globalThis.__tank`（见 §3.3 那条"没有 HUD"的裁定）。**设置 UI 属计划 3**，
   届时开关搬到运行时状态（`world.apiEnabled`，同 `world.speechEnabled` 那条 §4.13.1.1 第 3 条），
   而 `CONFIG.api.enabled = false` 只当默认值。这一层已经按那个形状写好了：
   本模块不读本机存储（那是 main.js 的口子，`localStorage` 这个名字在 src/ 里只许出现在 main.js），
   它只接一个调用方传来的 `cfg`。`buildRequest` 返回的是**一段纯数据描述**
   `{ url, method, headers, body, timeoutMs }` —— 发请求与掐它在 `src/main.js`（B19b-ii 已落地），
   而**定时器一个都没有**：到期扫描本身就是超时机制，见下面第 8 条。
   这条分界不是洁癖：正因为 api.js 一个网络名字都不出现，它才在 Node 里全程可测，
   而 `fetch` 仍然被 `tests/constraints.test.js` 钉在 main.js 一个文件里。
7. **那一拍是"有界地按住"，不是"事后换字"（`API_HOLD_MS = 1200`）。** 接线层（`src/main.js` 的
   `attachApiTier`）遇到 `say` 时**不当帧交付**，而是连原文案一起放进暂存队列，上界 `apiHoldMs`；
   落地（模型成功 / 任何失败 / 到期）时把**当下手上那句**交出去。为什么不选"先按规则档画出来、
   回复到了再换"：§4.13.1 的显示纪律是 3 秒淡出，而实测一缸最坏**单秒 5 句**（B18 那轮量的同一批数），
   4× 下换算是 20 拍/真实秒 ⇒ "回复迟到"是常态而不是边缘情况，事后换字大多数时候换在一个已经淡完的气泡上，
   玩家看到的是"这一档几乎没效果"，而它照样要付每一次往返。
   **代价就只有一句**：开了这一档，那句话最多晚 1200 毫秒出现。它由 `tests/config.test.js` 钉成两条硬不等式：
   `apiHoldMs ≤ 1200` 且**严格小于** `bubbleTtl × 1000` —— 按住比气泡整个生命还久等于把已经要说的一句话
   按到看不见，那仍然是"取消"而不是"延后"。
   **这一处也解释了 `consumeEvents` 的一个连带变化**：那一拍被按住时是整条事件被按住，
   所以「啾」（B18 那条唯一允许的耦合）与气泡**一起**晚一点出现，而不是各响一次。
   这是表现层的时序，世界状态一个字节不动 —— 决策 1 那条"旁路不是开关"仍然成立。
8. **没有定时器：到期扫描就是超时机制。** `src/main.js` 里没有一处 `setTimeout` / `setInterval`，
   队列每帧按 `duePending(p, 时钟毫秒)` 收一次，`api.frame` 同时完成"接管新拍 + 到期释放 + 交付"三件事。
   这样 `stop()` 没有定时器要摘、后台标签页回来不会攒下一堆到期的回调，
   而"迟到的回复"由**代号（token）对不上**判掉并计数（`late`），不会写进后来那一拍。
   缸停了之后还挂着的请求一律 `abandon()` 掐掉，两条读数都留（`aborted` / `droppedStaged`）。
9. **交付数组只有一处非对称，且关掉时是零额外动作。** `step()` 里 `let events = world.events;`
   —— 缺省就是那个数组**本身**（引用，不是拷贝：写成拷贝就每帧一次分配，而 §5.3 禁这个），
   只有 `api.state.active` 为真时才换成 `api.frame(...)` 的产出数组。
   renderer 与 audio 读的**都是** `events`，`world.events.length = 0` 仍由本文件在两个消费方之后做。
   两处源码级守卫（`tests/audio.test.js`「audio.consume 不在事件数守卫里」、
   `tests/render-bubble.test.js`「say 仍然每帧被喂给 renderer」）跟着改读这个局部名，
   并各自**加了一条更硬的**：`events` 的缺省必须是 `world.events` 本身 ——
   否则"关掉 ⇒ 零额外动作"那条断言就成了假话。
10. **暂存队列有上界，而装不下不等于不 说。** `API_PENDING_CAP = 8`，
    刻意**不借** `bubble.js` 的 `bubblePoolCapacity()`：那个函数说的是"屏幕上能挂几条"，
    这里要的是"最多按着几拍等回复"，两回事；借过来还会让页面入口 import 绘制层（`tests/render-bubble.test.js`
    正有一条拦这个）。`pushPending` 返回 0（形状不对、或腾不出位）时，那一拍**当场原样交付**，
    并分别进 `badShape` / `notTaken` 计数；同一只第二次开口时旧的那拍让位（`superseded`）并当场出去。
    于是"这一档开着的时候反而少说话"这一类事故在结构上写不出来 —— 它是 §4.13.2 第 1 条的最后一道。
11. **key 住在本机存储的一个命名空间里，而读数永远脱敏。** `localStorage` 的键是 `tank.api.v1`，
    值是 `{enabled, endpoint, model, key, timeoutMs, maxInFlight}`；读它在 `main.js` 里包 `try/catch`
    （隐私模式下的 Safari 一碰 `localStorage` 就抛），读不出来就**按关着处理**、缸照常跑、
    并且只 `console.warn` 一次。`controller.getApiConfig()` **永远不返回 key 的值**，只返回 `hasKey: true|false`
    与 `source`；写则通过 `setApiConfig(patch)` 落回同一个键。计划 3 的设置页读的就是这两个口。

**如实记录：本轮一次真实端点都没调用过。** 仓库里没有 key，也没有可打的服务，
所以上面每一条都是**桩验证**（stub-verified）：请求形状是断言出来的，不是发出去被服务端接住的。
真实端点才能证明的东西一律没被证明，清单如下，交给计划 3 或任何填了 key 的人复核：
① 端点是否真的接受这个 body 形状（`max_tokens` 是否被当回事、`content` 是否可能返回数组/多段）；
② 401 / 429 / 超时 / 半截 TCP 各自的**回落延时**是否短到"它还在说话"读起来自然；
③ 模型是否真的会照那句"2 到 5 个词，空格隔开"输出 —— 不照做的比例有多高，
   即 `too-many-tokens` / `too-few-tokens` 这两条实际会触发多少次（拒得太多就等于变相 §4.13.2 第 1 条）；
④ 温度 0.7 换出来的措辞是否**更好**（这是这一档唯一的价值主张，桩测不出"更好"）；
⑤ 中文词表气质会不会被英文模型抹平（它可能把"饿饿"升级成"我饿了"，而那不是同一只生物）。

### 5.1 身体：五角星软体 + 卷毛 + 尾巴

> **⚠️ 2026-10-20 由「半透明凝胶团子」改。** 参考物是用户那张粉色卷毛五角星抱枕的照片。轮廓从"一圈 24 点围成的圆"变成"一圈 24 点围成的**五角星**"（5 个外角 + 5 个内凹，点沿星形轮廓按弧长分布），弹簧动力学、Catmull-Rom 平滑、形变来源**全部原样复用** —— 变的只是"静止时的目标半径"这个数组。这是本次造型改动里最便宜的部分。

```
形变来源 = 运动挤压（沿速度轴 squash & stretch）
         + 情绪（怒→压扁且前端变尖 / 惧→整体收缩 / 喜→膨胀）
         + 碰撞局部凹陷（撞墙或被撞的那一侧凹进去）
         + 抚摸局部凹陷（温柔接触时，离手最近的那一侧凹进去）
         + 蹦跳落地（§4.7.2 的一次性冲量 → 竖向压扁 + 过冲回弹）
         + wobble 基因决定的弹簧刚度与阻尼
绘制     = Catmull-Rom 平滑闭合曲线 → 贝塞尔路径
```

**抚摸与碰撞共用 `body.dip`，不新增渲染通道**（2026-10-25 补）。算不算抚摸仍只有内核的
`c.beingPetted` 一个门槛：温柔、接触、且没有被拎住；身体层不复制这些判定，只把
`world.playerHand` 的世界方向投影到 facing 对齐的局部空间，决定往哪里凹。逐点凹陷量按
朝向点积的平方分配，上限 `petDentMax = 0.16`，浅于碰撞的 `dentMax = 0.34`；每个点在各来源
与已有凹陷之间取最大值，不累加，也不让浅抚摸抹掉同侧更深的碰撞，之后统一按
`exp(-dentDecay × dt)` 回弹。拎起让路规则不变；局部毛倒伏不在这项里。

**星形的五个角是有用途的，不只是轮廓好看**：它们给了身体五个天然的"挂点"。尾巴挂在后侧那个凹角，眼睛长在 `facing` 那一侧的两个角之间，被摸时离手最近的那个角会单独凹陷，`flee` 时朝向角会指向逃跑方向。**一个没有挂点的圆，表达不出"它把屁股对着你"。**

**分层绘制**（由内到外，2026-10-20 重排）：

1. 光晕（`lighter` 叠加）—— 保留，但**半径收小、alpha 降低**：毛会散射光，所以发光现在是"整只柔和地亮起来"，不再是"暗水里一圈清晰的光边"
2. 身体本体 —— **不透明**填充（毛绒不透明，这是与凝胶最直接的区别），径向渐变改为"受光侧提亮 / 背光侧压暗"的同色相渐变，**不跨色相**
3. 花纹 —— 保留四型，但 alpha 压到 0.35 左右：**花纹是绣在毛里的，不是印在塑料上的**。完全清晰的图案 + 毛茸茸的轮廓会打架
4. 体内光 —— 原来的"发光核"一颗清晰亮椭圆，现在改成**透过毛看到的一片柔和亮区**，位置仍在体心，脉动节奏不变（`glow` 基线 × 情绪系数，§4.1 那条下限 0.35 的推理仍然成立）
5. 尾巴（3 段链，§4.7.1）
6. 眼睛 → 腮红
7. **毛尖碎边**（最上层，2 张预渲染 sprite 之一，随身体 squash 矩阵一起变换，§4.7）
7b. **抚摸时的局部毛倒伏**（2026-10-26 加，只在 `beingPetted` 时存在）：近手侧一条压毛暗带 + 短伏毛；
   全部走路径，不新增 sprite，也不改第 7 层原来那一张 `drawImage`
8. 语言气泡（§4.13.1）

**玩家的手是场景层，不属于上述八层**（2026-10-25 补，同日按控制方反馈改过一次）。
只要 `world.playerHand` 非 null（也就是按住缸内任意位置）就画一只肉色手：
指尖精确落在指针上，掌心在接触点**上方**，像从屏幕外落到头顶；靠边时两个轴各自镜像。
**布局尺度**按视口短边在 40–56 CSS px 之间自适应（比第一版小一号），手指与掌缘会向外
展开，所以实际包围盒略大于这个数。手用肉色填充与深肤色描边，不再借用星绒绒的樱花粉。
抚摸成立时——直接读既有 `c.beingPetted`，不复制速度或接触判定——手腕绕指尖摆动
（0.28 rad，相位从本次接触起算，避免第一帧跳变），两圈接触光按独立脉冲向外展开并淡出；
指尖始终压在接触点上，手看起来像在头顶一下一下地摸。松手即消失。
它画在生物与溶散粒子之上、语言气泡之下：手是伸进缸里的实体，但不该盖住"它说了什么"。
整层走路径，不使用图片、渐变、`shadowBlur` 或每帧新对象。

> **被这次改动牺牲掉的东西，写清楚**：原 §5.1 那句"高光和内阴影是让半透明凝胶看起来有体积感的关键，不是可选装饰"仍然对，但**对的对象变了** —— 毛绒的体积感不靠一条高光弧线，靠**毛尖碎边在受光侧更亮**。所以左上缘那条高光从"必须"降级为"轻微存在"，而碎边的亮度对比升级为主要手段。参考照片本身也印证这点：那只抱枕的高光是整圈毛尖的泛白，不是一条弧形反光。

### 5.3 性能预算

| 平台 | 种群上限 | 目标帧率 |
|---|---|---|
| 桌面 | 24 | 60fps |
| 手机 | 16 | 60fps |

硬约束：**不每帧 `shadowBlur`、不每帧新建渐变、运行时不分配对象**（微粒与事件用对象池）。

**2026-10-20 新增三条通道的预算归属**，它们都是"看起来是装饰、实际上是每帧成本"的东西：

| 通道 | 每帧成本 | 为什么在预算内 |
|---|---|---|
| 毛尖碎边 | 每只 **1 次** `drawImage` + 一次矩阵变换 | 靠 §4.7 那条"只画浅色碎边、不给每根毛上色"的决定，把 24 只 × 120 段贝塞尔（2880 段/帧，必崩）压成 24 次贴图 |
| 局部毛倒伏（2026-10-26 加） | 每只抚摸态 **2 次** `stroke`（压毛带 + 伏毛），最多每个轮廓点一条二次贝塞尔；零 `drawImage`、零渐变 | 只在 `beingPetted` 时存在，不重算整圈毛；压毛带只画相邻轮廓点的小段，伏毛 ≤ bodyPoints 条，24 只满摸时仍远低于每帧预算 |
| 尾巴 | 每只 3 段 Verlet + 3 次 `drawImage` | 链长固定 3，不随体型增长 |
| 语言气泡 | 同屏 **最多 2 个**，其余排队 | 文字排版（`measureText` + 圆角矩形）是 Canvas 2D 里相对贵的一步，24 个气泡同屏会直接吃掉整帧预算 —— 上限 2 既是性能决定**也是**审美决定（弹幕是这个项目最该避免的东西） |
| 叫声（2026-10-22 B18 加） | 每帧 **只读** 24 只 × 6 个标量比较（零分配：读数存在自己的 entry 上，嗓音只在真要发声时才算）；同时发声 **最多 6 个**，溢出计数丢弃 | 叫声是**稀疏事件**而不是每帧通道：判据是阈值跨越，一秒钟真正排程的通常只有 0–2 声。把 `voiceFor`（要 new 一个对象）搬进帧循环就会变成每秒 1440 次分配 —— 那正是这一条要躲开的形状 |

**降级顺序**（实测帧时间不达标时按此顺序砍，写进计划，不许临场发挥）：① 手机端种群上限 16 → 12；② 小体型个体的碎边 sprite 降一档密度；③ 关闭光束摆动。**先砍装饰，最后才砍尾巴和碎边** —— 那两条是用户点名要的，砍了就不是那个物种了。

### 5.4 声音：Web Audio 程序化合成，零音频文件

不加载任何 `.mp3` —— 全部用振荡器实时合成，所以**依然是零依赖**。

| 事件 | 声音 |
|---|---|
| 开心 | "咐咐" 两声短促上滑正弦，600→900Hz |
| 卖萌 | "啵" 快速下滑 400→200Hz + 一点气泡噪声 |
| 生气 | 低沉"咕噜" 90–140Hz，带轻微抖动 |
| 困倦 | 长缓慢下滑音，柔和起音 |
| 同步脉动（社交高峰，原「求偶成功」） | 柔和的两音小铃 —— **计划 2 不出声**：那一行随 §4.12 改孤雌时失去了对应的那一刻（A2c 删掉了 `mated` 事件），见 §5.4.1 第 2 条 |
| 孵化 | 细碎裂声 + 一个上扬小音 |
| 死亡 | 极轻的下滑音，几乎听不见 |

**关键设计：音高随体型变（小只高、大只低），音色随色相基因变** —— 所以**每条家族血脉有自己的嗓音**。你不看屏幕都能听出是哪一家的孩子在叫。这是零依赖方案独有的优势：音频文件做不到参数化。

> **⚠️ 2026-10-20 修订**：原文这句是"这仍然是『不能说话』—— 这些是非语言的生理性发声，不含任何词汇或语义"。前半句在 §4.13 之后不再成立，但**这条区分反而更重要了**，所以保留并升级成一条纪律：
> **叫声与文字是两条独立通道，各说各的。** 叫是生理性的、不含词汇、永远发生；文字是选择性的、按 `talk` 稀疏发生。**不许把两者同步**（说"开心"的同时放开心音效）—— 那会把两条通道退化成一条。§4.7.1 讲的冗余是**身体通道之间**的冗余，不包括文字。
> 唯一允许的耦合：出词前加一记极短的"啾"作前导，音高仍随体型变。作用是告诉玩家"这声音是它自己发的，不是环境音"，不是给台词配音。

手机浏览器要求用户先交互才能启动 AudioContext → 首次 pointer 事件时 `resume()`。默认开启、音量很小、右上角有静音按钮；若被阻止则静默降级并隐藏按钮。

#### 5.4.1 叫声层落地裁定（2026-10-22，Task B18）

上面那张表只有七行字，实现时每一行都撞到一个原设计没说的决定。八条，写给下一轮（体例同 §4.13.1.1 / §4.13.1.2）：

1. **内核不发情绪事件，所以"该不该叫"是表现层的只读阈值跨越**。
   实测 `world.events` 的种类只有十一种：`eat / laid / say / poke / death / dissolved / drift / emigrate / eggFailed / hatch / error`
   —— 一条心情都没有。表里"开心/卖萌/生气/困倦"那四行**没有对应事件**。两个选项：给内核加四类情绪事件，
   或在表现层读现量判跨越。选后者，理由是加事件 kinds 等于让内核重新发明一遍 `moodOf`
   （§4.5.1 明文"谁都不许把心情当状态写回去，那是刚被否决过的互斥状态机"），
   而且事件是**一次性队列**、跨越是**每帧巡检**，前者根本装不下"上升沿"这个语义。
   落点：`src/audio.js` 的 `DETECTORS` 六条 —— `emotions.joy` 上跨 `MOOD_HAPPY_JOY_MIN`、
   `emotions.anger` 上跨 `MOOD_ANGER_MIN`、`emotions.sleepy` 上跨 `AUDIO_SLEEPY_MIN`、
   `needs.energy` 上跨 `AUDIO_TIRED_MIN`（疲劳与困倦共用那一声明与那条冷却）、
   `affectionFor(memory, PLAYER)` 上跨 `AUDIO_AFFECTION_MIN`、`begLevelOf(c)` 上跨第一档。
   **两个阈值不在叫声层重抄**：joy 与 anger 直接读 §4.5.1 那两个数（唯一定义点，先例是 body.js 读 `begEscalate`）。
2. **七行里只有五行落地，其余一律不出声**。逐行映射：
   开心 / 困倦 / 孵化 / 死亡 = 上表的探测器与 `hatch` / `death` 事件；卖萌 = 好感跨越或求关注升档。
   不出声的那几条，每条都有理由，不是忘了：
   · **同步脉动（社交高峰，原「求偶成功」）**：这一行是 2026-10-20 孤雌制改写时留下的空壳 ——
     那一次改动（任务 A2c）删掉了 `mated` 事件与整个求偶结算，现在内核里**没有任何一刻**能挂它。
     为它发明一个"社交高峰"判据得改内核（要给两只的同步度建一个读数），超出了一个表现层 Task 的权限。
     记为**未实现**，等计划 3 若真要做社交同步的表现时一并定。
   · **poke**：戳会把 `anger` 推过 `MOOD_ANGER_MIN`，生气那一声明天然把它接走了；
     再配一记"被戳音效"就是给同一个动作发两个信号。
   · **eat / laid / eggFailed / dissolved / drift / emigrate**：表里没有它们，
     凭空造音色只会稀释那六声的语义（尤其"死亡"那一声必须是稀缺的）。这些事件在**画面**上都有对应表现（B16），不需要声音重复一遍。
3. **音频图靠注入，`src/audio.js` 一个浏览器全局都不出现**。
   §3.2 的机器化守卫（`tests/constraints.test.js`）规定七个浏览器标识符只许出现在 `src/main.js`。
   所以 `createAudio({ graph })` 收的是 duck-typed 的一条图：`{ currentTime, destination, createOscillator(), createGain() }`
   ＋ 可选的 `createBiquadFilter() / createBufferSource() / createBuffer() / sampleRate`，
   而 `new AudioContext()` 只在 main.js。回报是嗓音映射、六声表、跨越判据、冷却、发声上限、节点收支
   **全部在 Node 里可断言** —— 与 body / render / input / eyes / bubble 五个模块同一条决定。
   代价也如实记着：这一层的测试必须用**记数值**的桩（记频率、包络两端、波形、增益、start/stop 时刻、
   connect/disconnect 计数）。canvas 那三套桩刻意只数次数，这里照搬就会让"把 900 写成 600"这种错
   完全测不到 —— 节点数一个都不变。理由写在 `tests/audio.test.js` 的文件头。
4. **上下文在首次 pointerdown 上懒创建**（§5.4 末段的展开）。
   开缸就 `new` 的话，手机浏览器给一个永远 suspended 的上下文（iOS Safari 连构造都可能拒绝），
   症状是"桌面有声、手机上就是没声"且不报错。
   实现上有一条**不显然**的细节：创建点挂在 main.js 自己那条 `addEventListener('pointerdown', …)` 上，
   **不是**复用 input.js 的 `onHand` 回调 —— 后者由 `step()` 里的 `input.poll()` 触发，那是 rAF 的调用栈而不是手势的调用栈，
   而 `resume()` 只在手势调用栈内才被移动端认可。这条监听不读任何指针坐标，且在第一次按下就把自己摘掉，
   所以与 B17 的"每帧一次读数"纪律不打架。
   **降级为什么不静默**：`§7.7` 那张表把 AudioContext 被阻止写成了"静默降级"，本 Task 按**意图**加强了一档 ——
   `controller.audioState = { tried, ok, reason }` 是可读的事实（`__tank.audioState`），且 `console.warn` 恰好一次
   （每帧刷是把"不静默"做成"骚扰"）。一次失败之后不再重试：连按 24 下不许 new 出 24 个上下文；
   重试留给计划 3 那颗按钮显式触发。
5. **两条增量：hop 落地那记闷响、出词前那记「啾」**。它们**不在** §5.4 表里，是计划 2 有意加的，
   各自补的是表留的一个空洞：
   · **闷响**：§9.2 第 8 条要求"不看屏幕只听声音，能分辨哪只最活泼"，靠的就是"落地闷响的**密度**" ——
     而原表七行里没有任何一行是落地的声音。判据用**跨越**而不是相等：4× 一帧推进四个子步，
     进度可以从 0.68 直接跳到 0.78，**跨过** `RENDER_HOP_LAND_AT`（0.72）而不落在点上，按相等判就永远不响。
     时长口径读内核的 `intent.minDuration`（与 `hopProgress` 同一份读数），不在叫声层另抄一条公式。
     它带**两道**闸门：每只一次（`AUDIO_THUD_PER_SEC`）+ **全局**一次（`AUDIO_THUD_GAP_SEC`）——
     没有后面那道，24 只好动个体在 4× 下会把闷响打成一梭子，密度信息反而淹没在噪音里。
   · **「啾」**：§5.4 那条 2026-10-20 修订明文允许的唯一耦合（"出词前加一记极短的'啾'作前导"）。
     它的职责是"这声音是它自己发的，不是环境音"，所以**只许**由体型定音高、由色相定音色。
     **它自带一道全局闸门（`AUDIO_CHIRP_GAP_SEC = 0.3` 真实秒），这条是量出来的、不是想到的**：
     60 分钟一缸（seed 20261022、cap 24）实测出词 2755 句，**最坏的单秒有 5 句**、最坏三秒滑窗 8 句，
     而单音长只有 0.045 秒 ⇒ 倍速 4× 下换算是 **20 记/真实秒**，那是一串嗡嗡而不是"前导音"。
     事件通道**不过**每只的冷却（那 4 秒冷却是给跨越那六声用的），所以这一条必须全局拦。
     0.3 这个数刻意选在 **1× 下不 binding**（三秒窗最多放行 10 记 > 实测 8 记）：
     正常话痨的手感一个字都不动，只掐倍速捅出来的那一梭子，上限 ≈ 3.3 记/真实秒。
     **`hatch` / `death` 不进这道闸门** —— 把它们关进去的症状是"卵孵出来了却一声不响"，
     而死亡那一声的稀缺性正是要紧的东西，不该被一缸装饰声挤掉。溢出**计数**（`chirpDropped`），不静默。
6. **两通道反同步的测试形状：把「啾」的读数钉成与 `mood` 无关**。
   判据刻意写成"同一条 say 换掉 mood（happy / anger / sad / bliss / calm / undefined / null 七种），
   桩记下的**全部**读数（节点序列 + 每个参数的每次写入 + connect/disconnect）必须**逐字节相同**"，
   而不是"某几个数不许变"：配音进来时改的可能是频率、可能是增益、也可能是时长，
   整份读数参与比对才拦得住"只把音量调大一点"这种最小的作弊实现。
   配套的第二条是"任何 say 都**不许**触发六声表里的那六声"（`stats.calls.joy === 0` 那种计数断言）——
   两条一起才把"不许同步"钉死：前一条防给台词配音，后一条防把台词变成叫声的触发器。
   §5 开头那条老纪律（表现层不许改世界）在这里同样成立：跑完一整套叫声之后 `JSON.stringify(world)` 逐字节不变，
   个体身上也不许长出 `voice / lastCall / calls` 这类字段。
7. **发声上限与状态上界是同一类债，一起还**。
   同时活跃的发声槽 `AUDIO_MAX_VOICES = 6`，溢出**计数丢弃**（`stats.dropped`）——
   §7.7 禁止静默丢，而"听不见"没有任何可观察症状，只能靠计数器。
   每只个体的读数与冷却存在 `src/audio.js` 自己那张 Map 上，按**世界成员身份**回收
   （镜像 `reconcileBodies`，不用 `seen` 标记：0.5× 下有空帧，标记法会把全部状态误删，
   而这里的症状是"于是这只永远第一次被看见 ⇒ 一开嗓就永远不响"，静默且不报错）。
   60 分钟的缸要过约 80 个个体，不回收就是第二个 `world.events`。
   这里还有一条**快捷条件式的 bug** 被测试钉住：不能用 `entries.size > creatures.length 才扫`——
   同一帧里一只死掉、一只孵化是常态（size 恰好相等），那样写会留下永不回收的僵尸条目。
   冷却用 **graph 真实秒**而不是 `world.time` 模拟秒：倍速 4× 下跨越次数就是 4 倍，
   按模拟秒算冷却会让每秒的叫声数跟着倍速线性上升，而玩家的耳朵听的是真实秒。
8. **静音按钮属计划 3**（HUD）。计划 2 刻意没有任何 HUD，所以本 Task **不往 index.html 加按钮**，
   静音只经 `globalThis.__tank.setMuted(true)` 与模块级 `setMuted/getMuted` 暴露 —— 与时速（`setTimeScale`）同一条路。
   `§5.4` 那句"右上角有静音按钮；若被阻止则隐藏按钮"因此是计划 3 的验收项；计划 2 侧的等价物是
   `audioState.ok` 那个可读标志（按钮将来就据它决定显示与否）。

**已知债务（不是 bug，如实记着）**：① 六声表里只有"开心"那行是 spec 逐字给了两个 Hz 数与"两声"的计数，
其余五行的"短促/柔和/细碎/极轻"都只有方向 —— 数在 §11，**听感对不对只能靠耳朵**，自动化只断言相对排序；
② 单次戳把 anger 推 +0.25，**未必**跨过 `MOOD_ANGER_MIN`(0.5)，所以"戳被生气那一声接住"只在它已经有怒意时成立
（这一条没有真人数据，与 B17 记的 `HAND_SPEED_POKE` 无实测同源）；
③ 落地闷响对大只个体按 `pitchMix 0.5` 打折之后仍可能低到手机扬声器发不出的区间，需实机核对。

## 6. 玩家交互

### 6.1 手势

全部用 **Pointer Events** 统一触控与鼠标，**不依赖 hover**（手机没有 hover）。

| 操作 | 效果 |
|---|---|
| 从底部食物条**拖拽**食物入缸 | 投食（精确放置）。**2026-10-25 做掉了**，四条边界：① 与点按**共存** —— 原地按下抬起之后真浏览器还会补一个 `click`，那一发照旧落缸中央；② 一次**一颗**，走的还是 `feedAt` 那道 `foodMax` 闸门 ⇒ 拖拽不是第二条供给通道；③ 松手在缸外（手指底下不是绘制元素）**算撤回**，且撤回计数读得到（`hud.state.carryCancelled`，与 `grabState.suppressed` 同一条纪律）；④ **HUD 只上报像素**，"在不在缸内"由 `main.js` 用 `elementFromPoint` 判 —— 视口与绘制元素只有它知道，那条边界由一条源码判据钉住。附带一个对的行为：信息卡开着时压在卡上松手 ⇒ 不投（不然会隔着一张卡丢食物） |
| **长按**缸内一点 | 在该处撒食 |
| **按住**缸内任意位置（2026-10-25 新增，同日改版） | 出现一只半透明肉色手：指尖压在指针上、掌心从上方落到头顶，靠边自动镜像；松手即消失。抚摸成立时手腕明显摆动、指尖的接触圈向外脉动。它只是表现层，不改变任何手势判定 |
| 在生物身上**缓慢划动** | 抚摸 → `affection` +、`joy` +，它会蹭你的手 |
| **快速戳** | `safety` −、`fear`/`anger` +，它会躲开或抗议 |
| 按住一只**把它带离身体**（2026-10-24 新增） | **拎起来**：它跟着手走、松手甩出去（不受伤）；反应方向由**性格 × 好感**决定，见 §8.2 第 12 条与 `2026-10-24-grab-and-carry-design.md` |
| 拎着饿的那只**拖到食物上**（2026-10-25 新增） | **手喂**：它当场吃掉那份食物，与它自己吃走**同一套结算**（需求 / `fed` / 冰晶安抚 / `eat` 事件），额外记一格好感（`CONFIG.grab.feedAffection` 0.03 ≈ 摸半秒）。闸门沿用觅食那两个数（`EAT_DIST` 与 `EAT_HUNGER`）⇒ **吃饱的拖过去不咬**，手喂不是第二条供给通道 |
| **点按单只** | 打开信息卡 |
| **长按单只** | 给它取名 |
| 信息卡里的**输入框**打字 | **讲给它听** → 进那只个体的 `heard`（§4.8.1）。需要软键盘与焦点管理，**属计划 3 的 UI，计划 2 不做** |

**抚摸与戳是同一根手指、不同速度，反应完全相反。** 这个区分是整个交互的核心：它逼你**温柔地**对待它，而它会用身体告诉你你做对了还是做错了。这本身就是"通过行动表达想法"的双向版本。

判定方式：追踪最近若干 pointer 采样的速度；速度超过阈值且位移方向反复（戳）判为戳，速度低且沿生物身体轮廓移动（划）判为抚摸。

**"拎"加进来之后这张表必须有的那条优先级**（2026-10-24，`2026-10-24-grab-and-carry-design.md` §6）：
拖拽天生就满足"按下 + 快 + 贴上身体"，也就是**每一条戳的判据它都满足** —— 不显式处理的话
"拎起一只走"= 一路上升沿发 `poked`，玩家得到的不是"我拎起了它"而是"我一动它就被连扎"。
所以：**被拎住的那只不进入抚摸与戳的判定**，而这条让路**必须逐只判** ——
拎着 A 快速划过 B，B 仍然算被戳。让路点只写在 `isHeld` 一处（谓词开头），
散到各调用方的 `if (grab) skip` 早晚会被下一个消费者漏掉。
"摸"与"拎"的分界用**位移**而不是时间：手越过 `pullOutRatio × 身体半径` 才算带离，
手始终在它身体表面范围内滑动就还是抚摸 —— 引入一个 `grabMinMs` 那种没人能凭手感验证的常数，
不如让物理本身来分。

### 6.2 三种食物

食物刻意**避开粉色系**（青绿 / 琥珀 / 淡蓝），这样它们在粉紫色的世界里一眼可辨，不会被误认为生物。

| 食物 | 外观 | 作用 | 设计意图 |
|---|---|---|---|
| **光藻** | 青绿微粒 | 基础食物，恢复少，会缓慢自然再生 | 保底生存，不构成戏剧 |
| **蜜珠** | 琥珀金珠 | 高能量，恢复多，**所有生物都爱吃** | **争抢的主要来源，恩怨由此产生** |
| **冰晶** | 淡蓝结晶 | 安抚作用，降低 `anger`/`fear` | 玩家的"灭火器"，可在两只打架时丢一颗 |

### 6.3 UI

**名字**：自动生成粉色系叠词名（泡泡、团团、蜜桃、软软、樱樱、糯糯、朵朵…）+ 序号区分（`小桃·三`），可长按改名。**它学会并主动说的第一个词，很可能就是自己的名字** —— 这是 §4.8.1 那条"听进去的话"最自然的示范用例：你叫它，它回头；过几代它自己会喊。

雷达图**九个轴名要写在圈外**（大胆 / 黏人 / 暴躁 / 贪吃 / 好奇 / 好动 / 话多 / 聪明 / 恋巢，`PERSONALITY_AXES`）。2026-10-25 之前 DOM 层只取了值、把 `radarFor` 早就带着的中文名丢了，于是那是一坨读不出"哪一维高"的折线 —— 而名字是**类别名不是数值**，既不碰下一句"好感度不写数字"（那句的宾语是好感度），也不碰本节末尾那条"不许替它陈述心情"（九轴是性格基因，与 `moodOf` 那五档无关）。

## 7. 存档、多设备与错误处理

### 7.1 服务器

`server.ps1` 用 .NET `HttpListener`（Windows PowerShell 5.1 自带，无需安装）：

- 静态文件服务，绑定 `0.0.0.0` 以便手机通过局域网访问
- `GET /api/save` → 读取 `save.json`
- `PUT /api/save` → 写入。**原子写入**：先写 `save.json.tmp` 再 `Move-Item -Force` 覆盖，避免写一半时断电留下损坏文件
- `start.bat` 启动时打印本机局域网 IP（如 `http://192.168.1.5:8420`）供手机访问，并自动打开本机浏览器

### 7.2 存档格式

```jsonc
{
  "version": 2,
  "revision": 42,
  "savedAt": "2026-10-20T10:00:00Z",
  "world": {
    "seed": 12345,
    "timeScale": 1,
    "nextDriftAt": 240,          // 2026-10-20：下一次外来血统漂入的模拟时刻（§4.12）
    "food": [ { "id": "f1", "kind": "algae", "x": 0.42, "y": 0.81 } ]
  },
  "creatures": [
    {
      "id": "c1", "name": "小桃·三", "customName": false,
      "stage": "juvenile", "age": 214.5, "alive": true, "sick": false,
      "genes": { "hue": [0.83, 0.91], "size": [0.4, 0.6], "fluff": [0.55, 0.2],
                 "activity": [0.7, 0.66], "talk": [0.9, 0.8], "intellect": [0.3, 0.44],
                 "broody": [0.5, 0.5] /* …九位点，双等位… */ },
      "catchphrase": "喵喵",       // 出生时抽定后固化，不每帧重抽（§4.13.1）
      "needs":    { "hunger": 0.2, "energy": 0.4, "social": 0.1, "safety": 0.05 },
      "emotions": { "joy": 0.6, "anger": 0, "fear": 0.1, "curiosity": 0.3, "sleepy": 0.2, "arousal": 0 },
      "pos": { "x": 0.40, "y": 0.60 }, "vel": { "x": 0, "y": 0 },
      "memory": [ { "id": "c2", "familiarity": 0.8, "affection": 0.5, "kinship": 0.5, "role": "sibling" } ],
      "heard":    [ { "token": "吃饭", "price": 0.6, "boundMood": "快乐",
                      "heardAt": 180.2, "lastUsed": 210.0, "uses": 3 } ],
      "lineage": { "mother": "c0", "father": null, "fromEgg": "e7", "offspring": [] }
    }
  ],
  "eggs": [ { "id": "e1", "mother": "c1", "genes": {}, "eggSize": 1.18, "eggTint": "macaron-blue",
              "age": 12, "x": 0.3, "y": 0.95 } ],
  "stats": { "births": 12, "deaths": 3, "generation": 4,
             "driftIns": 2, "meanHeterozygosity": 0.31 }   // 后两条是 2026-10-20 新增的多样性指标
}
```

**位置存归一化 `[0,1]²`，体型存世界单位** —— 这样同一份存档在竖屏手机和横屏电脑上都正确（见 3.4 第 2 条）。

**表现层的身体状态（控制点相位、尾巴角度、毛边 sprite 选择、当前气泡）一律不入档。** 它们是每帧重算的确定性函数，存下来只会让存档变大并制造"读档后身体弹一下"的假象。唯一例外是 `catchphrase`，因为它必须终身稳定。

**2026-10-24 补：`beingPetted` / `beingPoked` / `held` 这三个上升沿寄存器属于同一族，也不入档。**
理由与上面那条同源但更硬：它们记的是"**此刻玩家的手在做什么**"，而手是输入层的读数
（`world.playerHand` 本身就在 `WORLD_SKIP_FIELDS` 里）。存下来的后果很具体 ——
读档后那只一进场就被判成"正被拎着"，而没有任何人会去清它，症状是它永久卡在追随一只不存在的手。
所以三个都在 `CREATURE_SKIP_FIELDS` 里，出厂与读档都归 false。

**API key 绝不写进 `save.json`** —— 那是多设备共享的明文文件（§7.1），把 key 写进去等于把它广播到局域网里所有设备上。key 只存本机 `localStorage`，读档时不合并。这是 §4.13.2 那三条纪律之外的第四条，因为它涉及的是泄露而不是降级。

> **v1 → v2 迁移**（§7.7 的"尝试迁移"这条路径的具体内容）：新增的九个基因位点在旧档里不存在，**用 `rng(seed + creature.id)` 派生**而不是取默认值 —— 派生是可复现的，同一份旧档迁移两次得到同一个结果；取默认值会让所有旧个体性格趋同。`heard` 补空数组，`catchphrase` 同样按 id 派生，`father` 原样保留（旧档里它可能非 null，那是历史事实，不删）。`meanHeterozygosity` 在迁移后首次 tick 重算。

### 7.3 写入时机

- ~~每 5 秒 flush 一次~~ → **每 30 个模拟秒**（`CONFIG.save.everySimSec`，2026-10-22 C-1 落地时改）
- `visibilitychange → hidden` / `pagehide` 时**立即** flush（手机上切后台太常见了，不能等到下一个节奏点）
- 两次**写入**之间再叠一道墙钟下限 `CONFIG.save.minIntervalMs = 2000`（只兜事件那两条路，见下面第 3 条）

#### 7.3.1 存档落地的裁定（2026-10-22，Task C-1）

计划 2R 的验收（§9.3）抓到一件很难看的事：**`src/save.js` 没有任何地方 import 它**。
纯函数与迁移有 13 条单测，而页面从头到尾没有一条路能把一缸写出去再读回来 ——
所以 §9.2 第 5 条（存档往返）当时是**结构性做不到**，不是"没来得及验"。下面八条是接线落地时的裁定。

1. **读不懂的档，绝不被覆盖 —— 这是本条任务唯一的承重决定。** 要让它不可能发生的序列是：
   加载失败 → 起一缸新的 → 下一个节奏点自动落盘 → **把用户那份读不懂、但可能救得回的档覆盖掉**。
   落地的顺序是：读主键 → 解析 / `migrate()` / `assertCreatureShape()` / `restoreWorld()` **任何一步失败**
   → 把**原文逐字节**挪进 `tank.save.v2.corrupt` → 才允许起新缸。
   "逐字节"是刻意的：转手 `JSON.parse` 再 `stringify` 就等于二次损坏，那一份就不再是证据了。
   **连隔离区都挪不动时**（写隔离区也抛），唯一安全的动作是**永不再写主键**
   （`blocked = 'quarantine-failed'`），而不是"那至少新缸能存"。
   四种坏法各有一条 boot 级测试钉住这条顺序：坏 JSON、`version` 比实现还新、能解析但缺 `creatures`、
   过了 migrate 但个体缺 `id`。
2. **隔离区只留最早那一份。** 第二次及以后的坏档**计数丢弃**（`saveState.discarded`），不覆盖已有的那份。
   一个会被第二次失败冲掉的隔离区就不是隔离区了，而"最早那份"恰恰是玩家真正失去的那一缸。
3. **两个时钟各管一件事。** 节奏用**模拟秒**（存档密度跟着世界的内容走，不跟倍速走）；
   事件路径用**墙钟下限**（连点标签页会在几秒里发十几次 `visibilitychange`，没有下限就是十几次同步写）。
   显式 `controller.saveNow()` **不受下限管** —— 那是人在 devtools 里按的，"按了没落盘"会让人以为存档坏了，
   代价由按的人负责。
4. **没有定时器。** 全层零 `setTimeout` / `setInterval`：落盘挂在既有的帧循环上，
   于是 `stop()` 没有定时器要摘、后台标签页回来不会攒下一堆到期的回调。（与 §5.4.1 第 8 条、
   §4.13.2.1 第 8 条同一条决定 —— 这个项目第三次做这个选择，已经成惯例了。）
5. **恢复是"状态的延续"，不是"随机流的延续"。** 存档**不序列化内核的 RNG 状态**，
   所以"存 → 读 → 再跑 N 拍"**不等于**"连续跑"。这一条刻意**不写成测试**（写成就是一条假测试），
   而是写在这里：真正保证的是个体身份（名字 / 19 个位点 / 口癖 / 世代 / 位置）、
   记忆与 `heard`、`world.time` 与 `nextDriftAt` 与统计量原样回来，且恢复出来的缸过得了
   `assertCreatureShape`。计划 3 若要"两台设备接着同一缸继续长"，得先决定要不要序列化 RNG ——
   那会让 seed 复现性变成一件需要设计的事。
6. **key 只住本机，存档里一个字节都不许有它。** `tank.api.v1`（API 档）与 `tank.save.v2`（世界）是两个键；
   有一条测试把 API key 填进去、落盘、再在存档原文里搜那个子串，搜不到才算过。
   §7.2 末那条第 4 纪律到这里才第一次真的被机器守住 —— 之前没有落盘路径，它只是句正确的话。
7. **降级不静默，但也不吵。** 配额爆了 → `quotaHits` 计数 + 缸照常跑 + warn **恰好一次**；
   存储整个不可用（Safari 隐私模式：光是**读那个属性**就抛）→ 这一层退场、`enabled = false`、warn 恰好一次。
   每帧刷一条 warn 是把"不静默"做成骚扰（§7.7 的反面）。
   ⚠️ 存档层与 API 层共用同一个 storage，所以两层**各响一次**是正确的 —— 测试按消息文本区分，
   数在一起就是一条假红。
8. **`boot({ save: false })` 连属性访问都不许有。** 不只是"不读不写"，而是连 `globalThis.localStorage`
   都不摸一下 —— 在隐私模式下那一次访问本身就抛。测试用一个会数读写的存储桩钉它。

**成本实测（两组都留着）**：浏览器里量到 中位 1.86ms / 最坏 4.22ms、约 160KB；
控制方复核时在 Node 里重量（seed 20261022、23 只）：刚开缸 13.4KB / 0.38ms，
跑满 60 模拟分钟 66.4KB / 0.82ms ⇒ 按 4× 下每 7.5 真实秒一次算，占帧预算 **0.011%**。
两组差一个量级，而**结论不依赖是哪一组**：30 模拟秒这个档不用改。

**§7.5 / §7.6 的边界，如实说明**：那两节写的 `revision` 计数、`PUT` 带版本号、服务器比对后返 409、
"绝不静默丢失任何一边的进度" —— 是一套**服务器**方案，计划 2 用的是 `localStorage`，
**没有 revision、没有并发仲裁**。多设备同时打开同一个缸在计划 2 里的现状是"各存各的本地档"，
§7.5 仍是待实现目标而不是已实现事实。

### 7.4 离线暂停

存档记 `savedAt`，但**恢复时不补算流逝时间**。世界从暂停那一刻继续 —— 你三天后回来，它们还在你离开的那一秒等着你，一只都没少。

### 7.5 多设备同时打开同一个缸

共享存档的真实风险。策略：存档带 `revision` 计数。

- 客户端持有自己加载时的 `revision`
- `PUT` 时带上该值；服务器比对磁盘上的 `revision`
- 若磁盘的更新 → 返回 **409**，**不覆盖**
- 客户端弹出提示"另一台设备刚刚改动了这个世界"，让用户选择**加载它的版本**或**接管**（强制覆盖）
- **`revision` 只由服务器递增**：每次成功写入后，服务器把磁盘上的 `revision` +1 并写回。客户端从不自行计算 `revision`，只负责携带自己加载时读到的那个值。这个单一所有权避免了两边各算一套导致的编号错乱

**绝不静默丢失任何一边的进度。**

### 7.6 服务器不可达时自动降级

若 `/api/save` 请求失败（例如项目被丢到 GitHub Pages 上当纯静态站打开），自动改用 `localStorage`，并在 HUD 显示一个小图标提示"本地存档"。

**同一份代码同时支持共享存档和独立部署** —— 这是很划算的鲁棒性收益，也顺手解决了"手机上不依赖电脑开机也能玩"的场景。

### 7.7 错误处理原则

**绝不静默丢失用户数据，绝不让整个世界崩溃。**

| 情况 | 处理 |
|---|---|
| 存档 JSON 解析失败 | 坏文件重命名为 `save.corrupt-<时间戳>.json` **保留证据**，开一个新缸，HUD 提示一次 |
| 存档 `version` 不兼容 | 尝试迁移；无法迁移则同样备份后重置 |
| **单只生物 tick 抛异常** | `try/catch` **隔离这一只**（标记 `sick: true`、停止行为、记录日志），其余照常。**任何一只的边界 bug 都不该导致白屏** |
| canvas 不可用 | 友好提示 |
| AudioContext 被阻止 | 静默降级，首次交互时重试；仍失败则隐藏声音按钮（**2026-10-22 B18 收紧**：降级不是"什么都不说"，而是 `controller.audioState = {tried, ok, reason}` 可读 + `console.warn` 恰好一次；失败之后**不再**每次按下都重试，重试留给计划 3 那颗按钮显式触发。见 §5.4.1 第 4 条） |
| 标签页长时间后台 | rAF 自然暂停，恢复时 dt 封顶 0.25s |
| 端口被占用 | `start.bat` 打印明确错误并尝试下一个端口 |

**F-3 已经量完了（C-4，2026-10-22），结论是"判据要改写，代码不用改"**：同一缸跑 120 分钟，
`activity` ↔ 蹦跳总次数的 Spearman 整程 **0.254**（B20 在 60 分钟窗量到 0.219），
但**两端是完全单调的**：activity 最低的三只 `0.17→77 次`、`0.39→530`、`0.64→2769`，
最高的三只 `0.98→4756`、`0.98→5916`、`0.99→8232` —— 首尾差 **100 倍**。
所以低 ρ 不是"关系不存在"，而是两件事叠在一起：
① **测量窗太短**——10 分钟窗口只有 2 个能算（多数个体在那一窗里一跳都没有，并列把秩相关的分母打成 0），
可算的两窗均值只有 0.140；② **幸存者偏差**——`总次数` 是按"活着的时长"累积的，
新活下来的个体天然次数少，这会把中段的秩打乱而与活泼度无关。
⇒ 本条的裁定：**§9.2 第 8 条的"分辨哪只最活泼"是指分辨两端，不是给全缸排序**，
按总次数排全缸是一个**问错了的问题**；正确的读数是**单位寿命内的蹦跳率**。
代码一行没改（`activity` 驱动蹦跳的链路本身是对的），改的是这条验收的口径。
量它的脚本是一次性的（`.superpowers/sdd/tmp/c4-hop-density.mjs`），**没有**进测试套件 ——
它依赖具体 seed 下的种群结构，做成断言就是一条会随任何内核改动而假红的测试。

**方法学上的一次突破，记下来免得下一轮重新踩**：`visibilityState = hidden` 挡不住取证 ——
把 `requestAnimationFrame` 换成"只记录回调"的桩、`boot()` 到一张离屏 canvas、
**手写** `viewport.width/height/dpr` 与 `canvas.width/height`（hidden 页面零布局尺寸，
`boot()` 自己的 `resize()` 会把 `canvas.width` 设成 0），再手动喂递增的时间戳就能泵出真帧。
⚠️ 但 `canvas.toDataURL()` **只导出 canvas、不导出水**（§3.4-5 决定水体走 CSS `body` 背景），
裸导出的 PNG 里水体那一片是白的 —— 任何拿裸导出做的对比度判断都可疑，
必须先按 CSS 那三段色合成一张等尺寸底图再叠。清单第 0.2 节写着这条。

## 10. 范围外（YAGNI）

明确**不做**的东西，避免范围蔓延：

- 多缸 / 多世界切换
- 账号系统与云同步（共享存档走局域网即可）
- 天气与季节系统
- 疾病、寄生虫、变异怪物
- 玩家之间的多人互动
- 捏合缩放等复杂手势
- 音频素材文件（全部程序化合成）
- 生物进化出新器官或上岸
- 拍照 / 分享 / 导出视频
- 构建工具、打包器、TypeScript
- 任何 npm 依赖
- **内置语言模型、训练、任何要打包进仓库的模型权重**（§4.13.2 那个可选端点是唯一例外，而且它不落在仓库里，只落在用户本机设置里）
- **让模型改世界状态**（§4.13.2 纪律 2）。它是只读的旁路，越界一次整个世界的可信度就没了
- **语音合成 TTS** —— 它"说话"是气泡里的词加一记"啾"，不是把字念出来。念出来要素材或系统语音，两条都破坏零依赖
- **语义理解**：问答、指代消解、时态、把两个词组合出新意思。规则档明确做不到，**不要在 UI 上假装能**（这是 §4.8.1 那条能力边界的 UI 版本）
- **玩家输入文字的上传、审核或跨设备展示**：`heard` 里的 token 只进本机那份存档、只在这口缸里复现。没有上传就没有审核负担 —— 这条是主动的范围收缩，不是遗漏

### 13.2 裁定记录（2026-10-20 控制方逐条裁定：五条采纳推荐值，第 6 条否决）

1. **身体锁粉色家族，蛋放开到马卡龙全谱。** 用户那句"它们之间可以有不同颜色"落在蛋上兑现，身体不放开 —— 照片那只就是粉的，而"这个物种就是粉色的"（§4.2）是物种认同的根基。后果：`HUE_RANGE` 不动，**`tests/simulate.mjs` 那条"色相全程锁在粉色区间"的断言保持原样**，这条断言不会在本次修订里被削弱。
