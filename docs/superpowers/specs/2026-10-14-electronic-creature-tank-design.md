# 电子生物生态缸 · 设计文档

- **日期**：2026-10-14
- **状态**：已与用户逐节确认，待编写实现计划
- **技术路线**：零依赖 vanilla JS + Canvas 2D + ES Modules，PowerShell `HttpListener` 提供静态服务与共享存档
- **运行环境**：Windows 桌面浏览器 + 手机浏览器（同一 WiFi 打开同一份存档）

---

## 1. 愿景

创造一种**新物种**。它不能说话，没有一句台词、没有一个文字气泡、没有任何符号外挂。它拥有的一切表达手段只有两样：**身体的动作与形变**，以及**体色与发光**。

它是一个**群体**，不是一个宠物。它们在深水里自己觅食、相遇、卖萌、吵架、求偶、产卵、孵化、长大、衰老、死去。你是照料者 —— 你可以投食、可以抚摸、可以看着它们，但你控制不了它们。

它最核心的设计承诺是：**你能在不读任何文字说明的情况下，读懂它们。**

### 核心设计原则

1. **身体是唯一的语言**。不加 ♡ 💢 ？ ！ 这类漫画符号气泡 —— 那是"外挂"，会立刻破坏"真实生物"的感觉。所有情绪必须通过形变、姿态、运动、体色、发光、眼睛来表达。
2. **涌现优先于脚本**。不写好剧本。胆大的先探到缸底发现食物、贪吃的去抢兄弟姐妹的食物被打了一顿于是记住了这笔账 —— 这些必须是系统交互的自然结果，不是我编排的动画。
3. **世界规则始终自洽**。种群上限不靠硬编码屏蔽，而表现为"求偶被拒绝""这枚卵的光慢慢熄灭了"。绝不出现"明明在求偶却什么都没发生"的突兀感。
4. **绝不静默丢失用户数据，绝不让整个世界崩溃。**
5. **零依赖**。不装 npm 包，不构建，不加载音频文件。十年后双击 `start.bat` 还能打开。

### 3.2 模块边界原则

**纯逻辑模块**（`genes` `needs` `emotions` `memory` `personality` `behavior` `rng` `names`）**不得 import `canvas`、不得 import `world`、不得触碰 DOM**。

这条约束的回报是：它们能在 Node 里直接单测，不需要浏览器、不需要 jsdom、不需要任何测试框架依赖。`node --test tests/*.test.js` 就能跑完。

每个模块对外只暴露具名函数，内部状态由调用方持有（生物对象），模块本身无状态。这样模块可独立理解、独立替换。

### 3.3 主循环数据流

```
requestAnimationFrame
 → 累加器切成固定步长 dt（1/60s），乘时间流速
 → world.tick(dt)
     每只生物：
       needs.decay(dt)               需求衰减
       memory.decay(dt)              恩怨随时间淡化
       senses = world.perceive(c)    看到的食物 / 邻居 / 玩家的手
       emotions.update(...)          需求 + 事件 → 情绪向量
       behavior.decide(...)          情绪 × 性格 × 情境 → 行动意图
       c.act(intent, dt)             移动 / 求偶 / 进食 / 卖萌 / 逃避
       body.update(emotion, motion)  形变与体色跟随情绪
       c.age(dt)                     生长推进 / 阶段切换 / 衰老 / 死亡
     world.resolve()                 碰撞、配对、产卵、孵化、争食、哀悼
     world.respawnFood(dt)           光藻缓慢再生
 → render.draw(world)
 → ui.sync(world)
 → 每 5 秒 save.flush()
```

### 3.4 五个关键技术决定

1. **固定步长积分**
   模拟用累加器切成 1/60s 定步长，渲染按真实帧率。手机 120Hz 与电脑 60Hz 下，生物的生长速度、饥饿速度完全一致 —— 否则同一份共享存档在两台设备上会活得快慢不同，这对"手机电脑同一个缸"是致命的。
   累加器**封顶 0.25s**，防止标签页从后台恢复时一次补算几百步（死亡螺旋）。

2. **世界坐标归一化存储**
   位置存 `[0,1]²`，体型存"世界单位"。渲染时世界尺寸 = 视口 CSS 尺寸，缩放系数由视口**短边**推导并 clamp。
   隐喻是**水填满容器**：竖屏手机上缸是高高的，横屏电脑上是宽的，同一份存档在两边都自然铺满，生物不会在手机上小到看不见。
   `resize` 时按新旧尺寸比例映射所有位置。

3. **发光用预渲染光晕精灵**
   启动时按色相量化成 32 桶预渲染光晕 sprite，运行时 `drawImage` + `globalCompositeOperation='lighter'`。
   **绝不每帧调 `shadowBlur` 或新建渐变对象** —— 这是手机浏览器上最大的性能杀手。

4. **空间网格做邻居查询**
   感知与碰撞天然是 O(n²)。用均匀空间网格降到接近 O(n)，保证桌面 24 只、手机 16 只都满帧。

5. **静态背景交给 CSS**
   深水渐变写在 `css/main.css` 的背景上，canvas 保持透明叠加。省掉每帧一次全屏填充，也让 `lighter` 混合只在 canvas 内部生效（正是想要的效果）。

## 4. 生命系统

### 4.1 基因：孟德尔式双等位基因

每个性状存**两个等位基因** `[a, b]`（各为 0–1 的浮点数），不是单个数值。

```
表现型 phenotype = a × dom + b × (1 − dom)      dom = 该位点的母方权重（0.5 = 共显性，公平混合）
配子   gamete    = 随机取 a 或 b（各 50%）+ N(0, mutationRate) 后 clamp 到 [0,1]
子代   offspring = 双亲各贡献一个配子，组成新的 [a, b]
槽位约定         = slot 0 是母方、slot 1 是父方（layEggs(mother, father) → inherit(rng, mother.genes, father.genes)）
```

**`dom` 到底是什么 —— 以及它不是什么。** 这一条必须写清楚，因为它决定了家谱读起来是什么感觉，也因为它容易被误读成教科书里的显隐性：

- `dom = 0.5` 是**共显性**：表现型就是两个等位基因的均值，与谁在 slot 0 无关。`hue` 属于这一类 —— 颜色永远是双亲的公平混合，交换父母顺序不会改变孩子的色相。这是有意的：色相是整个项目里最显眼的性状，它不该取决于家谱里谁被写在前面。
- `dom ≠ 0.5` 是**偏母本权重**：slot 0（母方）的等位基因占更大比重。`pattern` 的 0.7 意味着花纹更像妈妈，`glow` 的 0.6 意味着发光基线略偏母方。因此**正反交的结果不同** —— 同一对基因，母方与父方互换会得到花纹不一样的孩子。这是刻意的家族信号：颜色混双方、花纹随母亲，于是"看得出像谁"在家谱里有了两条独立的线索。
- 它**不是**等位基因层面的显隐性。这个模型里没有任何一个等位基因会被另一个"掩盖"：`dom` 是加权系数，不是掩码。所以本节早先"因为玫红基因在双亲体内都是隐性的"那句解释是错的，已在下面更正。

**这个模型孟德尔的部分在哪里**：在**颗粒遗传**与**分离定律**，不在显隐性。两个等位基因在基因组里始终是分开的两个数，永远不会被平均掉；每个亲本形成配子时随机交出其中一个。正因为等位基因保持颗粒性，两个杂合亲本（各自都携带一个低色相等位基因、但表现型只是中等偏浅）可以生出一个**纯合低值**的孩子 —— 那孩子的色相落在双亲之外，比父母都深。

这才是"隔代惊喜"的真实机制，而它是**分离**在做功，不需要显隐性参与。`tests/genes.test.js` 里的 F1→F2 重现测试正是钉住这条路径的：如果分离退化成"永远取 slot 0"或"永远取 slot 1"，那条测试会失败。

**所有等位基因都是 `[0,1]` 区间内的无量纲浮点数**，由表现型解码函数映射到实际性状。这样做有两个必要好处：

1. **混合永远在基因空间（线性）进行，不在性状空间进行。** 这对色相尤其关键 —— 粉色区间跨越 0°，直接在角度空间插值会绕远路得到错误的中间色；在基因空间插值则永远正确。
2. 存档与变异逻辑与具体性状的单位无关，新增性状不需要改遗传代码。

**为什么用双等位基因而不是单个数值**：因为**颗粒遗传 + 分离**能生出双亲之外的性状。一对浅樱粉的父母可能生出一只深玫红的孩子 —— 不是因为玫红基因被"隐性掩盖"过（这个模型没有显隐性），而是因为双方都携带一个低色相等位基因，而分离让这两个低值在孩子身上凑到了一起。共显性性状（如色相）在多数情况下表现为混合色，但偶尔会跳出双亲的范围。几代之后缸里会自然分化出可辨认的家族支系，而你能在家谱里看出谁像谁 —— 色相看双方、花纹看母亲。单个数值的加权平均永远给不出这种惊喜：它只会让每一代都向均值收敛，几代之后全缸长成一个样。

**外观基因**

| 基因 | 表现型解码 | 母方权重 `dom` |
|---|---|---|
| `hue` | `(315 + phenotype × 70) mod 360` → 315°–385°(=25°)，即粉色区间 | 0.5（共显性） |
| `sat` | `0.45 + phenotype × 0.5` → HSL 饱和度 **45%–95%** | 0.5（共显性） |
| `lum` | `0.62 + phenotype × 0.22` → HSL 亮度 **62%–84%** | 0.5（共显性） |
| `size` | `MIN_SIZE + phenotype × (MAX_SIZE − MIN_SIZE)`，单位为世界单位 | 0.5（共显性） |
| `glow` | `0.35 + phenotype × 0.65` → 发光**基线**强度 **0.35–1.0** | 0.6（偏母本） |
| `pattern` | **分桶离散化**：`[0,0.2)` 无 / `[0.2,0.4)` 圆斑 / `[0.4,0.6)` 环纹 / `[0.6,0.8)` 云斑 / `[0.8,1.0]` 星点 | 0.7（偏母本） |
| `patternDensity` | 直接作为花纹密度系数 | 0.5（共显性） |
| `wobble` | 直接输出 `[0,1]`，由运动层（计划 2）映射到身体弹簧的刚度与阻尼 | 0.5（共显性） |

**为什么 `sat` / `lum` / `glow` 是区间映射而不是直接透传**（这三行修正了本节早先"直接作为 HSL 饱和度/亮度"的写法，那句与 §4.2 的粉色锁定冲突）：

- **`sat` 下限 45%**：饱和度接近 0 的个体是灰白的，而灰白不是粉色。用户对这个物种的明确要求是"颜色是粉色，可爱一点"，§4.2 也写着"这个物种就是粉色的"。让基因自由决定饱和度，等于允许缸里出现不符合物种认同的灰色个体。
- **`lum` 区间 62%–84%**：下界保证个体在深靛紫水体（`#0B0620 → #2D1240`）里始终可读 —— 一只接近黑色的半透明凝胶在暗水里等于隐形；上界防止高光溢出成白色而丢掉色相。
- **`glow` 下限 0.35**：`decode().glow` 是**基因决定的发光基线**，不是最终亮度。情绪表现层（§5）会在此基础上做乘法调制 —— 困倦时脉冲几乎停摆、恐惧时光晕收缩到核心、兴奋时最亮。有下限才意味着"从不发光"不是这个物种的状态，情绪的明暗变化靠调制而非开关来表达。渲染层（计划 2）应当读取这个 `[0.35, 1.0]` 的基线，再乘以情绪系数。

**`wobble` 的行是有意留白的**：它是唯一不在 `decode` 里完成单位换算的外观基因，因为它要变成弹簧物理参数，而那属于运动层。`decode` 只负责外观单位（色相角度、HSL 百分比、世界单位尺寸），物理参数由计划 2 的 `body.js` 解释。


`pattern` 是唯一需要离散化的基因：它必须分桶，因为"半个圆斑和半个环纹"没有意义。分桶的副作用是有益的 —— **两个表现型相近的父母可能因为落在不同桶里而生出花纹完全不同的孩子**，这是另一种隔代惊喜。

**性格基因**（均为 0–1，`dom` 一律 0.5 即共显性 —— 性格是双亲的公平混合，不偏向任何一方）

| 基因 | 低值 ← → 高值 |
|---|---|
| `bold` | 胆小 ↔ 胆大 |
| `clingy` | 独立 ↔ 黏人 |
| `irritable` | 温和 ↔ 暴躁 |
| `gluttonous` | 少食 ↔ 贪吃 |
| `curious` | 安分 ↔ 好奇 |
| `libido` | 冷淡 ↔ 积极 |

### 4.2 色系：锁定粉色家族

`hue` 基因的取值范围从 0–360° **收窄到 315°–360° + 0°–25°**，即樱花粉 → 桃粉 → 珊瑚粉 → 玫红粉 → 淡粉紫这一段。饱和度和亮度仍自由变异。

**这个物种就是粉色的。** 家族色系在粉色区间内分化，比"什么颜色都可能"更有物种认同感，而孟德尔遗传带来的隔代惊喜完整保留。

| 性状 | 色值 |
|---|---|
| 樱花粉（最常见基色） | `#FFC8DE` |
| 桃粉 | `#FF9EB5` |
| 珊瑚粉 | `#FF8FA3` |
| 淡粉紫 | `#E8A7D8` |
| 玫红（稀少 —— 需要双亲都携带低色相等位基因，靠分离凑到一起，见 §4.1） | `#FF4D8D` |
| 腮红 | `#FF6B9D` |
| 瞳孔 | `#2D1240`（**不用纯黑** —— 纯黑在粉色身体上显得空洞） |

花纹四种：**圆斑 / 环纹 / 云斑 / 星点**（星点是身上散落的小亮点，像雀斑，在暗水里会单独发光）。

### 4.3 背景：深靛紫而非冷蓝黑

原来的深蓝黑会**压制**粉色（接近补色对抗，粉色会显得脏）。改用深靛紫渐变：

```
#0B0620  顶部深水
#1A0B2E  中部
#2D1240  底部
微粒：#FFD9E8，alpha 0.15–0.4，缓慢上浮
```

靛紫与粉色在色环上相邻，所以**和谐**；但明度差极大，所以粉色生物光依然**对比强烈、像在发光**。这是"可爱"和"梦幻"能同时成立的关键。

### 4.4 需求：四条匮乏度

全部为 0–1，**0 = 满足，1 = 极度匮乏**。

| 需求 | 上升于 | 满足于 | 基因调制 |
|---|---|---|---|
| `hunger` 饥饿 | 时间流逝 | 吃到食物 | 体型大、`gluttonous` 高 → 上升更快 |
| `energy` 精力 | 活动 | 休息 / 睡眠 | — |
| `social` 社交 | 独处 | 附近有同伴 | `clingy` 高 → 上升更快 |
| `safety` 安全感 | 被戳、被欺负、被逼近 | 安静环境 + 亲属或伴侣在旁 | `bold` 高 → 上升更慢 |

**需求的角色**：需求**不直接决定行为**，而是为 4.10 的效用评分提供"紧迫度"这一项。所以最匮乏的需求会强烈地推高相关候选行为的得分，但不会一票否决其他行为 —— 一只极饿但正被大只逼近的生物，仍然会选择先逃。**这个竞争关系正是行为看起来"像活的"的原因。**

### 4.5 情绪：并存向量，不是互斥状态机

**情绪向量恰好六个分量**：`joy` `anger` `fear` `curiosity` `sleepy` `arousal`，各 0–1。

- **带惯性平滑趋近**目标值 —— 生气不会瞬间消失，会持续一阵再慢慢平复。这是"生物感"的关键。
- **关键决定：情绪可以并存。** 一只生物能同时"害怕 0.7 + 好奇 0.4"，即想靠近又不敢。行为由加权竞争决定，**表现由主导情绪决定，但次要情绪会泄漏出来**（害怕地缩着，却还是微微往前探了一点）。

这正是"不能说话但你能读懂它"的丰富性来源：它不是显示一个状态，而是**同时表达好几层**。

> **注意：`affection`（依恋/卖萌）不是情绪向量的分量。** 它是 `memory` 里的**关系性数值**（针对某个特定对象，见 4.8），因为"依恋谁"本质上是关于一段关系的，不是关于当下状态的。
> 下表把"卖萌"列为一种**表达状态**，它的触发条件是：`memory[PLAYER].affection` 高 **且** 玩家的手在附近 **且** `joy` 不低。它由记忆 + 情境共同触发，而不是由一个独立的情绪分量驱动。

#### 情绪 → 身体语言与体色（本项目的灵魂）

| 情绪 / 表达状态 | 身体语言 | 体色 | 发光 |
|---|---|---|---|
| `joy` 开心 | 膨胀成圆球、轻快上下浮动、小幅弹跳、蹭玩家 | 亮桃粉 `#FF9EB5` | 光晕扩大，缓慢脉动 |
| `anger` 生气 | 剧烈颤抖、身体压扁且前端变尖、冲刺撞对方、背过身 | 深品红 `#FF1F6B` | 高频急闪，光晕收紧变刺 |
| `fear` 害怕 | 摊平贴缸底、缩成一小团、急逃、躲到缸壁角落 | 褪成灰白粉 `#D8C4CC` | 收缩到只剩核心一点 |
| `curiosity` 好奇 | 身体朝目标伸长、缓慢靠近、前端左右摆 | 偏蜜桃橙粉 | 光晕前移集中 |
| `sleepy` 困倦 | 下沉瘫在缸底、形变幅度极小、缓慢起伏 | 暗粉紫 `#8E6A8C` | 脉动慢到几乎停止 |
| `arousal` 求偶 | 绕圈、脉动同步、轻触、膨胀展示 | 粉紫 ↔ 桃粉双色交替 | 全场最亮 |
| 卖萌（记忆驱动，非情绪分量） | 贴着手指蹭、翻肚皮、吐小泡泡、轻撞玩家的手 | 最柔樱花粉 + 腮红泛开 | 呼吸式柔和脉动 |

### 4.6 眼睛与朝向：可爱最大的杠杆

半透明团子靠形变表达情绪是好的，但在"不能说话"的设定下，**眼睛是信息密度最高的通道**。眼睛属于身体，不是漫画外挂。

**先定义朝向（`facing`）**：一只软体团子必须有明确的"前端"，否则"前倾""后移""背过身"全都无从谈起。

```
facing = 单位向量，由速度方向平滑插值得到（转向有惯性，不是瞬间掉头）
静止时  = 保持上一次的 facing（它不会失去朝向）
朝向改变的速度由 bold 基因调制：胆大的转身果断，胆小的迟疑
```

眼睛长在 `facing` 一侧，垂直于 `facing` 的方向上左右分开。所有眼睛参数的"前/后"都指**沿 `facing` 方向的偏移**。

用**四个连续参数**驱动，不用预设表情：

```
pupilSize   瞳孔大小 0–1
lidOpen     眼睑开合 0–1
eyeSpacing  两眼间距（惊吓外扩，生气内收）
eyeOffset   沿 facing 的位置偏移（前倾=好奇，后移=害怕，上望=卖萌时叠加一个垂直分量）
```

| 情绪 | 眼睛 |
|---|---|
| joy | 眯成两道上弯弧 `^^`，`lidOpen ≈ 0.3` |
| anger | 瞪圆但上眼睑压低，`pupilSize ≈ 0.25`，`eyeSpacing` 内收 |
| fear | 瞪到最大，`pupilSize ≈ 0.15`，`eyeOffset` 沿 facing 后移 |
| curiosity | **一只眼睁大一只微眯**，瞳孔放大，`eyeOffset` 前倾 |
| sleepy | 半闭，极缓慢地眨 |
| 卖萌 | 瞳孔放到最大 `≈ 0.95`（婴儿式），叠加向上的垂直偏移（微微上望） |
| 信任玩家 | 看着玩家的手时**缓慢眨一次眼**（猫的 slow blink） |
| 死亡 | 眼睛缓缓闭合，`lidOpen → 0` |

眼睛大而圆，占身体宽度约 28%。瞳孔用深紫 `#2D1240`，**不用纯黑** —— 纯黑在粉色身体上显得空洞。

**"看着玩家的手"**：当玩家的手指/光标在附近时，`facing` 会缓慢转向它（好感高时主动转，好感低时反而转开）。这个"它在看你"的感觉，比任何表情都更能建立联系。

### 4.7 可爱的两个物理机制

**幼态比例（neoteny）**：可爱有生理基础 —— 大眼、圆身、短小、动作笨拙（婴儿图式 baby schema）。所以：

- 眼睛比例偏大，且**成体也保留幼态特征**（不像真实动物那样长大后眼睛比例变小）
- 身体更圆更短，`wobble` 基因整体偏高 → 形变更明显
- 幼体与亚成体的移动带**轻微笨拙感**：偶尔冲过头、撞到缸壁、跌一下再爬起来。**这不是 bug，是可爱。**

**Q 弹物理**：形变必须带**过冲回弹**（squash & stretch + overshoot）：

- 落地/停下时先压扁再弹回，弹回时**超过**原尺寸一点点再收敛
- 移动时身体有延迟跟随的惯性抖动（像果冻）
- 挤压幅度由 `wobble` 基因决定，所以有的孩子天生更 Q，有的更挺

### 4.8 关系记忆：它记得谁对它好

每只生物对其他个体维护一条记录：

```js
{ id, familiarity /* 熟悉度 0–1 */, affection /* 好感 −1..1 */,
  kinship /* 亲缘系数 */, role /* mother|father|sibling|mate|offspring|null */ }
```

- `affection` 由互动累积：喂食 / 抚摸 / 求偶 / 共同孵化 → **+**；抢食 / 撞击 / 欺负 → **−**
- **恩怨指数衰减趋向 0** —— 会淡忘。但长期伴侣、母子的衰减极慢，近乎不忘
- `kinship`：父母与同胞 0.5、祖孙 0.25 → 用于**近亲回避**与**亲属偏好**（更容忍亲属靠近）
- **对玩家也维护一条同结构的记忆** `id: 'PLAYER'` —— 这是"手机上喂过它，回到电脑上它还认得你"的实现基础。好感高的会主动游向玩家的手卖萌；好感低的会躲开；被戳多了的一见手就逃
- **容量上限 12 条**，超出时淘汰 `familiarity` 最低的 —— 多代之后内存不会无限增长，而且"遗忘"本身就是真实的

### 4.9 性格 → 行为调制

性格基因不直接指定行为，而是**调阈值和权重**：

| 基因 | 调制效果 |
|---|---|
| `bold` 高 | 害怕阈值高、更敢接近玩家的手、被打扰后恢复快 |
| `clingy` 高 | 社交匮乏上升快、更倾向靠近其他个体、更常卖萌 |
| `irritable` 高 | 生气阈值低、生气持续时间长、更常撞击 |
| `gluttonous` 高 | 饥饿阈值提前触发觅食、会为食物争抢 |
| `curious` 高 | 新事物出现时好奇增长快、探索半径大 |
| `libido` 高 | 求偶欲上升快、更容易接受求偶 |

**结果**：同一窝出生的孩子，因为基因组合不同，会走出完全不同的生活。这些是涌现的，不是编排好的剧本。

### 4.10 行为决策：效用评分

```js
候选 = [觅食, 进食, 休息, 社交, 求偶, 产卵, 探索, 逃避, 卖萌, 抗议, 争斗]

score(候选) = 需求紧迫度 × 性格权重 × 情境可行性 × 情绪倾向
            + 少量随机扰动

选择最高分者；行为有最小持续时间和中断规则（进食被打断会生气）
```

选效用评分而非状态机的理由：新增行为只要加一个候选项和评分函数，不动其他代码；行为之间的竞争与犹豫是自然涌现的；随机扰动避免机械感 —— **它不该每次都做"最优"选择**。

### 4.11 生命周期：连续生长 + 阶段门槛

默认时长（模拟秒，@1×）。**完整寿命 = 60 + 180 + 300 + 480 + 180 = 1200 秒 = 20 分钟**；从卵到具备繁殖能力的成体需 540 秒 = 9 分钟：

| 阶段 | 时长 | 特征 |
|---|---|---|
| 卵 `egg` | 60s | 缸底微光脉动；快孵化时脉动加快，壳内透出轮廓 |
| 幼体 `hatchling` | 180s | 极小、光弱、几乎只吃和睡、紧贴孵化点、认妈妈 |
| 亚成体 `juvenile` | 300s | 快速长大、好奇强、爱探索、会和同伴打闹、不能繁殖 |
| 成体 `adult` | 480s | 性成熟、体型最大、发光最强 |
| 老年 `elder` | 180s | 体型微缩、动作变慢、光转暗转暖、不再繁殖 |
| 死亡 | — | 停止运动 → 光慢慢熄灭 → 身体溶散成微粒上升消散 |

20 分钟 @1× 是刻意选的：一晚上开着 4× 就能看到十几代，而单只的寿命又长到足以建立感情。这两个目标互相拉扯，20 分钟是折中点，最终靠 `config.js` 调。

**生长是连续插值，不是阶段跳变**：体型、光强、花纹密度都随年龄平滑变化，阶段只是能力门槛。所以你能看见它一天天变大，而不是某天突然换了一个形态。

**死亡时，附近的个体会停顿、变暗一小会儿** —— 一种非常原始的哀悼。不解释、不提示，你看到就看到了。

### 4.12 繁殖：求偶仪式 + 近亲回避

1. **触发条件**：两只均为成体、亲缘系数低于阈值、`arousal` 都够高、都吃饱、附近无威胁
2. **求偶仪式（8–12 秒，可被打断）**：
   - 相互绕圈，速度逐渐同步
   - **体色脉动同步**（整个项目最动人的画面）
   - 前端轻触对方，双方膨胀展示
   - 脉动同步的瞬间，身体表面散落几个小亮点闪一下
   - 若一方 `affection` 太低或被打扰 → **拒绝，转身离开**；被拒方短暂变暗或生气
3. **产卵**：1–3 枚，双亲基因按分离 + 重组 + 变异写入**每一枚**（所以每枚都不同）
4. **孵化**：幼体出壳，双亲互记为 `mate`，子代记 `mother`/`father`；母亲在幼体期会守在附近（`affection` 高时）
5. **近亲回避**：`kinship > 0.25` 的两只**不会进入求偶**，保证多代后种群健康
6. **种群上限用叙事实现**：达上限后求偶评分被压低（表现为"彼此不太感兴趣"），卵不孵化（表现为"这枚卵的光慢慢熄灭了"）。世界规则始终自洽

## 5. 表现层

### 5.1 软体身体

身体是**一圈 24 个控制点**围成的闭合环，每个点带弹簧动力学：

```
形变来源 = 运动挤压（沿速度轴 squash & stretch）
         + 情绪（怒→压扁且前端变尖 / 惧→整体收缩 / 喜→膨胀）
         + 碰撞局部凹陷（撞墙或被撞的那一侧凹进去）
         + wobble 基因决定的弹簧刚度与阻尼
绘制     = Catmull-Rom 平滑闭合曲线 → 贝塞尔路径
```

**分层绘制**（由内到外）：光晕（`lighter` 叠加）→ 半透明凝胶体（alpha ≈ 0.55 径向渐变）→ 花纹 → **发光核**（体心一颗脉动的亮椭圆，颜色 = 情绪色）→ 眼睛 → 腮红 → 左上缘高光。

高光和内阴影是让"半透明凝胶"看起来有体积感的关键，不是可选装饰。

### 5.2 深水体

- 静态背景用 **CSS 渐变**（见 4.3），canvas 透明叠加
- 上浮微粒 60–120 个，**对象池**复用，运行时零分配
- 2–3 道缓慢摆动的柔光束，预渲染 sprite 平移
- 缸底一条深色沉积带 + 几个柔软小丘（产卵点）

### 5.3 性能预算

| 平台 | 种群上限 | 目标帧率 |
|---|---|---|
| 桌面 | 24 | 60fps |
| 手机 | 16 | 60fps |

硬约束：**不每帧 `shadowBlur`、不每帧新建渐变、运行时不分配对象**（微粒与事件用对象池）。

### 5.4 声音：Web Audio 程序化合成，零音频文件

不加载任何 `.mp3` —— 全部用振荡器实时合成，所以**依然是零依赖**。

| 事件 | 声音 |
|---|---|
| 开心 | "咐咐" 两声短促上滑正弦，600→900Hz |
| 卖萌 | "啵" 快速下滑 400→200Hz + 一点气泡噪声 |
| 生气 | 低沉"咕噜" 90–140Hz，带轻微抖动 |
| 困倦 | 长缓慢下滑音，柔和起音 |
| 求偶成功 | 柔和的两音小铃 |
| 孵化 | 细碎裂声 + 一个上扬小音 |
| 死亡 | 极轻的下滑音，几乎听不见 |

**关键设计：音高随体型变（小只高、大只低），音色随色相基因变** —— 所以**每条家族血脉有自己的嗓音**。你不看屏幕都能听出是哪一家的孩子在叫。这是零依赖方案独有的优势：音频文件做不到参数化。

**注意**：这仍然是"不能说话" —— 这些是非语言的生理性发声，不含任何词汇或语义。

手机浏览器要求用户先交互才能启动 AudioContext → 首次 pointer 事件时 `resume()`。默认开启、音量很小、右上角有静音按钮；若被阻止则静默降级并隐藏按钮。

## 6. 玩家交互

### 6.1 手势

全部用 **Pointer Events** 统一触控与鼠标，**不依赖 hover**（手机没有 hover）。

| 操作 | 效果 |
|---|---|
| 从底部食物条**拖拽**食物入缸 | 投食（精确放置） |
| **长按**缸内一点 | 在该处撒食 |
| 在生物身上**缓慢划动** | 抚摸 → `affection` +、`joy` +，它会蹭你的手 |
| **快速戳** | `safety` −、`fear`/`anger` +，它会躲开或抗议 |
| **点按单只** | 打开信息卡 |
| **长按单只** | 给它取名 |

**抚摸与戳是同一根手指、不同速度，反应完全相反。** 这个区分是整个交互的核心：它逼你**温柔地**对待它，而它会用身体告诉你你做对了还是做错了。这本身就是"通过行动表达想法"的双向版本。

判定方式：追踪最近若干 pointer 采样的速度；速度超过阈值且位移方向反复（戳）判为戳，速度低且沿生物身体轮廓移动（划）判为抚摸。

### 6.2 三种食物

食物刻意**避开粉色系**（青绿 / 琥珀 / 淡蓝），这样它们在粉紫色的世界里一眼可辨，不会被误认为生物。

| 食物 | 外观 | 作用 | 设计意图 |
|---|---|---|---|
| **光藻** | 青绿微粒 | 基础食物，恢复少，会缓慢自然再生 | 保底生存，不构成戏剧 |
| **蜜珠** | 琥珀金珠 | 高能量，恢复多，**所有生物都爱吃** | **争抢的主要来源，恩怨由此产生** |
| **冰晶** | 淡蓝结晶 | 安抚作用，降低 `anger`/`fear` | 玩家的"灭火器"，可在两只打架时丢一颗 |

### 6.3 UI

**名字**：因为它不能说话，名字是你给的。自动生成粉色系叠词名（泡泡、团团、蜜桃、软软、樱樱、糯糯、朵朵…）+ 序号区分（`小桃·三`），可长按改名。

**信息卡**：名字 / 年龄 / 阶段 / 体型 / 父母 / 伴侣 / 孩子数 / **性格雷达图**（六维基因）/ **对玩家的好感度**。
好感度用**心形填充度**表示，**不写数字** —— 保持"它不能用语言交流"的一致性。信息卡是你这个照料者的观察记录，不是它在对你说话。

**家谱**：树状图，节点是代表色相的小圆点，连线表示亲代 / 伴侣 / 同胞。手机上全屏，桌面上侧栏。

**HUD 极简**：左上种群数与食物余量，右上时间流速（0.5× / 1× / 2× / 4×）+ 静音 + 暂停，底部食物条。**平时半透明淡出，交互时才浮现**，不遮挡水体。所有触控目标 ≥44px，适配 iOS `env(safe-area-inset-*)`。

## 7. 存档、多设备与错误处理

### 7.1 服务器

`server.ps1` 用 .NET `HttpListener`（Windows PowerShell 5.1 自带，无需安装）：

- 静态文件服务，绑定 `0.0.0.0` 以便手机通过局域网访问
- `GET /api/save` → 读取 `save.json`
- `PUT /api/save` → 写入。**原子写入**：先写 `save.json.tmp` 再 `Move-Item -Force` 覆盖，避免写一半时断电留下损坏文件
- `start.bat` 启动时打印本机局域网 IP（如 `http://192.168.1.5:8420`）供手机访问，并自动打开本机浏览器

### 7.2 存档格式

```jsonc
{
  "version": 1,
  "revision": 42,
  "savedAt": "2026-10-14T10:00:00Z",
  "world": {
    "seed": 12345,
    "timeScale": 1,
    "food": [ { "id": "f1", "kind": "algae", "x": 0.42, "y": 0.81 } ]
  },
```

**位置存归一化 `[0,1]²`，体型存世界单位** —— 这样同一份存档在竖屏手机和横屏电脑上都正确（见 3.4 第 2 条）。

### 7.3 写入时机

- 每 5 秒 flush 一次
- `visibilitychange` / `pagehide` 时**立即** flush（手机上切后台太常见了，不能等到下一个 5 秒）

### 7.4 离线暂停

存档记 `savedAt`，但**恢复时不补算流逝时间**。世界从暂停那一刻继续 —— 你三天后回来，它们还在你离开的那一秒等着你，一只都没少。

### 7.5 多设备同时打开同一个缸

共享存档的真实风险。策略：存档带 `revision` 计数。

- 客户端持有自己加载时的 `revision`
- `PUT` 时带上该值；服务器比对磁盘上的 `revision`
- 若磁盘的更新 → 返回 **409**，**不覆盖**
- 客户端弹出提示"另一台设备刚刚改动了这个世界"，让用户选择**加载它的版本**或**接管**（强制覆盖）
- **`revision` 只由服务器递增**：每次成功写入后，服务器把磁盘上的 `revision` +1 并写回。客户端从不自行计算 `revision`，只负责携带自己加载时读到的那个值。这个单一所有权避免了两边各算一套导致的编号错乱

**绝不静默丢失任何一边的进度。**

### 7.6 服务器不可达时自动降级

若 `/api/save` 请求失败（例如项目被丢到 GitHub Pages 上当纯静态站打开），自动改用 `localStorage`，并在 HUD 显示一个小图标提示"本地存档"。

**同一份代码同时支持共享存档和独立部署** —— 这是很划算的鲁棒性收益，也顺手解决了"手机上不依赖电脑开机也能玩"的场景。

### 7.7 错误处理原则

**绝不静默丢失用户数据，绝不让整个世界崩溃。**

| 情况 | 处理 |
|---|---|
| 存档 JSON 解析失败 | 坏文件重命名为 `save.corrupt-<时间戳>.json` **保留证据**，开一个新缸，HUD 提示一次 |
| 存档 `version` 不兼容 | 尝试迁移；无法迁移则同样备份后重置 |
| **单只生物 tick 抛异常** | `try/catch` **隔离这一只**（标记 `sick: true`、停止行为、记录日志），其余照常。**任何一只的边界 bug 都不该导致白屏** |
| canvas 不可用 | 友好提示 |
| AudioContext 被阻止 | 静默降级，首次交互时重试；仍失败则隐藏声音按钮 |
| 标签页长时间后台 | rAF 自然暂停，恢复时 dt 封顶 0.25s |
| 端口被占用 | `start.bat` 打印明确错误并尝试下一个端口 |

## 8. 测试策略

### 8.1 单元测试（自动化）

`node --test tests/*.test.js`，无需浏览器、无需任何测试依赖 —— 这是 3.2 节模块边界约束的直接回报。

| 模块 | 重点覆盖 |
|---|---|
| `genes` | 大量采样后子代表现型落在双亲之间且方差符合预期；变异被正确 clamp 到 `[0,1]`；**双亲之外的极端性状确实能隔代出现**（这是设计承诺，必须被测到 —— 机制是分离而非显隐性，见 §4.1）；**同胞之间必须互不相同**（每枚卵独立分离与变异）；**`inherit` 的实参顺序被钉住**（slot 0 = 母方，交换父母会改变 `pattern`/`glow`） |
| `needs` | 衰减速率正确；满足后不会变负；**结果与时间步长无关**（固定步长的核心保证） |
| `emotions` | 惯性平滑单调趋近目标；**并存向量互不清零**；事件冲击幅度正确 |
| `memory` | 好感累积与指数衰减；容量上限淘汰的是 `familiarity` 最低的；亲缘系数计算正确 |
| `personality` | 各基因对阈值的调制方向正确 |
| `behavior` | 固定 rng 种子下决策**可重现**；饥饿极高时必选觅食；**近亲绝不进入求偶**；种群达上限时求偶评分被压低 |
| `creature` | 阶段按年龄正确切换；死亡后不再 tick |
| `rng` | 同种子产生同序列；分布均匀性 |
| `names` | 不重复冲突时追加序号 |

### 8.2 视觉核对清单（手工）

渲染层是视觉的，不做单测。改为 `tests/visual-checklist.md`，逐项核对：

- 七种情绪的身体语言与体色是否**在无文字提示下可辨认**
- 粉色生物在深靛紫背景上是否确实"像在发光"
- 竖屏手机上缸是否铺满、生物是否不畸形不过小
- 求偶仪式的脉动同步是否看得懂
- 死亡的溶散是否足够温和（不惊悚）
- Q 弹回弹是否自然而非抽搐

## 9. 初始状态与成功标准

### 9.1 新缸

生成 **4 只亚成体**（基因随机、色相在粉色区间、性格各异）+ 少量光藻。

选亚成体而不是卵，是为了让你**几分钟内就能看到第一次求偶**，而不是对着空缸等。

### 9.2 成功标准（验收依据）

1. 你能在**不读任何文字说明**的情况下，看出一只生物现在是开心、生气、害怕、困还是在卖萌
2. 你能看出**两只之间的关系** —— 谁喜欢谁、谁在躲谁、谁是谁的孩子
3. 你能看出**孩子像谁**，并且偶尔遇到一次隔代遗传的惊喜
4. 手机竖屏和电脑横屏打开**同一份存档**，缸都自然铺满，生物大小都合适
5. 关掉三天再打开，它们**还在你离开的那一秒**，一只都没少
6. 你会舍不得让某一只死掉

## 10. 范围外（YAGNI）

明确**不做**的东西，避免范围蔓延：

- 多缸 / 多世界切换
- 账号系统与云同步（共享存档走局域网即可）
- 天气与季节系统
- 疾病、寄生虫、变异怪物
- 玩家之间的多人互动
- 捏合缩放等复杂手势
- 音频素材文件（全部程序化合成）
- 生物进化出新器官或上岸
- 拍照 / 分享 / 导出视频
- 构建工具、打包器、TypeScript
- 任何 npm 依赖
