# 共享存档（局域网 + 409 仲裁）—— 设计（2026-10-29）

主 spec §7.5 / §7.6 早写死了协议（revision 计数、PUT 带版本、409、两份选择、"绝不静默丢失"），
但计划 2 只落了 `localStorage`。本文件定的是**局域网这一档**怎么把它做出来：
托管方式与冲突策略由控制方在 2026-10-29 拍定 —— **扩展 `server.ps1`（零月费、零账号）**、
**冲突时 409 + 让玩家选**。

## 0. 一句话

页面服务与存档服务**同一个进程、同一个源**：`server.ps1` 多两条路由，
`GET /api/save` 取缸、`PUT /api/save` 交缸（带 `baseRevision`），版本对不上就 409；
客户端拿不到服务器就退回 `localStorage` 并在 HUD 挂一个"本地存档"图标。

## 1. 协议

### 1.1 `GET /api/save`

- `200` → `{ "revision": <int>, "doc": <存档对象> }`（`doc` 就是 `serialize()` 的产物）
- `404` → 服务器上还没有缸（第一次开）
- 其它 → 客户端按"服务器不可用"处理

### 1.2 `PUT /api/save`

请求体：`{ "baseRevision": <int>, "doc": <存档对象> }`

- 磁盘上 `revision === baseRevision` → 写入 `doc`（`doc.revision = baseRevision + 1` 由**服务器**写），
  返回 `200 { "revision": baseRevision + 1 }`
- 磁盘上 `revision !== baseRevision` → **不写**，返回 `409 { "revision": <磁盘上的> }`
- 磁盘上没有缸（首次）→ 视作 `baseRevision === 0` 才成立，否则 409

**`revision` 只由服务器递增**（§7.5 原文）。客户端只携带自己加载时读到的那个数，
从不自增 —— 两边各算一套编号的经典错法在这里一次性排掉。

### 1.3 落盘（服务器侧）

- 文件：`save.json`，**与 server.ps1 同目录**，不进版本库（`.gitignore` 加一条）。
- **原子写**：先写 `save.json.tmp` → `Move-Item -Force` 覆盖。写到一半断电不会留下半份档。
- 没有 `save.json` ⇒ 404，不自动建空档（自动建空档会把"还没玩过"变成"有一份空缸"）。
- 只服务 `GET /api/save` 与 `PUT /api/save`；其它 `/api/*` 一律 404（不给自己留暗门）。

### 1.4 安全边界（如实写，不假装有）

**没有认证**：能连上这个端口的人都能读、能写这缸。所以它只适合**家庭局域网**，
监听地址仍是 `localhost`/内网，不做出公网的说明与默认值。要公网共享得另做一层
（那是 §7.5 的云托管档，本轮不做）。
`/api/save` 与页面同源，所以不需要 CORS；`server.ps1` 也不加任何跨源头。

## 2. 客户端

### 2.1 纯层（`src/remote.js`，可单测）

只有三个纯函数，`fetch` 的调用方仍然是 `main.js`（§3.2 的机器化守卫：浏览器标识符
只许出现在 `main.js`）：

- `parseSaveResponse(status, text) → { kind: 'ok'|'none'|'conflict'|'error', revision?, doc?, reason? }`
  —— 把 HTTP 状态与响应体归成**四种**，别的一律 `error`。坏 JSON 也是 `error`。
- `nextRevision(base) → int` —— 服务器侧语义的单点定义（`base + 1`），测试钉住它不吃负数。
- `decideBoot(local, remote) → 'use-remote' | 'use-local' | 'fresh' | 'ask'`
  —— 加载时两边都有档怎么办：**内容相同就用远端**（省一次仲裁）；不同就 `ask`
  （**绝不静默挑一个**）；只有一边有就用那一边；都没有 = `fresh`。
  "内容相同"的判据是 `revision` 与 `savedAt` 都相等 —— 不比对整个 doc（那是几万字符的
  deepEqual，且 RNG 不序列化，逐字节相同本来就不该期待）。

### 2.2 接线（`main.js`）

- **boot**：先 `GET /api/save`（只试一次，带 `AbortSignal.timeout(1500)`）。
  - 网络错/超时/5xx → **本地档**，`saveState.backend = 'local'`，HUD 挂"本地存档"图标（§7.6）。
  - `ok`/`none` → `decideBoot` 决定用哪份；`ask` 时**不开缸**，直接把选择摆给玩家。
- **保存**：远端模式下 `write()` 序列化之后 `PUT`（异步），成功后把 `revision` 记进
  `saveState.revision`；失败分两类：
  - 409 → **冻结远端**（此后不再 PUT，本地继续跑）并把冲突读数挂出来，弹两份选择；
  - 其它（网络/超时/5xx）→ 切到本地档（本会话不再回远端），写一次 `localStorage`，
    HUD 挂图标。**下一拍刷新时再试远端** —— 自动重连要处理"离线期间对方改过"，
    那是又一轮仲裁，本轮不假装做到了。
- **远端模式下不写 `localStorage` 主键**：两份真相一旦并行，下次开机就得先猜谁是新的。
  唯一的例外就是 2.2 里那次"切到本地"的写。
- **冲突的两份选择**（§7.5 原文）：`加载它的版本` / `接管`。
  - `加载它的版本` = 重新 `GET` 并 `restoreWorld`，**不用刷新页面**（`restoreWorld` 已经是
    boot 路径上验证过的入口；`bodies` 由 `updateBodies`/`reconcileBodies` 自行收敛）。
  - `接管` = 用**服务器当前的 `revision`** 当 `baseRevision` 再 PUT 一次（§7.5 的"强制覆盖"）。
  - 在玩家选之前**冻结远端写**：既不再 PUT，也不静默丢弃本地进度（本地还在跑）。

### 2.3 HUD

- 一个角标：`本地存档`（§7.6 原文要求）。`saveState.backend === 'local'` 且
  `saveState.fallbackReason !== null` 时显示（全新设备本来就没有远端，不该挂这个角标）。
- 冲突时一个两按钮的条：文案「另一台设备刚刚改动了这个世界」+ `加载它的版本` / `接管`。
  两个按钮都要有 `aria` 名，键盘可达，回车不误触。

## 3. 明确不做（YAGNI）

- **不做云托管**：控制方选了局域网档。协议同一套，将来换托管只换 `fetch` 的地址。
- **不做自动重连/自动合并**：离线期间对面改过就是一次仲裁，别假装能自动决定。
- **不做 RNG 序列化**（§7.3.1 第 5 条那条老账）：本轮不碰，"两台设备接着同一缸继续长"
  仍然指**状态**的延续，不是随机流的延续。
- **不做多缸/多用户**：一个 `save.json` 一条缸。多缸要动协议、要定命名与配额，与本轮无关。
- **不做鉴权**：见 §1.4，如实写在文档里而不是藏在默认值里。

## 4. 验收判据

1. **协议纯层**：四种归类的边界各一条（200 缺 doc、409 缺 revision、坏 JSON、500）；
   `decideBoot` 的四条分支各一条，且"两边都不同"必须是 `ask`（静默挑一边就红）。
2. **服务器**：`GET` 无档 404；`PUT` 首次（base 0）成功并写 `revision: 1`；
   第二次带对版本成功 `revision: 2`；带旧版本 409 **且磁盘文件一个字节没变**；
   原子性：tmp 文件在成功后不存在。
3. **客户端**：远端可达 + 远端有档 ⇒ 用远端；远端 404 + 本地有档 ⇒ 用本地并上传；
   网络错 ⇒ 本地档 + `backend:'local'` + 角标；409 ⇒ 冻结远端（`saveState.blocked = 'conflict'`）
   且此后不再发 PUT（用计数的 fetch 桩钉住）。
4. **不静默丢**：冲突时本地世界继续跑、`localStorage` 不写主键（远端模式），
   两个选择各自的行为都有测试。
5. **角标只在降级时出现**：全新设备（没有远端档、没有本地档）不挂"本地存档"。
