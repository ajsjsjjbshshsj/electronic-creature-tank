# 拎着玩：拖动星绒绒（grab & carry）

> 日期：2026-10-24　状态：待控制方过　落点：本文件是设计真相，实现前还要出一份计划
> 上游依据：`2026-10-14-electronic-creature-tank-design.md` §6.1（抚摸与戳）、§4.1（世界字段与边界）、
> §4.7（squash & stretch）、§7.2（表现层不入档）
> 本文**回写**主 spec 的位置见 §11。

## 0. 这一件事的量级（为什么不是"加一条手势"）

现网代码里已经存在一条会吃掉拖动的通道：`isPoking` = **按下 + 手速快 + 贴上身体**（`src/sim.js`）。
拖拽把三条全满足 ⇒ 若不处理，"拎起一只走"= 一路上升沿发 `poked`
（`fear +0.45 / anger +0.25 / joy −0.3`）+ 每次一发 `startleAmount 0.55` 的安全感冲击 + 每一下都往
`world.events` 塞一条 `poke`。**症状是"我一动它就被连扎"，而不是"我拎起了它"。**
反过来 `isBeingPetted` = 慢 + 贴上，慢慢拎着走会一路白买好感（`petAffectionRate 0.06/s`）。

所以本设计的主干不是"新增手势"，而是**给手与身体的接触重排一套优先级**，并且要逐只判、不能整只手一刀切
（拎着 A 快速划过 B，B 仍然算被戳）。这也是它被判成 architectural 而不是 bounded 的原因。

## 1. 裁定汇总（控制方已点头的三条 + 本文补的细则）

| # | 裁定 | 依据 |
|---|---|---|
| R-1 | 拖动的目的是**拎起来玩，它要有反应**，不是摆放、不是工具性拖拽（拖去喂食留给计划 4） | 控制方选定 |
| R-2 | 反应方向由**性格 × 好感共同决定**，同一句话拖两只要得到两种反应 | 控制方选定 |
| R-3 | 松手**甩出去**：带惯性、会撞壁撞同伴、落地被现有 stretch 画成拉长；**不引入伤害与死亡** | 控制方选定 |
| R-4 | 接缝走 **A′**：`world.playerHand` 仍是表现层唯一可写字段，给它**加载荷** `grab: { id } \| null` | 控制方选定 |
| R-5 | 抓取成立由**位移**判，不引入时间阈值（"摸"与"拎"由物理本身分开） | 本文提出，控制方以"生成 spec 文档"回应 ⇒ **视为采纳**（这条是推断，不对就推翻）；唯 `pullOutRatio` 数值待实测（§12） |
| R-6 | 被拎的那只走**一条独立的运动律**，不复用 `moveToward` | 同上（同为推断）⇒ **视为采纳**；`followStiffness` 待实测（§12） |

## 2. 接缝：一个字段，多一个载荷

```
表现层（main.js）              内核（sim.js）
  pointerdown ──pickCreature──▶ 候选 id（每帧可换）
  每帧 poll 到手 ──shouldGrab──▶ world.playerHand = { pos, speed, down, appeared, grab: { id } }
                                        │
                                        └─▶ senses.playerHand.grab（拷贝，不搬引用，见 §8）
```

- **为什么是 A′**：`pickCreature`（`src/gestures.js`）用的半径是 `radiusPx`（`src/render.js:142`，含年龄
  与蛋加成）再夹 `CONFIG.hud.minHitPx` 下限 —— 与信息卡**同一口径**。内核只按距离自己推的话要另算一套
  几何，重叠时"拎的"与"点的"会不是同一只，而幼体屏上半径可小到 3px，内核那套半径会直接抓不住。
- **边界不破**：`world.playerHand` 依旧是表现层唯一写入点（`src/main.js:38` 那条自述、`src/sim.js:819`
  那条 ⚠️ 都仍然成立），约束守卫不用放宽。
- **不新增第二个上升沿寄存器以外的世界状态**。

## 3. 抓取判定（R-5：用位移，不用时间）

三条同时成立才算"拎住了"：

1. `down` 为真，且手上有一个候选 `id`（`pointerdown` 时用 `pickCreature` 定下）。
   **候选只在"还没拎住"的时候才换**：手仍在某只的接触范围内 ⇒ 候选可以改到那一只；
   一旦 `grab` 成立就**粘住**，抬起之前不换 —— 否则拖着拖着穿过另一只身上，手里会凭空换一只，
   而那正是玩家最先骂出来的错。
2. 手与该只中心的距**超过** `sizeOf(c)/1000 × CONFIG.grab.pullOutRatio` —— 即手把它**带离**了身体。
   手始终在身体表面范围内滑动 ⇒ 还是抚摸，一条都不变。
3. 该只 `alive` 且不是蛋。

抬起、候选消失、被拎的那只死亡 ⇒ `grab` 立即清空。

**必须成立的一条不等式**（写进守卫测试）：`CONFIG.grab.pullOutRatio > CONFIG.behavior.petContactRatio`
（现值 1.15）。否则"拎"与"摸"会同时为真，§6 的让路规则就白写。
`pullOutRatio` 的初值本文**不给数** —— 它是要用手拖两下才能定的手感量，见 §12。

## 4. 跟随与释放（R-6：一条独立的运动律）

`moveToward` 把速率钳在 `CONFIG.motion.baseSpeed × speedFactor`（`src/sim.js:756-767`）。
复用它 ⇒ 手快拖时身体追不上 ⇒ "一拖就脱手"。所以被拎的那只走**临界阻尼追随**：

```
// src/grab.js（纯函数，不碰浏览器、不碰 Math.random）
heldStep(c, hand, dt, cfg) → { x, y, vx, vy }
  // 半隐式欧拉：a = k(hand − pos) − 2√k · v      ← 临界阻尼，只有一个旋钮 k
```

`sim.js` 在 `switch (intent.kind)` **之前**判 `held`：命中就调 `heldStep`，写 `c.pos`（过 `clampPos`）
与 `c.vel`，置 `c.moving = true`，`return` —— 正常决策照旧发生但这一 tick 不执行它，松手后下一 tick 自然接管。

这条运动律同时白送三件事：

- **身体滞后于手** ⇒ `updateBody` 已有的"沿速度轴 squash & stretch"（`src/body.js:376-380`）自动把它画长，
  不需要任何新的渲染代码。
- **`c.vel` 就是真实位移率** ⇒ 松手即惯性。甩出去的初速度不需要另算一个"投掷"公式，
  也就不引入第二个可能与追随打架的真相。
- **墙与同伴碰撞照旧生效** ⇒ 拖到墙边手继续走，身体被墙截住 ⇒ 画面是"压在墙上拉长"，正是毛绒玩具该有的样子。
  R-3 的"不受伤"落在这里：沿用现有 `clampPos` 的"只截位置"语义，**不加**任何扣需求/扣血的通道。

追随刚度 `k` 与"甩出去"的爽感是同一个旋钮的两面（k 太小 → 像拖着一团面；太大 → 手一抖就飞出去），
同样留给实测，见 §12。

## 5. 反应：一条可测的规则，不是一堆系数

```
enjoy = clamp01( clingy × wClingy + affection × wAffection − irritable × wIrritable )
```

三项全部读现成字段：`c.traits.personality.{clingy, irritable}`、`affectionFor(c.memory, PLAYER_ID)`
（`src/sim.js:835` 已在用这个读法）。权重进 `CONFIG.grab`，不写死在代码里。

- **抓住的上升沿发一次**（与 `petted` / `poked` 完全同形，靠 §7 那个寄存器而不是计时器）：
  情绪表里加**两行**，各自按互补比例缩放后叠加 —— `applyEvent(emotions, kind, scale = 1)` **本来就接第三个
  参数**（`src/emotions.js`），所以这条不需要动任何接口：

  ```
  applyEvent(c.emotions, 'grabbedHappy', enjoy);
  applyEvent(c.emotions, 'grabbedRough', 1 - enjoy);
  ```

  为什么是两行而不是一行带符号：`applyEvent` 对表里**每一项乘同一个 scale**。写成一行
  `{ joy: +, anger: + }` 再乘一个 `k ∈ [−1, 1]`，会让"k<0 时 joy 降"与"k<0 时 anger 也降"同时发生 ——
  而不开心时 anger 应该**升**。两行 + 互补缩放是唯一能用现成机制表达"同一次事件的两个方向"的写法。
- **期间**：按手速连续积一个"被摇"的不适，符号仍由同一个 `enjoy` 翻转（不新增第二套规则）；
  `enjoy > 0.5` 才买好感，`familiarity` 照旧买。理由与 §6.1 抚摸那条同构：**"刷拎"换不到喜欢**，
  否则把手挂在那只身上就能喂满好感度。
- **出口**：`world.events.push({ kind: 'grab', id, enjoy })` 与 `{ kind: 'release', id, enjoy, speed }`
  —— 表现层拿它出气泡与表情。**本轮不加新叫声**：六声表与它的守卫是另一整件事（见 §10）。
- 眼睛完全不动：星星眼 / 委屈眼已经由 `moodOf` 驱动，情绪一变它们自己就变。

## 6. 让路规则（逐只判，不能整只手一刀切）

| 谓词 | 被拎的那只 | 其余个体 |
|---|---|---|
| `isPoking` | **false**（拖 ≠ 扎） | 照旧（拎着 A 划过 B，B 算被戳） |
| `isBeingPetted` / `isPetting` | **false** | 照旧 |
| `startled`（手突然出现） | **false**（它已经在你手里） | 照旧 |
| 决策 / `intent` | 本 tick 由 `held` 接管 | 照旧 |
| 个体间碰撞 | 照旧参与（会被撞、也会撞别人） | 照旧 |

实现要求：让路点**只加在各谓词开头的 `isHeld(c, senses)` 一判**，不许在调用方散着写 `if (grab) skip` ——
后者会在下一个消费者身上漏掉。

## 7. 世界状态与存档

- 新增一个上升沿寄存器 `c.held`（与 `c.beingPetted` / `c.beingPoked` 同形同族）：
  出生与读档时归零（`src/sim.js:353-354` 那一旁），并**加进 `save.js` 的 `CREATURE_SKIP_FIELDS`**
  （`'beingPetted', 'beingPoked'` 那一行）—— 表现层瞬时状态不入档，是 §7.2 的既有裁定。
- `world.playerHand` 本来就在跳过之列（`src/save.js:202/207`）⇒ **刷新页面天然松手**，不需要"存档里的抓"这种概念。
- 除 `c.held` 之外不落任何新字段；`grab` 的候选 id 属于表现层（`input`/`main`），不进世界。

## 8. 确定性与边界自查（这几条是这个仓库最常踩的）

1. **senses 拷贝**：`sim.js:525-527` 建 `senses.playerHand` 时 `pos` 是**按引用**搬的，而 `main.js:941`
   留了一句 ⚠️ —— "哪天内核改成把 `senses.playerHand.pos` 存进跨帧结构，这里就必须改成每次交付一份拷贝"。
   拖动会把抓的状态**跨帧存**（`c.held` 与候选 id），所以本轮必须把 `grab` 拷成新对象
   （`grab: h.grab ? { id: h.grab.id } : null`）。这条不写就会得到"隔帧读到的 id 是别人的"。
2. **倍速与空帧**：4× 时同一份手样本喂多个 tick ⇒ 上升沿必须靠 `c.held` 寄存器判，**不许**靠"这帧手速
   超过阈值"判次数；0.5× 有空帧 ⇒ 追随写成 `× dt`，不许写成"每帧位移"（与 `c.pos.y + 0.012 * dt` 同一条理由）。
3. **零 `Math.random`**、**只有 `main.js` 碰浏览器全局**：`grab.js` 是纯函数模块，`pickCreature` 的调用点
   仍然只在 `main.js`。约束守卫（七标识符白名单）不动。
4. **`world.events` 是新事件的唯一出口**，照 `poke` / `eat` 那条既有形状走，表现层每帧清空。

## 9. 测试策略（判据先于实现；每条都要有探针）

**纯函数层（新 `tests/grab.test.js`）**
1. `shouldGrab`：手在接触范围内移动 ⇒ 不成立；越过 `pullOutRatio` ⇒ 成立；抬起 ⇒ 立即失效。
   再加一条 **粘住**：已经拎住之后手穿过另一只的接触范围 ⇒ `grab.id` **不变**（§3 第 1 条的那条歧义
   就得靠这条测试来固定，否则两种读法都能过测试）。
2. `heldStep` 的三条数学性质：**临界阻尼不振**（过冲不反向越过手位）、`dt` 线性（同一 tick 拆两次 ≈ 一次，
   容差写死）、结果与 `k` 单调。
3. `enjoyOf` 单调：`clingy ↑` / `affection ↑` / `irritable ↑` 三个方向各一条，另加一条"三项全 0 ⇒ 中位而非 0"。

**内核层（`tests/sim*.test.js` 加段）**
4. **拖一只 ≠ 连续戳**（R-1 的全部意义）：造一段"按住 + 快速 + 贴上 + 越界"的手样本，断言
   `poked` 情绪事件的**次数为 0**、`startle` 未被冲击、`world.events` 里没有 `poke` 条目。
   这条是行为判据，不是 grep。
5. **拎着 A 划过 B，B 仍算被戳**：两只并排，只把 A 标成 held，断言 B 的 `poke` 上升沿照发。
6. `c.held` 只在上升沿那一次发情绪：`grabbedHappy/grabbedRough` 各断"按 enjoy 的比例缩放"，
   探针是把 `scale` 写成 1 —— 必须红。
7. 墙与碰撞：把手拖出缸外 ⇒ 位置被 `clampPos` 截住、`vel` 不越界、**没有任何需求/血量字段变化**（R-3）。
8. 松手惯性：同一份手速下断 `c.vel` 连续（不是归零），且随后一 tick 决策重新接管。
9. 存档：`held: true` 的个体存出去再读回来 ⇒ `held === false`，且序列化里不出现 `grab` 字样。
10. 确定性：同种子同手样本跑 N tick，两次跑世界投影逐字段相同（含被拎的那只）。

**接线层（`tests/hud-boot.test.js` 加段，复用现成的 `withHudTank` 假手）**
11. `pointerdown` 落在哪只 ⇒ `world.playerHand.grab.id` 就是那一只（断的是**与信息卡同一个 id**，
    这正是选 A′ 的全部理由，必须用它自己的判据钉住）。
12. 候选失效（那只死了）⇒ `grab` 归 null，且下一帧 `c.held` 全部为 false。
13. §8 第 1 条的拷贝：断 `senses.playerHand.grab` **不是** `world.playerHand.grab` 的同一对象引用
    （`assert.notEqual` 引用比较）—— 这条是唯一能钉住"按引用搬"的判据。

**守卫**
14. 常量守卫：`CONFIG.grab` 一段的节点数与顶层键数要**实测**后写进 `tests/config.test.js`
    （现为 nodes 61 / keys 53，本轮新增一行 `eventMagnitude` 与一段 `grab` ⇒ 都要按同一套遍历跑出来，不许推算），
    `Object.keys(CONFIG).sort()` 那条列表加 `'grab'`。
15. **不等式守卫**：`CONFIG.grab.pullOutRatio > CONFIG.behavior.petContactRatio`，红了就说明有人把两个
    手感旋钮调到互相重叠。

**反空判据自查**：上面每条都要先写成一个"当前实现必然红"的测试（本轮的教训：结果对不对分不出实现，
只有数它做了几次能分开 —— 第 4 条数的就是次数）。

## 10. 这一轮明确不做的事

| 项 | 为什么不做 |
|---|---|
| 拖到食物条取食 / 从 HUD 拖进缸 | 那是 DOM→canvas 的指针捕获移交，与本设计的"手抓身体"是两件事；仍留在 §10.3 划界表里 |
| 多指同时拎多只 | `input.js` 的 tracker 是单指模型，扩它是另一整块；先不做 |
| 甩脱手 / 挣脱判定 | R-3 选了"松手才释放"；加了挣脱就要重调 `k` 与手感，两个旋钮互相咬 |
| 撞伤 / 生病 / 扣需求 | 控制方明确选了"不受伤"；不新开伤害通道 |
| 新叫声（六声表加一行） | 六声表与它的参数区间守卫是独立一块，混进来会让本轮的探针范围失控 |
| 把两只拖到一起催化互动 | R-1 选的是"拎起来玩"；社交侧语义留给计划 4 |

- **§4.7 可爱的两个物理机制**（主 spec:409）：squash & stretch 的消费场景补"被拎着走时的滞后拉伸"

  "同一句话拖两只要得到两种反应"（R-2 的白话版）。

## 12. 两个必须由实测决定的旋钮（本轮不许拍脑袋填数）

| 旋钮 | 含义 | 定它的方法 |
|---|---|---|
| `CONFIG.grab.pullOutRatio` | 手移出多远算"带离身体"（摸与拎的分界） | 与 `petContactRatio 1.15` 成对试：拖两下，看"轻抚"会不会被误判成拎、"拎"会不会要拔老高 |
| `CONFIG.grab.followStiffness`（k） | 追随的紧不紧，直接决定甩出去的爽感 | 固定一段手样本跑 `heldStep`，量"手停后身体收敛用时"与"最大过冲"；临界阻尼应零过冲，量出来不是就说明积分写法错 |

这两个的**初值由实现轮实测后回填**，回填时把量到的数字写进本文件（与 D-1 那条
"量 assets → 定常数 → 写判据"的链条同形）。`enjoy` 的三个权重同理，但那是观感量，
判据只能写成单调性而不是具体数值。
