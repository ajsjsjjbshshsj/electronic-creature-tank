# 生命内核 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现电子生物的全部纯逻辑内核 —— 遗传、需求、情绪、关系记忆、性格、生命周期、繁殖与行为决策 —— 并用一个无头模拟器证明它能跑出可信的多代种群。

**Architecture:** 每个系统一个 ES module，**无状态**（状态由调用方持有的普通对象承载），**不 import DOM、不 import canvas、不 import 彼此的内部实现**。`sim.js` 是唯一知道"世界"的编排者，它把上述模块组合成一个可脱离浏览器运行的模拟。验收靠两样东西：`node --test` 的单元测试，和 `tests/simulate.mjs` 打印出的种群统计。

**Tech Stack:** 零依赖。原生 ES Modules（`package.json` 声明 `"type": "module"`）。测试用 Node 内置 `node:test` + `node:assert/strict`。Node ≥ 18（本机 `C:\nvm4w\nodejs\node.exe`）。

**Spec:** `docs/superpowers/specs/2026-10-14-electronic-creature-tank-design.md`

**后续计划：** 本计划只做纯逻辑层，不产生画面。计划 2「活着的缸」加渲染与世界，计划 3「照料与传承」加交互与存档。三份各自可独立交付。

## Global Constraints

每一条都从 spec 逐字抄来，所有 Task 的要求都隐含包含本节。

- **零依赖**：不得引入任何 npm 包，不得创建 `node_modules`。`package.json` 不得出现 `dependencies` / `devDependencies` / `peerDependencies` 任一字段；允许的键仅限 `name`、`private`、`type`、`scripts`。约束的实质是"没有任何外部代码"，而不是"字面上只能有两个键"。
- **纯逻辑模块禁止触碰 DOM / canvas / Web API**：`config.js` `rng.js` `genes.js` `needs.js` `emotions.js` `memory.js` `personality.js` `creature.js` `breeding.js` `behavior.js` `sim.js` 中不得出现 `document`、`window`、`canvas`、`requestAnimationFrame`、`AudioContext`、`fetch`、`localStorage`。这是它们能在 Node 里单测的前提。
- **不使用 `Math.random()`**：所有随机性必须经由传入的 `rng`。这保证固定种子下决策可重现（spec 8.1 的硬性测试要求）。
- **所有等位基因都是 `[0,1]` 无量纲浮点数**，混合永远在基因空间进行，不在性状空间进行（spec 4.1）。
- **情绪向量恰好六个分量**：`joy` `anger` `fear` `curiosity` `sleepy` `arousal`。`affection` **不是**情绪分量，它是 `memory` 里的关系性数值（spec 4.5 的注意事项）。
- **色相解码式固定**：`(315 + phenotype × 70) mod 360`（spec 4.1 / 4.2）。
- **需求不直接决定行为**，只为效用评分提供"紧迫度"项；最匮乏的需求不会一票否决其他行为（spec 4.4）。
- **生命周期时长（模拟秒 @1×）**：`hatchling 180` / `juvenile 300` / `adult 480` / `elder 180`。卵单独计时 `egg 60`（spec 4.11、11）。
- **种群上限**：桌面 24、手机 16。达上限时**不得硬屏蔽**，而表现为求偶评分被压低与卵不孵化（spec 4.12 第 6 条）。
- **近亲回避阈值**：`kinship > 0.25` 的两只绝不进入求偶（spec 4.12 第 5 条）。
- **记忆容量 12 条**，超出时淘汰 `familiarity` 最低的（spec 4.8）。
- **提交规范**：Conventional Commits（`feat:` / `test:` / `docs:` / `fix:` / `chore:`）。`chore:` 专用于控制方的仓库簿记（如 `.gitattributes`、`.gitignore`），实现方不得用它来提交功能代码。每个 Task 结尾必须提交。
- **测试命令**：全量 `node --test tests/`，单文件 `node --test tests/<file>.test.js`。工作目录始终是 `F:\电子宠物`。

```js
    assert.ok(v >= -5 && v < 5);
  }
});

  const r = createRng(4);
  const seen = new Set();
  for (let i = 0; i < 2000; i++) {
    const v = r.int(1, 3);
    assert.ok(Number.isInteger(v) && v >= 1 && v <= 3);
    seen.add(v);
  }
  assert.deepEqual([...seen].sort(), [1, 2, 3], '1..3 三个值都应出现');
});

test('gaussian 均值接近 0、标准差接近 1', () => {
  const r = createRng(5);
  const N = 40000;
  let sum = 0;
  let sumSq = 0;
  for (let i = 0; i < N; i++) {
    const g = r.gaussian();
    sum += g;
    sumSq += g * g;
  }
  const mean = sum / N;
  const sd = Math.sqrt(sumSq / N - mean * mean);
  assert.ok(Math.abs(mean) < 0.03, `均值偏离: ${mean}`);
  assert.ok(Math.abs(sd - 1) < 0.05, `标准差偏离: ${sd}`);

    assert.equal(r.chance(0), false);

  const arr = ['a', 'b', 'c'];

});

test('fork 产生独立且可复现的子流', () => {

  const b = createRng(42);

  const fb = b.fork();

  // 父流在 fork 之后继续消费，两个父流仍须一致

test('fork 出的子流与父流后续序列不同（真的独立）', () => {

  const child = parent.fork();
  const p = parent.next();
  const c = child.next();
  assert.notEqual(p, c);
```

- [ ] **Step 5: 写 `src/rng.js`**

```js
// mulberry32：32 位状态、无依赖、快，周期足够本项目使用。
// 全部随机性必须经由本模块，绝不在其他模块调用 Math.random()，
// 否则"固定种子下决策可重现"这条测试要求就无法成立。
export function createRng(seed) {
  let s = (seed >>> 0) || 0x9E3779B9;   // 种子 0 会让 mulberry32 退化，换成黄金比例常数

  const next = () => {
    s = (s + 0x6D2B79F5) >>> 0;
    let t = s;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };

  // Box-Muller：每两个均匀数产出一个标准正态数。
  // 缓存第二个以免浪费 —— 变异需要大量高斯采样。
  let spare = null;
  const gaussian = () => {
    if (spare !== null) {
      const v = spare;
      spare = null;
      return v;
    }
    let u = 0;
    let v = 0;
    while (u === 0) u = next();
    while (v === 0) v = next();
    const mag = Math.sqrt(-2 * Math.log(u));
    spare = mag * Math.sin(2 * Math.PI * v);
    return mag * Math.cos(2 * Math.PI * v);
  };

  return {
    next,
    gaussian,
    range: (min, max) => min + next() * (max - min),
    int: (min, max) => min + Math.floor(next() * (max - min + 1)),
    pick: (arr) => arr[Math.floor(next() * arr.length)],
    chance: (p) => next() < p,
    // 派生独立子流：让"某只生物的行为随机"与"世界的食物随机"互不干扰，
    // 同时保持整体可复现。
    fork: () => createRng((s ^ Math.imul((next() * 0xFFFFFFFF) >>> 0, 0x85EBCA6B)) >>> 0),
  };
}
```

```js
import { CONFIG } from './config.js';

export const APPEARANCE_GENES = [
  'hue', 'sat', 'lum', 'size', 'glow', 'pattern', 'patternDensity', 'wobble',
];
export const PERSONALITY_GENES = [
  'bold', 'clingy', 'irritable', 'gluttonous', 'curious', 'libido',
];
export const ALL_GENES = [...APPEARANCE_GENES, ...PERSONALITY_GENES];

export const PATTERNS = ['none', 'spots', 'rings', 'clouds', 'stars'];

// 显性度：0.5 = 共显性（表现型为两等位基因均值），>0.5 = 第一个等位基因偏显性。
// "显性"在这里是位点属性而非等位基因属性 —— 这是为了让 pattern 这类离散性状
// 能稳定地"像某一方"，而不是永远卡在两桶之间。
const DOMINANCE = {
  hue: 0.5, sat: 0.5, lum: 0.5, size: 0.5,
  glow: 0.6, pattern: 0.7, patternDensity: 0.5, wobble: 0.5,
  bold: 0.5, clingy: 0.5, irritable: 0.5,
  gluttonous: 0.5, curious: 0.5, libido: 0.5,
};

const clamp01 = (v) => (v < 0 ? 0 : v > 1 ? 1 : v);

export function phenotype(gene, alleles) {
  const dom = DOMINANCE[gene];
  if (dom === undefined) throw new Error(`未知基因: ${gene}`);
  return clamp01(alleles[0] * dom + alleles[1] * (1 - dom));
}

export function phenotypeAll(genes) {
  const out = {};
  for (const g of ALL_GENES) out[g] = phenotype(g, genes[g]);
  return out;
}

export function randomGenome(rng) {
  const genes = {};
  for (const g of ALL_GENES) genes[g] = [rng.next(), rng.next()];
  return genes;
}

// 配子形成：每个位点随机分离一个等位基因，再叠加高斯变异。
// 变异必须 clamp —— 否则多代累积后会出现越界值污染 decode，
// 表现为"某一代之后所有孩子都变成同一个极端颜色"。
export function gamete(rng, genes) {
  const g = {};
  for (const name of ALL_GENES) {
    const [a, b] = genes[name];
    const picked = rng.chance(0.5) ? a : b;
    g[name] = clamp01(picked + rng.gaussian() * CONFIG.mutationRate);
  }
  return g;
}

export function combine(gameteA, gameteB) {
  const genes = {};
  for (const name of ALL_GENES) genes[name] = [gameteA[name], gameteB[name]];
  return genes;
}

export function inherit(rng, genesA, genesB) {
  return combine(gamete(rng, genesA), gamete(rng, genesB));
}

export function patternBucket(v) {
  const i = Math.min(PATTERNS.length - 1, Math.floor(clamp01(v) * PATTERNS.length));
  return PATTERNS[i];
}

// 表现型 → 实际性状。这是唯一知道"单位"的地方，
// 其他所有模块只处理 [0,1] 的无量纲基因值。
// hue 的解码式来自 spec 4.1：(315 + p*70) mod 360，
// 其中 70 = 从 315° 跨 0° 到 25° 的弧长。
export function decode(genes) {
  const p = phenotypeAll(genes);
  const [hueStart, hueEnd] = CONFIG.hueRange;
  const span = (hueEnd - hueStart + 360) % 360;      // 315→25 = 70
  return {
    hue: (hueStart + p.hue * span) % 360,
    sat: 0.45 + p.sat * 0.5,                          // 45%–95%
    lum: 0.62 + p.lum * 0.22,                         // 62%–84%
    size: CONFIG.minSize + p.size * (CONFIG.maxSize - CONFIG.minSize),
    glow: 0.35 + p.glow * 0.65,
    pattern: patternBucket(p.pattern),
    patternDensity: p.patternDensity,
    wobble: p.wobble,
    personality: {
      bold: p.bold,
      clingy: p.clingy,
      irritable: p.irritable,
      gluttonous: p.gluttonous,
      curious: p.curious,
      libido: p.libido,
    },
  };
}
```

```js
import { CONFIG } from './config.js';

const clamp01 = (v) => (v < 0 ? 0 : v > 1 ? 1 : v);
const KEYS = ['hunger', 'energy', 'social', 'safety'];

// 初值刻意不是全 0：新孵化的幼体带一点饥饿，好让它立刻开始觅食，
// 玩家不必干等两分钟才看到第一个行为。
export function createNeeds() {
  return { hunger: 0.15, energy: 0.1, social: 0.1, safety: 0 };
}

// 所有速率都是"每秒线性变化"，因此结果与时间步长严格无关（除非触发 clamp）。
// 这是 spec 3.4 第 1 条"固定步长积分"能在需求层成立的前提。
// ctx: { moving: boolean, resting: boolean, companions: number }
export function decay(needs, dt, traits, ctx) {
  const p = traits.personality;

  // 饥饿：体型越大、越贪吃，消耗越快
  const sizeFactor = 0.7 + (traits.size / CONFIG.maxSize) * 0.6;
  const gluttonFactor = 0.7 + p.gluttonous * 0.6;
  needs.hunger = clamp01(
    needs.hunger + CONFIG.needs.hungerRate * sizeFactor * gluttonFactor * dt,
  );

  // 精力：休息时恢复；否则按是否移动分档消耗
  const energyRate = ctx.resting
    ? CONFIG.needs.energyRateRest
    : (ctx.moving ? CONFIG.needs.energyRateActive : CONFIG.needs.energyRateIdle);
  needs.energy = clamp01(needs.energy + energyRate * dt);

  // 社交：有同伴在场则大幅抑制匮乏
  const clingyFactor = 0.6 + p.clingy * 0.8;
  const relief = ctx.companions > 0 ? (1 - CONFIG.needs.socialRelief) : 1;
  needs.social = clamp01(
    needs.social + CONFIG.needs.socialRate * clingyFactor * relief * dt,
  );

  // 安全感：只随时间自然恢复；冲击走 startle()，安抚走 comfort()
  const boldFactor = 0.5 + p.bold;
  needs.safety = clamp01(needs.safety - CONFIG.needs.safetyRecover * boldFactor * dt);
}

export function feed(needs, amount = CONFIG.needs.feedAmount) {
  needs.hunger = clamp01(needs.hunger - amount);
}

export function startle(needs, amount = CONFIG.needs.startleAmount) {
  needs.safety = clamp01(needs.safety + amount);
}

export function comfort(needs, amount = CONFIG.needs.startleAmount) {
  needs.safety = clamp01(needs.safety - amount);
}

export function rest(needs, dt) {
  needs.energy = clamp01(needs.energy + CONFIG.needs.energyRateRest * dt);
}

// 返回最匮乏的一条。全零时返回 'hunger' 作为稳定默认值，
// 避免调用方拿到 undefined 然后在 switch 里静默落空。
//
// 注意（spec 4.4）：mostUrgent 只是给 behavior 的一个提示信号，
// 它不直接决定行为，也没有一票否决权。
export function mostUrgent(needs) {
  let best = 'hunger';
  let bestV = needs.hunger;
  for (const k of KEYS) {
    if (needs[k] > bestV) { bestV = needs[k]; best = k; }
  }
  return best;
}
```

```js
import { CONFIG } from './config.js';

// 恰好六个分量。affection 不在这里 —— 它是 memory 的关系性数值（spec 4.5）。
export const EMOTION_KEYS = ['joy', 'anger', 'fear', 'curiosity', 'sleepy', 'arousal'];
export const EVENT_KINDS = Object.keys(CONFIG.emotions.eventMagnitude);

const clamp01 = (v) => (v < 0 ? 0 : v > 1 ? 1 : v);

export function createEmotions() {
  const e = {};
  for (const k of EMOTION_KEYS) e[k] = 0;
  return e;
}

// 由需求与情境推导"情绪应该趋向哪里"。
// ctx: { pleasure, provocation, threat, novelty, canBreed }
//
// arousal 由 canBreed 一票门控：亚成体与老年个体不该有求偶欲。
// canBreed 的判定在 creature.canBreed（看阶段与年龄），本模块只负责"给了就能算"。
export function computeTargets(needs, ctx, traits) {
  const p = traits.personality;
  const satisfied = 1 - needs.hunger;
  return {
    joy: clamp01(satisfied * 0.35 + ctx.pleasure * 0.65),
    // 烦躁主要来自被招惹；极饿时额外叠一层"饿到发脾气"
    anger: clamp01(
      ctx.provocation * (0.55 + p.irritable * 0.45) + (needs.hunger > 0.7 ? 0.2 : 0),
    ),
    // bold 高 → 同样威胁下更不害怕
    fear: clamp01(needs.safety * 0.7 + ctx.threat * (0.5 - p.bold * 0.25)),
    curiosity: clamp01(ctx.novelty * 0.6 + p.curious * 0.4),
    sleepy: clamp01(needs.energy),
    arousal: ctx.canBreed
      ? clamp01(satisfied * 0.45 + (1 - needs.energy) * 0.3 + p.libido * 0.25)
      : 0,
  };
}

// 一阶指数趋近：e += (target - e) * min(1, inertia * dt)
//
// min(1, ...) 是关键：没有它，dt 过大时步长系数会超过 1，
// 情绪会在目标值两侧来回振荡而不是收敛。这也让"大 dt 一次算完"
// 与"小 dt 分多步算"给出同样的稳定结果。
export function update(emotions, targets, dt) {
  const k = Math.min(1, CONFIG.emotions.inertia * dt);
  for (const key of EMOTION_KEYS) {
    emotions[key] = clamp01(emotions[key] + (targets[key] - emotions[key]) * k);
  }
}

// 事件冲击：立即生效，绕过惯性。
// 这才有"被戳一下瞬间炸毛"的手感；若走惯性，冲击会被平滑得毫无反应。
export function applyEvent(emotions, kind, scale = 1) {
  const deltas = CONFIG.emotions.eventMagnitude[kind];
  if (!deltas) throw new Error(`未知情绪事件: ${kind}`);
  for (const [key, delta] of Object.entries(deltas)) {
    emotions[key] = clamp01(emotions[key] + delta * scale);
  }
}

export function dominant(emotions) {
  let best = null;
  let bestV = 0;
  for (const k of EMOTION_KEYS) {
    if (emotions[k] > bestV) { bestV = emotions[k]; best = k; }
  }
  return best;
}

// 次要情绪只有在"够强"时才算存在，否则表现层会泄漏出一个实际上
// 并不成立的情绪（joy 0.8 + fear 0.05 不该看起来又开心又害怕）。
// 阈值取主导值的一半 —— 这是"害怕地缩着却还是往前探了一点"能成立的边界。
export function secondary(emotions) {
  const first = dominant(emotions);
  if (first === null) return null;
  const firstV = emotions[first];
  let best = null;
  let bestV = 0;
  for (const k of EMOTION_KEYS) {
    if (k !== first && emotions[k] > bestV) { bestV = emotions[k]; best = k; }
  }
  return bestV >= firstV * 0.5 ? best : null;
}
```

```js
import { CONFIG } from './config.js';

export const PLAYER_ID = 'PLAYER';
export const ROLES = ['mother', 'father', 'sibling', 'mate', 'offspring'];

// 亲缘系数用于近亲回避（spec 4.12 第 5 条）。
// mate 为 0 —— 配偶没有血缘关系，不能因为"它是我伴侣"就误判为近亲而拒绝交配。
export const KINSHIP = {
  mother: 0.5, father: 0.5, sibling: 0.5, offspring: 0.5,
  grandparent: 0.25, grandchild: 0.25, halfSibling: 0.25,
  mate: 0,
};

const clamp = (v, lo, hi) => (v < lo ? lo : v > hi ? hi : v);

export function createMemory() {
  return { entries: [] };
}

export function get(memory, id) {
  for (const e of memory.entries) if (e.id === id) return e;
  return null;
}

// 幂等：已存在则返回原记录，且不用 opts 覆盖已有的 kinship / role。
// 覆盖会毁掉"它是它妈妈"这类一旦确立就不该再变的关系。
export function ensure(memory, id, opts) {
  const existing = get(memory, id);
  if (existing) return existing;
  const entry = {
    id,
    familiarity: 0,
    affection: 0,
    kinship: opts && opts.kinship !== undefined ? opts.kinship : 0,
    role: opts && opts.role !== undefined ? opts.role : null,
  };
  memory.entries.push(entry);
  // 保护刚建立的这条：新记录的 familiarity 是 0，
  // 若不保护，记忆满时"第一次见面"会被自己挤掉 —— 它将永远记不住任何新个体。
  prune(memory, id);
  return entry;
}

export function adjust(memory, id, dAffection, dFamiliarity = 0.05) {
  const e = ensure(memory, id);
  e.affection = clamp(e.affection + dAffection, -1, 1);
  e.familiarity = clamp(e.familiarity + dFamiliarity, 0, 1);
  return e;
}

export function affectionFor(memory, id) {
  const e = get(memory, id);
  return e ? e.affection : 0;
}

export function familiarityFor(memory, id) {
  const e = get(memory, id);
  return e ? e.familiarity : 0;
}

export function kinshipBetween(memory, id) {
  const e = get(memory, id);
  return e ? e.kinship : 0;
}

// 指数衰减：affection *= exp(-rate * dt)
//
// 用 exp 而非 (1 - rate*dt)，才能做到与时间步长严格无关 ——
// 这是"手机 120Hz 与电脑 60Hz 下恩怨淡化速度一致"的数学保证，
// 也是共享存档在两台设备间不会漂移的前提。
// 乘法衰减还天然保持符号：好感不会从正翻负。
// 亲属与伴侣用慢得多的速率（近乎不忘），见 spec 4.8。
export function decay(memory, dt) {
  for (const e of memory.entries) {
    const isKin = e.role !== null || e.kinship >= 0.25;
    const affRate = isKin ? CONFIG.affectionDecayKin : CONFIG.affectionDecay;
    e.affection *= Math.exp(-affRate * dt);
    e.familiarity *= Math.exp(-CONFIG.familiarityDecay * dt);
  }
}

// 超出容量时淘汰 familiarity 最低的。
// "遗忘"本身就是真实的：多代之后不可能记住每一只先祖。
// 这同时也是内存上界 —— 种群再大，每只的记忆开销恒定。
//
// protectId：本次淘汰中豁免的条目。ensure() 传入新建条目的 id，
// 否则新记录（familiarity 0）会在被记住之前就立刻被淘汰掉。
export function prune(memory, protectId) {
  if (memory.entries.length <= CONFIG.memoryCapacity) return;
  const protectedEntry = protectId === undefined ? null : get(memory, protectId);
  if (protectedEntry) {
    // 精确移除"未被豁免的条目里 familiarity 最低的那条"。
    // 不做整体排序截断 —— 那会把刚建立的记录一起排到末尾再切掉。
    let victim = null;
    for (const e of memory.entries) {
      if (e === protectedEntry) continue;
      if (victim === null || e.familiarity < victim.familiarity) victim = e;
    }
    if (victim) {
      memory.entries.splice(memory.entries.indexOf(victim), 1);
      return;
    }
  }
  // 无豁免（或全部都是被豁免的）时，按 familiarity 降序保留前 N 条。
  // entries 的顺序不承载语义 —— get() 是线性扫描，这里排序只为截断。
  memory.entries.sort((a, b) => b.familiarity - a.familiarity);
  memory.entries.length = CONFIG.memoryCapacity;
}

// 存档恢复用：直接写入一条完整记录，同 id 覆盖。
// 必须拷贝（{...entry}）而不是持有引用，否则存档对象与运行时状态
// 会共享同一个对象，序列化时机不同就会写出不一致的数据。
export function remember(memory, entry) {
  const existing = get(memory, entry.id);
  if (existing) {
    existing.familiarity = entry.familiarity;
    existing.affection = entry.affection;
    existing.kinship = entry.kinship;
    existing.role = entry.role;
    return;
  }
  memory.entries.push({ ...entry });
  prune(memory);
}
```

```js
// 性格基因 → 阈值与权重的纯映射（spec 4.9）。
//
// 设计要点：性格不指定行为，只调阈值与权重。
// 本模块是纯函数、无状态、不依赖随机源 —— 同一份性格永远给出同一组阈值，
// 这是"固定种子下决策可复现"（spec 8.1）能成立的前提。
//
// 每个方向的注释都写明了"高 → 效果"，改数值时照着注释检查方向，
// 方向搞反是本模块最容易犯且最难发现的错误。
export function thresholds(p) {
  const bold = p.bold;
  const clingy = p.clingy;
  const irritable = p.irritable;
  const gluttonous = p.gluttonous;
  const curious = p.curious;
  const libido = p.libido;

  return {
    // bold 高 → 需要更大的威胁才害怕（阈值高）
    fearThreshold: 0.3 + bold * 0.5,

    // irritable 高 → 一点火星就炸（阈值低）
    angerThreshold: 0.65 - irritable * 0.45,

    // irritable 高 → 气得更久（秒）
    angerDuration: 4 + irritable * 12,

    // gluttonous 高 → 还没真饿就去觅食（触发阈值低）
    hungerTrigger: 0.55 - gluttonous * 0.3,

    // clingy 高 → 稍感孤单就去找同伴（触发阈值低）
    socialTrigger: 0.5 - clingy * 0.28,

    // curious 高 → 探索半径大（归一化世界单位）
    exploreRadius: 0.25 + curious * 0.6,

    // libido 高 → 求偶欲上升快
    arousalRate: 0.5 + libido * 1.0,

    // 卖萌倾向：黏人与胆大都推高，暴躁压低。
    // 允许为负 —— 负值意味着它会主动避开玩家的手。
    playerApproach: clingy * 0.5 + bold * 0.3 - irritable * 0.35,

    // bold 高 → 转身果断（rad/s）。胆小的迟疑，这本身就是身体语言。
    turnRate: 2 + bold * 4,

    // libido 高 → 更容易接受求偶（作为求偶评分的乘子）
    courtshipWillingness: 0.6 + libido * 0.8,
  };
}
```

```js
import { CONFIG } from './config.js';
import { randomGenome, decode } from './genes.js';
import { createNeeds } from './needs.js';
import { createEmotions } from './emotions.js';
import { createMemory } from './memory.js';
import { thresholds } from './personality.js';

// 不含 'egg' —— 卵是独立实体（见 breeding.js），
// 因为它没有需求、情绪、记忆，硬塞进 Creature 会让所有模块都要判空。
export const STAGES = ['hatchling', 'juvenile', 'adult', 'elder', 'dead'];

// 阶段边界在模块加载时算一次，避免每帧重复加法。
// 顺序必须与 STAGES 前四项一致。
const BOUNDARIES = [
  CONFIG.stage.hatchling,
  CONFIG.stage.hatchling + CONFIG.stage.juvenile,
  CONFIG.stage.hatchling + CONFIG.stage.juvenile + CONFIG.stage.adult,
  CONFIG.stage.hatchling + CONFIG.stage.juvenile + CONFIG.stage.adult + CONFIG.stage.elder,
];

export function createCreature(opts) {
  // rng 是必需参数。这条抛错是有意的：Global Constraints 禁止 Math.random()，
  // 让缺参数的调用立刻炸掉，比让它静默退化成一个不可复现的随机源好得多。
  // 只有"完全从既有基因组重建"（读档）时才允许不传 —— 那种情况必须传 genes。
  if (!opts.rng && !opts.genes) {
    throw new Error('createCreature 需要 rng 参数（或既有 genes）；禁止使用 Math.random');
  }
  const genes = opts.genes || randomGenome(opts.rng);
  const traits = decode(genes);
  return {
    id: opts.id,
    name: opts.name,
    customName: opts.customName || false,
    generation: opts.generation || 1,

    genes,
    traits,
    thresholds: thresholds(traits.personality),

    age: opts.age || 0,
    stage: opts.stage || stageForAge(opts.age || 0),
    alive: true,
    sick: false,
    dying: 0,          // >0 表示已进入死亡动画；表现层据此播放溶散

    pos: { x: opts.x, y: opts.y },
    vel: { x: 0, y: 0 },
    facing: { x: 1, y: 0 },   // 单位向量；静止时保持上一次朝向（spec 4.6）

    needs: createNeeds(),
    emotions: createEmotions(),
    memory: createMemory(),

    intent: null,
    intentTime: 0,
    resting: false,
    moving: false,

    courtship: null,   // null | { partnerId, t, duration, phase }
    mourn: 0,          // 哀悼剩余秒数（spec 4.11）

    lineage: {
      mother: opts.mother || null,
      father: opts.father || null,
      mates: [],
      offspring: [],
    },
  };
}

export function stageForAge(age) {
  if (age < BOUNDARIES[0]) return 'hatchling';
  if (age < BOUNDARIES[1]) return 'juvenile';
  if (age < BOUNDARIES[2]) return 'adult';
  if (age < BOUNDARIES[3]) return 'elder';
  return 'dead';
}

// 年龄推进。死亡只触发一次：靠 alive 门控，
// 保证 dying 不会被后续 tick 重置，表现层的溶散动画才能完整播完。
export function ageCreature(c, dt) {
  if (!c.alive) return;
  c.age += dt;
  const next = stageForAge(c.age);
  if (next === 'dead') {
    c.alive = false;
    c.stage = 'elder';        // 阶段标签停在 elder，死亡由 alive/dying 表达
    c.dying = 1e-6;           // 非零哨兵值，表示"动画已开始"
    return;
  }
  if (next !== c.stage) c.stage = next;
}

// 连续生长（spec 4.11）：体型随年龄平滑插值，阶段只是能力门槛。
// 分段线性而非阶跃 —— 这样你看到的是"一天天长大"，不是某天突然变形。
// 老年段略微回缩（×0.88 下限），配合光转暗转暖，是衰老的可见信号。
export function growthFactor(c) {
  const age = c.age;
  const h = BOUNDARIES[0];
  const j = BOUNDARIES[1];
  const a = BOUNDARIES[2];
  const e = BOUNDARIES[3];

  if (age < h) return 0.22 + 0.28 * (age / h);                       // 0.22 → 0.50
  if (age < j) return 0.5 + 0.35 * ((age - h) / (j - h));            // 0.50 → 0.85
  if (age < a) return 0.85 + 0.15 * ((age - j) / (a - j));           // 0.85 → 1.00
  return 1 - 0.12 * Math.min(1, (age - a) / (e - a));                // 1.00 → 0.88
}

export function sizeOf(c) {
  return c.traits.size * growthFactor(c);
}

// 只有成体能繁殖。老年不再繁殖（spec 4.11）。
// sick 个体也排除 —— 它是 tick 抛异常后的隔离标记（spec 7.7），
// 隔离期间继续繁殖会把问题扩散到下一代。
export function canBreed(c) {
  return c.alive && !c.sick && c.stage === 'adult';
}

// 成体与老年都算"成年" —— 用于社交判定、哀悼触发、以及幼体的"认妈妈"。
export function isAdultLike(c) {
  return c.stage === 'adult' || c.stage === 'elder';
}
```

> **实现注意**：`createCreature` 对 `rng` 的抛错是有意的设计，不要"顺手兼容一下"改成回退到 `Math.random()`。Global Constraints 明令禁止 `Math.random()`；一旦这里允许静默回退，"固定种子下世界完全可复现"这条性质就会在某个没人注意的分支上失效，而且失效方式是**偶发的、跨设备不一致的**，几乎无法追查。
>
> 唯一合法的无 `rng` 路径是读档重建 —— 那时必然带着完整的 `genes`，不需要任何随机性。上面的实现正是按这个语义写的。

```js
import { CONFIG } from './config.js';
import { inherit } from './genes.js';
import { canBreed, createCreature } from './creature.js';
import { KINSHIP, affectionFor, ensure, kinshipBetween } from './memory.js';

// 卵的 id 计数器。模块级状态是这里唯一的例外 ——
// 它只用于生成唯一 id，不参与任何模拟决策，因此不影响可复现性。
let eggSeq = 0;

const clamp01 = (v) => (v < 0 ? 0 : v > 1 ? 1 : v);
const dist = (p, q) => Math.hypot(p.x - q.x, p.y - q.y);

// 求偶的前置门槛。全部是硬性事实（阶段、血缘、距离、状态），
// 不含任何"意愿"判断 —— 意愿由 courtshipScore 的连续评分表达。
export function canCourt(a, b, opts) {
  if (a === b || a.id === b.id) return false;
  if (!canBreed(a) || !canBreed(b)) return false;
  if (a.courtship || b.courtship) return false;

  // 近亲回避（spec 4.12 第 5 条）：双向检查，只要一方记得亲缘就拒绝。
  // 用 > 而非 >= —— kinship 恰好 0.25（半同胞/祖孙）属于允许的边缘，
  // 严格超过才拒绝。
  const kinA = kinshipBetween(a.memory, b.id);
  const kinB = kinshipBetween(b.memory, a.id);
  if (kinA > CONFIG.kinshipMateMax || kinB > CONFIG.kinshipMateMax) return false;

  if (opts.distance > CONFIG.courtshipRange) return false;

  // 意愿门槛：arousal 足够、不太饿、不太害怕
  const minArousal = 0.35;
  const maxHunger = 0.75;
  const maxFear = 0.5;
  if (a.emotions.arousal < minArousal || b.emotions.arousal < minArousal) return false;
  if (a.needs.hunger > maxHunger || b.needs.hunger > maxHunger) return false;
  if (a.emotions.fear > maxFear || b.emotions.fear > maxFear) return false;

  return true;
}

// 求偶的效用分，供 behavior.js 作为一个候选行为参与竞争。
//
// 种群上限在这里体现为"评分被压低"，而不是返回 false（spec 4.12 第 6 条）。
// 区别很重要：压低意味着它们仍会偶尔尝试、然后彼此失去兴趣 —— 这是行为；
// 归零意味着代码禁止了一件本该由世界规则解释的事 —— 那是穿帮。
//
// 渐变而非断崖：从 70% 容量开始线性衰减，到满容量时降到约 12%。
export function courtshipScore(a, b, opts) {
  if (!canCourt(a, b, opts)) return 0;

  const loadRatio = opts.populationCap > 0 ? opts.population / opts.populationCap : 0;
  const crowding = loadRatio < 0.7
    ? 1
    : 1 - ((loadRatio - 0.7) / 0.3) * 0.88;      // 0.7→1.0 时从 1 降到 0.12

  const affection = (affectionFor(a.memory, b.id) + affectionFor(b.memory, a.id)) / 2;
  const willingness = (a.thresholds.courtshipWillingness + b.thresholds.courtshipWillingness) / 2;
  const arousal = (a.emotions.arousal + b.emotions.arousal) / 2;
  // 距离越近越容易开始；归一化到 [0,1]
  const proximity = 1 - opts.distance / CONFIG.courtshipRange;

  return Math.max(0, crowding * willingness * (0.4 + arousal) * (0.6 + proximity) * (1 + affection));
}

// 仪式时长必须双方一致 —— 否则一方先结束会导致另一方卡在求偶状态。
export function startCourtship(a, b, rng) {
  const duration = rng.range(CONFIG.courtship.min, CONFIG.courtship.max);
  a.courtship = { partnerId: b.id, t: 0, duration, phase: 0 };
  b.courtship = { partnerId: a.id, t: 0, duration, phase: 0 };
}

// 推进仪式。返回 'complete' 时清空 courtship，
// 保证同一场仪式不会被完成两次（否则会产两窝卵）。
//
// phase 把仪式切成四段（spec 4.12 第 2 条），供表现层编舞：
//   0 绕圈（速度逐渐同步）  1 体色脉动同步  2 前端轻触  3 膨胀展示
export function tickCourtship(c, dt) {
  const court = c.courtship;
  if (!court) return 'ongoing';
  court.t += dt;
  const progress = Math.min(1, court.t / court.duration);
  court.phase = progress < 0.35 ? 0 : progress < 0.6 ? 1 : progress < 0.85 ? 2 : 3;
  if (court.t >= court.duration) {
    c.courtship = null;
    return 'complete';
  }
  return 'ongoing';
}

export function interruptCourtship(c) {
  c.courtship = null;
}

// 产卵。位置落在缸底附近（y 大 = 靠近底部，与世界坐标 y 向下增长一致），
// 母体若在中上层，卵也会沉到缸底 —— 这符合"沉性卵"的直觉。
export function layEggs(mother, father, rng, opts) {
  const count = rng.int(CONFIG.eggsPerClutch[0], CONFIG.eggsPerClutch[1]);
  const eggs = [];
  for (let i = 0; i < count; i++) {
    eggSeq += 1;
    eggs.push({
      id: `e${eggSeq}`,
      // 每枚卵独立走一次分离+重组+变异，所以同窝各不相同
      genes: inherit(rng, mother.genes, father.genes),
      age: 0,
      pos: {
        x: clamp01(mother.pos.x + rng.range(-0.04, 0.04)),
        y: clamp01(rng.range(0.78, 0.97)),
      },
      motherId: mother.id,
      fatherId: father.id,
      // 不可孵化不是"不产卵"，而是"产了但光会慢慢熄灭"（spec 4.12 第 6 条）
      viable: !opts.atPopulationCap,
    });
  }

  // 双亲互记为 mate。用 includes 去重，否则反复产卵会把 mates 塞满同一个 id。
  if (!mother.lineage.mates.includes(father.id)) mother.lineage.mates.push(father.id);
  if (!father.lineage.mates.includes(mother.id)) father.lineage.mates.push(mother.id);

  return eggs;
}

export function tickEgg(egg, dt) {
  egg.age += dt;
  if (!egg.viable) return 'failed';
  return egg.age >= CONFIG.stage.egg ? 'ready' : 'incubating';
}

// 孵化。基因组直接取自卵，不再二次变异 ——
// 变异已经在配子形成时发生过了，再加一次会让遗传学模型失真。
export function hatch(egg, rng, opts) {
  const baby = createCreature({
    id: `c-${egg.id}`,
    name: opts.nameFor(egg.genes, 0),
    x: clamp01(egg.pos.x + rng.range(-0.01, 0.01)),
    y: clamp01(egg.pos.y + rng.range(-0.01, 0.01)),
    age: 0,
    stage: 'hatchling',
    genes: egg.genes,
    generation: opts.generation,
    mother: egg.motherId,
    father: egg.fatherId,
    rng,
  });

  // 孩子认得父母（spec 4.11：幼体"认妈妈"）。
  // 父母侧的记忆由 sim.js 写回 —— 本模块不持有世界，拿不到父母对象。
  if (egg.motherId) ensure(baby.memory, egg.motherId, { kinship: KINSHIP.mother, role: 'mother' });
  if (egg.fatherId) ensure(baby.memory, egg.fatherId, { kinship: KINSHIP.father, role: 'father' });

  return baby;
}
```

### Task 9: 行为决策 —— 效用评分

**Files:**

- Test: `tests/behavior.test.js`

**Interfaces:**
- Consumes: `CONFIG.behavior`、`Creature`、`Thresholds`、`Emotions`、`Needs`、`affectionFor`（`memory.js`）、`PLAYER_ID`
- Produces:
  - `INTENTS: string[]` = `['forage','eat','rest','socialize','court','explore','flee','beg','protest','fight','mourn','idle']`
  - `Senses` 结构（见下）
  - `decide(c: Creature, senses: Senses, rng: Rng) => Intent`
  - `scoreAll(c: Creature, senses: Senses) => Record<string, number>` — 导出仅供测试与调试；`decide` 内部使用它

**`Senses` 结构**（由 `sim.js` 的 `perceive()` 构造，`behavior` 只读不写）：

```js
{
  foods: [{ id, kind, pos: Vec2, dist }],                     // 已按 dist 升序
  neighbors: [{ id, pos, dist, size, stage, alive, anger }],   // 感知半径内，已按 dist 升序
  threats: [{ id, pos, dist }],                                // 明显更大且愤怒的邻居，已按 dist 升序
  playerHand: { pos: Vec2, dist, speed } | null,               // speed 高 = 戳，低 = 抚摸
  courtshipOptions: [{ id, dist, score }],                     // 由 sim 用 courtshipScore 预算好
  provokerId: string | null,                                   // 最近那个也在生气、且贴得很近的邻居
  population: number,
  populationCap: number,
  atPopulationCap: boolean,
}
```

`behavior` 只读这些字段，一个都不写。`provokerId` 由 `perceive` 算好后直接给出，`behavior` 不需要自己再从 `neighbors` 里筛 —— 筛选标准（`anger > 0.5 && dist < 0.08`）只在一个地方定义。

> **为什么 `courtshipOptions` 的分数由 `sim` 预算**：让 `behavior` 自己去算就需要它拿到对方的完整 `Creature` 对象，从而 import `breeding`，形成 `behavior → breeding → creature` 的耦合链。预算好的分数让 `behavior` 保持纯粹的"读数字、出决策"，也让"种群上限压低求偶分"这条规则只有一个实现点。

```js
import { CONFIG } from './config.js';
import { affectionFor, familiarityFor, PLAYER_ID } from './memory.js';

export const INTENTS = [
  'forage', 'eat', 'rest', 'socialize', 'court', 'explore',
  'flee', 'beg', 'protest', 'fight', 'mourn', 'idle',
];

const clamp01 = (v) => (v < 0 ? 0 : v > 1 ? 1 : v);
const clampPos = (v) => (v < 0.02 ? 0.02 : v > 0.98 ? 0.98 : v);

// 每个候选的最小持续时间（秒）。
//
// 全部从 CONFIG.behavior.minIntentDuration 派生，而不是写死绝对秒数 ——
// 否则那个配置项就成了没人读的死配置，调它的时候行为不会有任何变化，
// 而这正是"改了配置却没生效"这类最难查的问题。
//
// 相对倍率的含义：
//   flee  0.4× —— 刻意最短。逃命时必须能随时改向，被锁定 1.2 秒会一头撞墙。
//   court 3.3× —— 刻意最长。求偶仪式本来就不该被一点风吹草动打断。
//   fight 0.85× —— 略短于基准：打斗是短促的爆发，不该拖成僵持。
const M = CONFIG.behavior.minIntentDuration;
const MIN_DURATION = {
  forage: M * 1.25, eat: M, rest: M * 2.5, socialize: M * 1.7,
  court: M * 3.3, explore: M * 1.7, flee: M * 0.4, beg: M * 1.25,
  protest: M, fight: M * 0.85, mourn: M * 1.7, idle: M * 1.25,
};

// 效用评分（spec 4.10）。
//
// 四项相乘而非相加，是有意的：任何一项为 0 都会让整个候选归零。
// 这实现了"情境可行性"的硬约束（没有食物就不能 eat、没有邻居就不能 socialize），
// 而不需要为每个候选写一堆 if。相加则会让"完全不可行但需求很强"的候选胜出。
//
// 返回的分数全部 >= 0，调用方可以直接比较。
export function scoreAll(c, senses) {
  const t = c.thresholds;
  const n = c.needs;
  const e = c.emotions;

  const nearestFood = senses.foods.length ? senses.foods[0] : null;
  const nearestNeighbor = senses.neighbors.length ? senses.neighbors[0] : null;
  const nearestThreat = senses.threats.length ? senses.threats[0] : null;
  const hand = senses.playerHand;
  const bestSuitor = senses.courtshipOptions.length
    ? senses.courtshipOptions.reduce((a, b) => (b.score > a.score ? b : a))
    : null;

  // provoker：最近那个也在生气的邻居，或 senses 显式指出的肇事者
  const provokerId = senses.provokerId || null;
  const provoker = provokerId
    ? senses.neighbors.find((x) => x.id === provokerId) || null
    : null;

  const playerAffection = affectionFor(c.memory, PLAYER_ID);
  const playerFamiliarity = familiarityFor(c.memory, PLAYER_ID);
  // 手移动得快 = 戳，慢 = 抚摸（spec 6.1 的核心区分）
  const handIsRough = hand ? hand.speed > 0.25 : false;

  const scores = {
    // 觅食：饥饿超过性格阈值才启动；贪吃者阈值低，会更早动身
    forage: n.hunger > t.hungerTrigger && nearestFood
      ? n.hunger * CONFIG.behavior.seekFoodUrgency * (1 + e.curiosity * 0.2)
      : 0,

    // 进食：已经贴着食物了才有意义。由 forage 抵达后自然触发。
    eat: nearestFood && nearestFood.dist < 0.035 && n.hunger > 0.05
      ? n.hunger * 2.5
      : 0,

    rest: n.energy > 0.55 ? n.energy * 1.4 * (1 - e.fear * 0.8) : 0,

    socialize: n.social > t.socialTrigger && nearestNeighbor
      ? n.social * 1.3 * (1 + t.playerApproach * 0.15)
      : 0,

    // 求偶：分数直接来自 sim 预算好的 courtshipScore，
    // 因此"种群上限压低求偶"与"近亲归零"自动传导到这里。
    court: bestSuitor && bestSuitor.score > 0
      ? bestSuitor.score * e.arousal * 1.6
      : 0,

    // 探索：好奇驱动，且在没有更紧迫的事时才有分量
    explore: e.curiosity * (0.4 + t.exploreRadius) * (1.2 - Math.max(n.hunger, n.energy)),

    // 逃避：权重最高（spec 4.10 的 fleeUrgency），但没有威胁时为 0。
    // 玩家的手粗暴地戳过来也算威胁。
    flee: Math.max(
      nearestThreat ? e.fear * CONFIG.behavior.fleeUrgency * (1 + (0.2 - nearestThreat.dist)) : 0,
      hand && handIsRough && playerAffection < 0.2 && t.playerApproach < 0.2
        ? e.fear * CONFIG.behavior.fleeUrgency
        : 0,
    ),

    // 卖萌：由"对玩家的好感 + 熟悉度 + 性格倾向 + 手在附近且动作温柔"共同触发。
    //
    // familiarity 单独也能开门（但阈值更高、权重更低），这是必需的正确性条件，
    // 不是可选的润色：内核里 affection 只有 beg 自己会累积，若只认 affection，
    // 就会死锁成"它因为不认识你所以不撒娇，因为不撒娇所以永远不认识你"，
    // 卖萌这个 spec 明确要求的表情将永远不会出现。
    //
    // 但"喜欢"仍然必须由抚摸买来（计划 3 的 input 层）—— 光是把手放在那儿
    // 只能买到"认识"，否则卖萌就退化成一个挂机计时器。
    //
    // 好感为负时归零 —— 它躲你，不会讨好你。
    beg: hand && !handIsRough && playerAffection >= 0
      && (playerAffection > 0.1 || playerFamiliarity > 0.3)
      ? (0.2 + playerAffection + playerFamiliarity * 0.4)
        * Math.max(0, t.playerApproach) * CONFIG.behavior.begUrgency
        * (0.5 + e.joy * 0.5)
      : 0,

    // 抗议：生气但不敢/不想真打。愤怒超过性格阈值才启动。
    protest: e.anger > t.angerThreshold && provoker
      ? e.anger * 1.2 * (1 - e.fear)
      : 0,

    // 争斗：只有打得过才打。体型差是硬门槛，
    // 否则会出现"幼体去撞成体"这种既不可信也不可爱的画面。
    fight: e.anger > t.angerThreshold + 0.15 && provoker && e.fear < 0.35
      && provoker.size <= c.traits.size * 1.25
      ? e.anger * CONFIG.behavior.fightUrgency * (1 + t.playerApproach * -0.2)
      : 0,

    // 哀悼：mourn 计时器 > 0 时有效。它压过日常行为但压不过逃命。
    mourn: c.mourn > 0 ? 1.8 * Math.min(1, c.mourn) : 0,

    // 兜底：什么都不做。基础分很低，只在其他候选都归零时胜出。
    idle: 0.12,
  };

  return scores;
}

// 选出最高分候选，并附上目标信息。
//
// 随机扰动（noiseScale）加在乘法之后：它让势均力敌的候选之间产生分歧，
// 避免生物每次都做"最优"选择而显得机械；但幅度很小，
// 压倒性的需求（饿到 0.99）不会被翻盘。
export function decide(c, senses, rng) {
  const scores = scoreAll(c, senses);

  let bestKind = 'idle';
  let bestScore = -Infinity;
  for (const kind of INTENTS) {
    const noisy = scores[kind] * (1 + rng.range(-1, 1) * CONFIG.behavior.noiseScale);
    if (noisy > bestScore) { bestScore = noisy; bestKind = kind; }
  }

  const nearestFood = senses.foods.length ? senses.foods[0] : null;
  const nearestNeighbor = senses.neighbors.length ? senses.neighbors[0] : null;
  const bestSuitor = senses.courtshipOptions.length
    ? senses.courtshipOptions.reduce((a, b) => (b.score > a.score ? b : a))
    : null;

  const intent = { kind: bestKind, minDuration: MIN_DURATION[bestKind] };

  switch (bestKind) {
    case 'forage':
    case 'eat':
      intent.targetId = nearestFood.id;
      intent.targetPos = { x: nearestFood.pos.x, y: nearestFood.pos.y };
      break;
    case 'socialize':
      intent.targetId = nearestNeighbor.id;
      intent.targetPos = { x: nearestNeighbor.pos.x, y: nearestNeighbor.pos.y };
      break;
    case 'court':
      intent.targetId = bestSuitor.id;
      break;
    case 'beg':
      intent.targetPos = { x: senses.playerHand.pos.x, y: senses.playerHand.pos.y };
      break;
    case 'protest':
    case 'fight': {
      const provoker = senses.neighbors.find((x) => x.id === senses.provokerId);
      if (provoker) {
        intent.targetId = provoker.id;
        intent.targetPos = { x: provoker.pos.x, y: provoker.pos.y };
      }
      break;
    }
    case 'flee': {
      // 逃向威胁的反方向；缸壁附近时贴着壁走，避免"逃到墙角卡住"
      const threat = senses.threats[0]
        || (senses.playerHand ? { pos: senses.playerHand.pos } : null);
      if (threat) {
        let dx = c.pos.x - threat.pos.x;
        let dy = c.pos.y - threat.pos.y;
        const len = Math.hypot(dx, dy) || 1;
        dx /= len;
        dy /= len;
        // 靠近边界时把逃离方向掰向缸中心，否则会一直顶着壁
        const cx = c.pos.x < 0.2 || c.pos.x > 0.8 ? (0.5 - c.pos.x) * 0.6 : 0;
        const cy = c.pos.y < 0.2 || c.pos.y > 0.8 ? (0.5 - c.pos.y) * 0.6 : 0;
        intent.targetPos = {
          x: clampPos(c.pos.x + dx * 0.25 + cx),
          y: clampPos(c.pos.y + dy * 0.25 + cy),
        };
      } else {
        intent.targetPos = { x: clampPos(0.5), y: clampPos(0.5) };
      }
      break;
    }
    case 'explore':
      // 在探索半径内随机挑一个点。半径由 curious 基因决定，
      // 所以胆大好奇的孩子会跑得更远 —— 这是可见的性格差异。
      intent.targetPos = {
        x: clampPos(c.pos.x + rng.range(-1, 1) * c.thresholds.exploreRadius),
        y: clampPos(c.pos.y + rng.range(-1, 1) * c.thresholds.exploreRadius),
      };
      break;
    case 'mourn':
    case 'rest':
    case 'idle':
    default:
      break;
  }

  return intent;
}
```

> **实现注意**：`scoreAll` 与 `decide` 都**不得修改 `c`**。`decide` 只返回 Intent，由 `sim.js` 负责写入 `c.intent` 与执行移动。这条边界让 `behavior` 保持纯函数，是它能被单测的原因。测试 `scoreAll 是纯函数` 就是守这条线的。

```js
      stage: 'juvenile',
      generation: 1,
      genes,
      rng,
    }));
  }

  return world;
}

// 默认命名：粉色系叠词 + 序号。计划 3 会用 names.js 替换它，

}

// ---------------------------------------------------------------- 空间网格

// 均匀网格把感知与碰撞从 O(n²) 降到接近 O(n)（spec 3.4 第 4 条）。
// 每 tick 重建一次：24 只个体的重建成本远低于维护增量更新的复杂度，
// 而且不会有"忘记更新网格"导致的幽灵邻居 bug。
const CELL = CONFIG.gridCell;

function cellKey(cx, cy) {
  return cx + ',' + cy;
}

function rebuildGrid(world) {
  world.grid.clear();
  for (let i = 0; i < world.creatures.length; i++) {
    const c = world.creatures[i];
    if (!c.alive) continue;
    const key = cellKey(Math.floor(c.pos.x / CELL), Math.floor(c.pos.y / CELL));
    let bucket = world.grid.get(key);
    if (!bucket) { bucket = []; world.grid.set(key, bucket); }
    bucket.push(i);
  }
}

// 查询以 c 为中心、半径 r 内的所有个体下标。
// 扫描覆盖该圆的所有格子，因此不可能漏掉跨格子的近邻。
function queryGrid(world, x, y, r) {
  const out = [];
  const minCx = Math.floor((x - r) / CELL);
  const maxCx = Math.floor((x + r) / CELL);
  const minCy = Math.floor((y - r) / CELL);
  const maxCy = Math.floor((y + r) / CELL);
  for (let cx = minCx; cx <= maxCx; cx++) {
    for (let cy = minCy; cy <= maxCy; cy++) {
      const bucket = world.grid.get(cellKey(cx, cy));
      if (bucket) for (const i of bucket) out.push(i);
    }
  }
  return out;
}

// ---------------------------------------------------------------- 感知

export function perceive(world, c) {
  const R = CONFIG.perceiveRadius;
  const neighbors = [];
  const threats = [];

  for (const i of queryGrid(world, c.pos.x, c.pos.y, R)) {
    const o = world.creatures[i];
    if (o === c || !o.alive) continue;
    const d = Math.hypot(o.pos.x - c.pos.x, o.pos.y - c.pos.y);
    if (d > R) continue;
    neighbors.push({
      id: o.id, pos: o.pos, dist: d,
      size: sizeOf(o), stage: o.stage, alive: o.alive,
      anger: o.emotions.anger,
    });
    // 威胁：明显更大且正在生气。体型差 1.35 倍是"打得过打不过"的分界，
    // 与 behavior 里 fight 的体型门槛呼应。
    if (sizeOf(o) > sizeOf(c) * 1.35 && o.emotions.anger > 0.4) {
      threats.push({ id: o.id, pos: o.pos, dist: d });
    }
  }
  neighbors.sort((a, b) => a.dist - b.dist);
  threats.sort((a, b) => a.dist - b.dist);

  const foods = [];
  for (const f of world.foods) {
    const d = Math.hypot(f.pos.x - c.pos.x, f.pos.y - c.pos.y);
    if (d <= R) foods.push({ id: f.id, kind: f.kind, pos: f.pos, dist: d });
  }
  foods.sort((a, b) => a.dist - b.dist);

  let playerHand = null;
  if (world.playerHand) {
    const d = Math.hypot(world.playerHand.pos.x - c.pos.x, world.playerHand.pos.y - c.pos.y);
    if (d <= R * 1.5) {
      playerHand = { pos: world.playerHand.pos, dist: d, speed: world.playerHand.speed };
    }
  }

  // 求偶候选：分数由 courtshipScore 预算，behavior 只读数字（见 Task 9 说明）
  const atCap = aliveCreatures(world).length >= world.populationCap;
  const courtshipOptions = [];
  for (const n of neighbors) {
    const o = world.creatures.find((x) => x.id === n.id);
    if (!o) continue;
    courtshipOptions.push({
      id: n.id,
      dist: n.dist,
      score: courtshipScore(c, o, {
        population: aliveCreatures(world).length,
        populationCap: world.populationCap,
        distance: n.dist,
      }),
    });
  }

  // provoker：最近那个也在生气、且离得很近的邻居。
  // behavior 用它决定 protest / fight 的目标。
  const provoker = neighbors.find((n) => n.anger > 0.5 && n.dist < 0.08);

  return {
    foods, neighbors, threats, playerHand, courtshipOptions,
    provokerId: provoker ? provoker.id : null,
    population: aliveCreatures(world).length,
    populationCap: world.populationCap,
    atPopulationCap: atCap,
  };
}

// ---------------------------------------------------------------- 情绪情境

function emotionCtx(c, senses) {
  const hand = senses.playerHand;
  const threat = senses.threats[0];
  return {
    // 进食中的愉悦最强；有同伴次之；独处时给一点基础值，
    // 免得"什么都不发生"的生物永远 joy=0 而显得死气沉沉。
    pleasure: c.intent && c.intent.kind === 'eat'
      ? 0.8
      : (senses.neighbors.length > 0 ? 0.25 : 0.08),
    provocation: senses.provokerId ? 0.6 : 0,
    threat: threat
      ? clamp01(0.5 + (0.2 - threat.dist))
      : (hand && hand.speed > 0.25 ? 0.5 : 0),
    novelty: hand ? 0.6 : (senses.foods.length ? 0.25 : 0.1),
    canBreed: canBreed(c) && senses.courtshipOptions.some((o) => o.score > 0),
  };
}

// ---------------------------------------------------------------- 行动执行

function executeIntent(world, c, senses, dt) {
  const intent = c.intent;
  c.moving = false;
  c.resting = false;

  if (!intent) return;

  const stageFactor = CONFIG.motion.stageFactor[c.stage] || 1;
  let speedFactor = stageFactor;
  // 幼态的笨拙（spec 4.7）：幼体与亚成体偶尔冲过头，靠速度上的轻微随机抖动实现
  if (c.stage === 'hatchling' || c.stage === 'juvenile') {
    speedFactor *= 0.85 + world.rng.range(0, 0.3);
  }
  if (intent.kind === 'flee') speedFactor *= CONFIG.motion.fleeFactor;
  if (c.courtship) speedFactor *= CONFIG.motion.courtshipFactor;
  if (c.mourn > 0 && intent.kind === 'mourn') speedFactor *= 0.1;   // 哀悼 = 几乎静止

  switch (intent.kind) {
    case 'rest':
    case 'mourn':
    case 'idle':
      c.resting = intent.kind === 'rest';
      // 休息时缓慢下沉到缸底（每秒 1.2% 世界高度）。
      // 写成 "速率 × dt" 而不是 "每帧位移" —— 后者会让手机 120Hz 下沉得比电脑快一倍。
      if (c.resting) c.pos.y = clampPos(c.pos.y + 0.012 * dt);
      break;

    case 'eat': {
      const f = world.foods.find((x) => x.id === intent.targetId);
      if (!f) { c.intent = null; break; }
      const d = Math.hypot(f.pos.x - c.pos.x, f.pos.y - c.pos.y);
      if (d < 0.035) {
        feedNeeds(c.needs, CONFIG.food[f.kind].energy);
        applyEvent(c.emotions, 'fed');
        if (CONFIG.food[f.kind].calms) {
          comfort(c.needs, CONFIG.food[f.kind].calms);
          c.emotions.anger = clamp01(c.emotions.anger - CONFIG.food[f.kind].calms);
          c.emotions.fear = clamp01(c.emotions.fear - CONFIG.food[f.kind].calms);
        }
        world.events.push({ kind: 'eat', id: c.id, foodId: f.id, foodKind: f.kind });
        const idx = world.foods.indexOf(f);
        if (idx >= 0) world.foods.splice(idx, 1);
        c.intent = null;      // 吃完了，下一步重新决策
      } else {
        moveToward(c, f.pos, dt, speedFactor);
      }
      break;
    }

    case 'forage': {
      const f = world.foods.find((x) => x.id === intent.targetId);
      if (!f) { c.intent = null; break; }
      moveToward(c, f.pos, dt, speedFactor);
      break;
    }

    case 'socialize':
    case 'protest':
    case 'fight':
    case 'beg': {
      const target = intent.targetPos
        || (intent.targetId ? (world.creatures.find((x) => x.id === intent.targetId) || {}).pos : null);
      if (!target) { c.intent = null; break; }
      // 社交保持一点距离，不要完全重叠；抗议/争斗则要贴上去
      const stopDist = intent.kind === 'socialize' ? 0.06 : 0.03;
      const d = Math.hypot(target.x - c.pos.x, target.y - c.pos.y);
      if (d > stopDist) moveToward(c, target, dt, speedFactor);
      if (intent.kind === 'beg' && senses.playerHand) {
        // 卖萌：蹭玩家的手，累积好感（spec 6.1）
        adjustMemory(c.memory, PLAYER_ID, 0.02 * dt, 0.03 * dt);
        c.emotions.joy = clamp01(c.emotions.joy + 0.1 * dt);
      }
      break;
    }
    case 'explore':
    case 'flee':
      if (intent.targetPos) moveToward(c, intent.targetPos, dt, speedFactor);
      break;

    case 'court': {
      // 求偶的编舞由 breeding 的 phase 驱动（绕圈/脉动同步/轻触/膨胀展示）。
      // 内核只负责让双方靠近并维持仪式；具体的圆圈轨迹在计划 2 的表现层实现。
      const partner = world.creatures.find((x) => x.id === intent.targetId);
      if (!partner || !partner.alive) { interruptCourtship(c); c.intent = null; break; }
      if (!c.courtship) {
        const d = Math.hypot(partner.pos.x - c.pos.x, partner.pos.y - c.pos.y);
        if (d < CONFIG.courtshipRange && courtshipScore(c, partner, {
          population: aliveCreatures(world).length,
          populationCap: world.populationCap,
          distance: d,
        }) > 0) {
          startCourtship(c, partner, world.rng);
        } else {
          moveToward(c, partner.pos, dt, speedFactor);
        }
      } else {
        moveToward(c, partner.pos, dt, speedFactor * 0.6);
      }
      break;
    }

    default:
      break;
  }
}

function moveToward(c, target, dt, speedFactor) {
  const speed = CONFIG.motion.baseSpeed * speedFactor;
  let dx = target.x - c.pos.x;
  let dy = target.y - c.pos.y;
  const len = Math.hypot(dx, dy);
  if (len < 1e-6) return;
  dx /= len;
  dy /= len;
  c.pos.x = clampPos(c.pos.x + dx * speed * dt);
  c.pos.y = clampPos(c.pos.y + dy * speed * dt);
  c.vel.x = dx * speed;
  c.vel.y = dy * speed;
  c.moving = true;

  // 朝向平滑转向（spec 4.6）：不是瞬间掉头，转向速率还受 bold 调制 ——
  // 胆大的转身果断，胆小的迟疑，这本身就是可见的性格差异。
  const rate = Math.min(1, (CONFIG.motion.facingLerp * (c.thresholds.turnRate / 4)) * dt);
  const fx = c.facing.x + (dx - c.facing.x) * rate;
  const fy = c.facing.y + (dy - c.facing.y) * rate;
  const flen = Math.hypot(fx, fy) || 1;
  c.facing.x = fx / flen;
  c.facing.y = fy / flen;
}

// ---------------------------------------------------------------- 单只 tick

function tickCreature(world, c, dt) {
  decayMemory(c.memory, dt);

  const senses = perceive(world, c);

  c.intentTime += dt;

  // 求偶仪式进行中：锁定 court 意图，完全不重新决策。
  //
  // 这不是优化，是必需的正确性修复。canCourt 要求 `!a.courtship`，
  // 所以仪式一旦开始，courtshipScore 对这一对就返回 0 —— 若此时照常重新决策，
  // court 候选的分数归零，两只会各自游开，仪式在半路上散掉。
  // 表现层（计划 2）会看到它们本该绕圈共舞却越走越远。
  if (c.courtship) {
    c.intent = {
      kind: 'court',
      targetId: c.courtship.partnerId,
      minDuration: c.courtship.duration,
    };
    c.intentTime = 0;
  } else if (!c.intent || c.intentTime >= c.intent.minDuration) {
    // 行为有最小持续时间，防止每帧重新决策导致的高频抖动（spec 4.10）
    const next = decide(c, senses, world.rng);
    if (!c.intent || next.kind !== c.intent.kind) {
      c.intent = next;
      c.intentTime = 0;
    }
  }

  executeIntent(world, c, senses, dt);

  // 温柔的手停在附近 → 它注意到你了：familiarity 上升，affection 不动。
  //
  // 这一小段是 behavior 里 beg 门槛能打开的唯一来源（见 Task 9 的注释）。
  // 少了它，卖萌永远不可能被触发。
  //
  // 刻意只给"认识"不给"喜欢"：喜欢必须由计划 3 的抚摸输入买来。
  // 光是把手放在那儿就能刷好感的话，卖萌会退化成一个挂机计时器，
  // 而 spec 6.1 的整个要点是"温柔与否有区别"。
  if (senses.playerHand && senses.playerHand.speed <= 0.25
      && senses.playerHand.dist < CONFIG.perceiveRadius * 0.5) {
    adjustMemory(c.memory, PLAYER_ID, 0, 0.04 * dt);
  }

  decayNeeds(c.needs, dt, c.traits, {
    moving: c.moving,
    resting: c.resting,
    companions: senses.neighbors.length,
  });

  updateEmotions(c.emotions, computeTargets(c.needs, emotionCtx(c, senses), c.traits), dt);

  // 求偶仪式推进。
  //
  // tickCourtship 在返回 'complete' 的同时会把 c.courtship 置为 null
  // （这是它防止同一场仪式被完成两次的机制）。但 resolve() 需要知道
  // "刚才是和谁完成的"才能配对产卵，所以必须在清空之前把 partnerId 抄下来。
  // 漏掉这一行，求偶永远完成不了、永远不会产卵。
  if (c.courtship) {
    c.courtshipPartnerId = c.courtship.partnerId;
    if (tickCourtship(c, dt) === 'complete') c.courtshipCompleted = true;
  } else {
    c.courtshipCompleted = false;
    c.courtshipPartnerId = null;
  }

  if (c.mourn > 0) c.mourn = Math.max(0, c.mourn - dt);

  ageCreature(c, dt);
  if (!c.alive && c.dying > 0 && !c.deathHandled) {
    c.deathHandled = true;
    onDeath(world, c);
  }
}

// ---------------------------------------------------------------- 死亡与哀悼

function onDeath(world, c) {
  world.stats.deaths += 1;
  world.events.push({ kind: 'death', id: c.id, pos: { ...c.pos }, name: c.name });

  // 附近的个体进入哀悼（spec 4.11）：停顿、变暗一小会儿。
  // 不解释、不提示 —— 这是给看得懂的人的。
  for (const o of aliveCreatures(world)) {
    if (o === c) continue;
    if (Math.hypot(o.pos.x - c.pos.x, o.pos.y - c.pos.y) <= CONFIG.mournRadius) {
      o.mourn = CONFIG.mournDuration;
      applyEvent(o.emotions, 'death');
    }
  }
}

function reapDead(world, dt) {
  for (let i = world.creatures.length - 1; i >= 0; i--) {
    const c = world.creatures[i];
    if (c.alive) continue;
    c.dying += dt;
    if (c.dying >= CONFIG.dissolveDuration) {
      world.creatures.splice(i, 1);
      world.events.push({ kind: 'dissolved', id: c.id });
    }
  }
}

// ---------------------------------------------------------------- 卵

function tickEggs(world, dt) {
  for (let i = world.eggs.length - 1; i >= 0; i--) {
    const egg = world.eggs[i];
    const result = tickEgg(egg, dt);

    if (result === 'failed') {
      // 卵的光慢慢熄灭（spec 4.12 第 6 条）—— 不是消失，是先变得不可孵化，
      // 再过一会儿才安静地散去。
      if (egg.age >= CONFIG.stage.egg * 3) {
        world.eggs.splice(i, 1);
        world.events.push({ kind: 'eggFailed', id: egg.id, pos: { ...egg.pos } });
      } else if (!egg.failCounted) {
        egg.failCounted = true;
        world.stats.hatchFailures += 1;
      }
      continue;
    }

    if (result === 'ready') {
      const mother = world.creatures.find((x) => x.id === egg.motherId);
      const father = world.creatures.find((x) => x.id === egg.fatherId);
      const generation = Math.max(
        (mother ? mother.generation : 0) + 1,
        (father ? father.generation : 0) + 1,
      );
      const baby = hatch(egg, world.rng, { nameFor: world.nameFor, generation });
      addCreature(world, baby);
      world.stats.births += 1;
      world.stats.generation = Math.max(world.stats.generation, generation);
      world.events.push({ kind: 'hatch', id: baby.id, pos: { ...baby.pos }, eggId: egg.id });

      // 父母侧的关系记忆与家谱由世界写回 ——
      // breeding.hatch 不持有世界，拿不到父母对象（见 Task 8 的设计说明）。
      if (mother) {
        ensureMemory(mother.memory, baby.id, { kinship: KINSHIP.offspring, role: 'offspring' });
        if (!mother.lineage.offspring.includes(baby.id)) mother.lineage.offspring.push(baby.id);
      }
      if (father) {
        ensureMemory(father.memory, baby.id, { kinship: KINSHIP.offspring, role: 'offspring' });
        if (!father.lineage.offspring.includes(baby.id)) father.lineage.offspring.push(baby.id);
      }

      world.eggs.splice(i, 1);
    }
  }
}

// ---------------------------------------------------------------- 交互结算

function resolve(world, dt) {
  const alive = aliveCreatures(world);

  // 求偶完成：双方都在同一 tick 标记完成才算成功。
  // 单方完成（对方被打断/死亡）则视为被拒绝，触发 rejected 事件。
  const completed = alive.filter((c) => c.courtshipCompleted);
  const paired = new Set();
  for (const a of completed) {
    const partner = alive.find((x) => x.id === a.courtshipPartnerId && x.courtshipCompleted);
    if (partner && !paired.has(a.id) && !paired.has(partner.id)) {
      paired.add(a.id);
      paired.add(partner.id);
      const atCap = alive.length >= world.populationCap;
      const eggs = layEggs(a, partner, world.rng, { atPopulationCap: atCap });
      for (const egg of eggs) world.eggs.push(egg);
      applyEvent(a.emotions, 'mated');
      applyEvent(partner.emotions, 'mated');
      adjustMemory(a.memory, partner.id, 0.25, 0.1);
      adjustMemory(partner.memory, a.id, 0.25, 0.1);
      world.events.push({
        kind: 'mated', a: a.id, b: partner.id,
        eggs: eggs.length, atPopulationCap: atCap,
      });
      a.courtshipCompleted = false;
      partner.courtshipCompleted = false;
    }
  }
  // 落单的完成者：对方没能一起完成（被打断、死亡、或走开了），算一次失败的求偶。
  //
  // 被拒绝要在关系记忆里留痕（CONFIG.rejectionAffection = -0.15）——
  // 这是 spec 4.8"恩怨"的一部分：被同一只拒绝过几次之后，
  // 它下次再靠近时这只的好感已经低了，求偶评分随之下降，于是会去别处。
  // 少了这一行，拒绝就只是一次性动画，世界不会记住它。
  //
  // 必须先抄下 partnerId 再清空，否则下面就找不到该记在谁的头上了。
  for (const a of completed) {
    if (!paired.has(a.id)) {
      const pid = a.courtshipPartnerId;
      a.courtshipCompleted = false;
      a.courtshipPartnerId = null;
      applyEvent(a.emotions, 'rejected');
      if (pid) adjustMemory(a.memory, pid, CONFIG.rejectionAffection, 0.05);
      world.stats.rejected += 1;
      world.events.push({ kind: 'rejected', id: a.id, by: pid });
    }
  }

  // 身体碰撞：重叠时互相推开，并给双方一点"被撞"的情绪冲击。
  // 只在真的挤到一起时触发，避免正常游动也被判为冲突。
  for (let i = 0; i < alive.length; i++) {
    for (let j = i + 1; j < alive.length; j++) {
      const a = alive[i];
      const b = alive[j];
      const dx = b.pos.x - a.pos.x;
      const dy = b.pos.y - a.pos.y;
      const d = Math.hypot(dx, dy);
      // 归一化体型 → 归一化碰撞半径。sizeOf 是世界单位（14–38），
      // 除以 1000 换算到 [0,1]² 世界坐标尺度。
      const minDist = (sizeOf(a) + sizeOf(b)) / 2000;
      if (d < minDist && d > 1e-6) {
        const push = (minDist - d) / 2;
        const nx = dx / d;
        const ny = dy / d;
        a.pos.x = clampPos(a.pos.x - nx * push);
        a.pos.y = clampPos(a.pos.y - ny * push);
        b.pos.x = clampPos(b.pos.x + nx * push);
        b.pos.y = clampPos(b.pos.y + ny * push);

        // 求偶中的碰撞不算冲突 —— 仪式本来就要贴近
        if (!a.courtship && !b.courtship) {
          applyEvent(a.emotions, 'bumped', 0.4);
          applyEvent(b.emotions, 'bumped', 0.4);
          // 记住这笔小账：好感轻微下降，多次碰撞才会累积成恩怨
          adjustMemory(a.memory, b.id, -0.01, 0.02);
          adjustMemory(b.memory, a.id, -0.01, 0.02);
        }
        // 亲属之间更宽容（spec 4.8：更容忍亲属靠近）
      }
    }
  }
}

// ---------------------------------------------------------------- 食物再生

function respawnFood(world, dt) {
  const algae = world.foods.filter((f) => f.kind === 'algae').length;
  if (algae >= CONFIG.foodMax) return;
  // 概率随 dt 缩放，保证不同帧率下再生速率一致
  if (world.rng.chance(CONFIG.foodRespawnRate * dt)) {
    spawnFood(world, 'algae', {
      x: world.rng.range(0.05, 0.95),
      y: world.rng.range(0.15, 0.95),
    });
  }
}

// ---------------------------------------------------------------- 主 tick

export function tickWorld(world, dt) {
  world.time += dt;
  rebuildGrid(world);
  respawnFood(world, dt);

  for (const c of world.creatures) {
    // sick 个体被完全冻结：不再感知、决策、进食、繁殖。
    // 不跳过的话，导致它出错的那个损坏字段会在每一 tick 再抛一次，
    // events 队列会被同一条 error 刷满（600 条/10 秒），把真正有用的事件淹掉。
    // 冻结也让表现层的处理变简单：sick 就是一只静止、变暗的生物。
    if (!c.alive || c.sick) continue;
    try {
      tickCreature(world, c, dt);
    } catch (err) {
      // 隔离故障个体而不是让整个世界崩溃（spec 7.7）。
      // sick 个体仍然留在 creatures 里被 render 画出来（变暗、静止），
      // 这样问题对用户是可见的，而不是无声地少了一只。
      c.sick = true;
      c.intent = null;
      world.events.push({
        kind: 'error',
        id: c.id,
        message: String((err && err.message) || err),
      });
    }
  }

  tickEggs(world, dt);
  resolve(world, dt);
  reapDead(world, dt);
}
```

`courtshipCompleted`、`courtshipPartnerId`、`deathHandled` 是 `sim.js` 在运行时挂到 `Creature` 上的三个编排层簿记字段。它们**不进** `createCreature`，也**不进**存档 —— 读档时仪式必然已经结束或被打断，死亡必然已经结算过，所以这三个字段重新从 `false`/`null` 开始才是正确的语义。
